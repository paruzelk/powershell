## Что выявлено в исходном MailMover.ps1

Текущий общий `Move-OPAItemsWithLimit` должен оставаться закрыт: оригинальный `Get-OPAArchiveDestination` сортирует найденные годовые части и выбирает старшую часть, когда в ней хватает места. Для маленькой Part1 возможна запись в существующий `Archive-2020.pst`, а не в отдельно запланированную `-02`.

В исходном массовом цикле до Move используется `Sync-OPADuplicateIndexFromJournal`, который может менять общий индекс, а сразу после успешного `Move` используется `Add-OPADuplicateEntry` **до** независимого реального перезапуска Outlook и сверки полного witness. Синтетический переключатель `ARCH3dSyntheticBoundary` отвергает живой Outlook по замыслу. Поэтому простой вызов стандартного Archive или включение `ARCH3dSyntheticBoundary` на живом PST нельзя считать безопасным one-shot.

В ARCH3k не добавлен второй (конкурирующий) Move-алгоритм. Не изменены `MailMover.ps1`, `ArchiveVerifier.ps1`, `OperationJournal.ps1` и `DuplicateIndex.ps1`. Вместо этого source-backed аудитор повторяет проверки текущего исходного состояния и фиксирует эти незакрытые границы.

## Выполнение Windows PowerShell 5.1 STA

Распакуйте сборку, войдите в папку `OutlookPOP3Archive`. `Plan` не обращается к Outlook. Для `Audit` один запущенный Outlook 2019 с профилем `Outlook`.

```powershell
$pin = @{
    RunId = '9d276dc4-a0e6-4e74-891f-81502fafe7db'
    IntentSha256 = 'f0860d55c5939498094832a8b924dbca9b65532cf53f8234f4aeda97ab631a2b'
    JournalSha256 = 'a19f113a6454b1d17333c9a53fc22d065876754b9fbab3167087487d0b2b981e'
}

.\Invoke-ARCH3k.ps1 -Mode Plan @pin | Format-List
.\Invoke-ARCH3k.ps1 -Mode Audit @pin | Format-List
```

| Параметр | Тип | Правило |
| --- | --- | --- |
| `-Mode` | `Plan` / `Audit` | По умолчанию `Plan`. **Нет режима Move или Prepare**. |
| `-RunId` | string GUID | Строго операторский исходный ARCH3j RunId. |
| `-IntentSha256` | string SHA-256 lowercase hex | Строго зафиксированный SHA PrepareIntent. |
| `-JournalSha256` | string SHA-256 lowercase hex | Строго зафиксированный SHA ORIGINAL OperationJournal. |

`Plan` проверяет исходные файлы, полный ARCH3i seal и маркеры исходного `MailMover` БЕЗ Outlook; `Audit` делает полный read-only Outlook COM witness и `Import-OPADuplicateIndex`, повторно определяет Year Part2 через original функции, подтверждает отсутствие нового PST и остаётся в `WriterPermit=False`.

**Не запускайте `-Mode Move`: такого режима нет.** Не повторяйте предыдущие `Seal`, `Prepare`, `Move` или `Resume`. Не удаляйте доказательства из LOCALAPPDATA.

## Следующий этап после реального ARCH3k Audit

Реальный one-shot требует отдельного защищённого маршрута строго в НОВЫЙ Part2 через оригинальные примитивы и блокировку общего индекса до независимой сверки. Перед COM должны быть immutable DestinationReady, полный pre-move witness, MoveClaimed и Flush(true); любая ошибка после claim — только независимая диагностика, **без автоматического повтора**. После Outlook restart использовать оригинальный ArchiveVerifier со сравнением исходного полного ARCH2b witness, затем original OperationJournal Reconciled, затем original DuplicateIndex (с readback). Синтетические success не являются живой сертификацией.
