# ARCH3w1: оригинальный семантический контроль Part2 вместо нестабильного SHA всего PST

**20 ноября 2026 | DEV | Windows PowerShell 5.1 STA | `ProductionReady=False`.**

## Причина новой версии

Оператор проверил ARCH3w `Plan/Audit/Prepare -WhatIf`. `Audit` зафиксировал архив 2020 Part1 размером 271360, SHA256 `8bc491f7b5e7b71e5458f88b01fa684f22270b425d7eca3fba572b1914e2514b`, Part2 размером 525312, SHA256 `43cbb3924b36cddae1d578eefcbaed35f587f6d2091510ec8dae23770fd8a279`. `Prepare` корректно остановлен до записи `Intent`, потому что полный бинарный SHA Part2 изменился. После корректного закрытия Outlook подтверждено: размер 525312 **не изменился**, а SHA Part2 стал `468f2ef0cc0ddfc2cea7e0306f3dba3aa1c95a7191011c9becf86c154e130004`; последнее изменение `20.11.2026 13:15:14`. Причина изменения байтов не доказана, и пользовательские письма в Part2 ещё требуется проверить.

**ARCH3w1 не принимает новый бинарный SHA без проверки.** Для Part1 сохраняется строгая SHA256 по байтам и размер 271360, поскольку новой независимой полной семантической точки для Part1 нет. Для Part2 обязательны оригинальные исторические цепочки `ARCH3o` Move, `ARCH3p` original ArchiveVerifier, `ARCH3q` Reconciled + `DuplicateIndex=501`, `ARCH3r` final immutable checkpoint, исходный ARCH3i full original witness и **НОВОЕ живое прочтение** сообщения с сравнением полного `ARCH2b` witness, включая настоящие SHA байтов вложений, и повторный запуск оригинального `Test-OPAArchiveMoves -RequireSemanticWitness`. Исторический SHA не является достаточным: необходимо подтвердить реальный архив **сейчас**.

## Режимы и полный синтаксис всех ключей

```powershell
# Используйте Windows PowerShell 5.1 -STA (ISE или powershell.exe -STA).
# Outlook должен быть открыт под профилем Outlook.
$pin = @{
    RunId = '093b5ce9-4a90-46fa-b6a5-7cdba61d2f15'
    SealSha256 = 'd071afbff028d4cbadcea69318a6d68009242ac401cd2a91abf08b5ffe9f6799'
    ExpectedAuditSha256 = '609e60e01082860ec8dfd936510243c812ba2c99b1403685a3d96c3718000a21'
    ExpectedPreviewSha256 = 'd9bc37c5f87aace732adb122d89488eb44111b7333ebf3b5d33c087766a42e57'
    ExpectedOriginalIndexSha256 = '5ada35eb30f34ff60dc4b89f23aa071b72cc0b98e5ff57299d61f1714b13d7ae'
}

# 1: без Outlook, никакой записи
.\Invoke-ARCH3w1.ps1 -Mode Plan @pin | Format-List

# 2: live read-only проверка 10 source + archived historical Part2
$audit = .\Invoke-ARCH3w1.ps1 -Mode Audit @pin
$audit | Format-List
$audit.ExistingOriginalArchiveParts | Format-List

# 3: предварительный отказ от любых записей, даже без Outlook
.\Invoke-ARCH3w1.ps1 -Mode Prepare @pin -ExpectedPrepareDigest $audit.PrepareDigest -ConfirmPrepareIntent -WhatIf | Format-List

# 4: ОДНОКРАТНЫЙ PREPARE — только после изучения Plan/Audit/WhatIf.
# ВНИМАНИЕ: только protected LOCALAPPDATA manifest + ORIGINAL 10 journal Intent.
# Ни COM Move, ни PST, ни DuplicateIndex изменяться не будут.
$prepared = .\Invoke-ARCH3w1.ps1 -Mode Prepare @pin -ExpectedPrepareDigest $audit.PrepareDigest -ConfirmPrepareIntent -Confirm:$false
$prepared | Format-List

# 5: offline independent integrity readback (не требует Outlook)
.\Invoke-ARCH3w1.ps1 -Mode Review -RunId $pin.RunId -SealSha256 $pin.SealSha256 -ManifestSha256 $prepared.ManifestSha256 -JournalSha256 $prepared.JournalSha256 | Format-List
```

**Полный интерфейс:**

`Invoke-ARCH3w1.ps1 -Mode <Plan|Audit|Prepare|Review> -RunId <GUID> [-SealSha256 <64 hex>] [-ExpectedAuditSha256 <64 hex>] [-ExpectedPreviewSha256 <64 hex>] [-ExpectedOriginalIndexSha256 <64 hex>] [-ExpectedPrepareDigest <64 hex>] [-ManifestSha256 <64 hex>] [-JournalSha256 <64 hex>] [-ConfirmPrepareIntent] [-WhatIf] [-Confirm:$false]`

| Параметр | Значение |
|---|---|
| `-Mode` | Обязательный режим `Plan`, `Audit`, `Prepare`, `Review`. |
| `-RunId` | Обязательный исходный GUID, строго `093b5ce9-4a90-46fa-b6a5-7cdba61d2f15`. Не использовать новый. |
| `-SealSha256` | SHA-256 исходного immutable ARCH3v Seal (`d071...`). |
| `-ExpectedAuditSha256` | Исходный полный source-witness ARCH3v SHA `609e...`. |
| `-ExpectedPreviewSha256` | Исходный ARCH3u preview SHA `d9bc...`. |
| `-ExpectedOriginalIndexSha256` | SHA original shared DuplicateIndex `5ada...`. |
| `-ExpectedPrepareDigest` | Только `Prepare`: новый стабильный SHA, полученный непосредственно из **ARCH3w1 Audit**. **Старый ARCH3w `7f4d497...` запрещён**: он содержит изменяемый бинарный SHA Part2 и не соответствует новому контракту. |
| `-ManifestSha256`, `-JournalSha256` | Только `Review`: SHA, возвращённые успешным Prepare. |
| `-ConfirmPrepareIntent` | Обязательное осознанное подтверждение при `Prepare`. |
| `-WhatIf` | `Prepare`: полная отмена записи и live Outlook, независимо от доступности Part2. |
| `-Confirm:$false` | Подавляет дополнительное интерактивное подтверждение PowerShell после явного `-ConfirmPrepareIntent`. |

## Проверки и ограничения

- **ARCH3v immutable**: повторное чтение SHA256 и 10 original ARCH2b Body/HTML/recipients/attachment full-witness. Все 10 source Inbox EntryID и 12 вложений повторно проверяются. Никакой записи в исходный PST.
- **Part1**: точные 271360 байт и `8bc491...` **физического** SHA256; если Outlook блокирует чтение Part1, FAIL CLOSED.
- **Part2**: точные 525312 байт; оригинальный post-commit Reconciled journal и original DuplicateIndex 501, исходный historical ARCH3i full witness SHA `8782b410...`, DestinationEntryID `00000000CB201CE90F11EB4AB6F01B5E5BEF7CED24002000`. `Get-OPA265ARCH3qState` + `Get-OPA265ARCH3qPinnedStages`, не старый `ARCH3p` precommit `Intent-only` reader.
- **Живая семантика Part2**: Part2 должен быть **уже подключён к Outlook** с исходным pinned StoreID; никакого `AddStoreEx`. Вся папочная иерархия Part2 должна содержать **ровно одно письмо** в `2020\Входящие`, иных элементов нет. `Compare-OPA265ARCH2bMailSemanticWitness` и **оригинальный** `Test-OPAArchiveMoves -RequireSemanticWitness` проверяют полное содержимое, вложения, папку, отсутствие оригинального SourceEntryID в Inbox и отсутствие дубля назначения. Несовпадение блокирует все Intent.
- **Part2 бинарный SHA не используется для допуска**: оригинальный MAPI provider может изменить байты PST, не меняя содержимое. Допуск устанавливается исключительно по живому архивному оригинальному full semantic verifier и immutable оригинальной historical цепочке. Размер Part2 остаётся жестко закреплён; любое изменение размера блокирует запись.
- **Part3**: исходный `Archive-2020-03.pst` строго отсутствует. Общий index SHA неизменен. Все 10 источников отсутствуют в original индексах и доступны в source Inbox.
- **Новый `PrepareDigest`**: связывает immutable ARCH3v `Seal`, original 10 source witness + ARCH3b original operation contracts, original shared index SHA, строгий Part1 SHA и размер, семантический proof SHA Part2, оригинальный EntryID/semantic full witness, и original destination path. Raw Part2 физический SHA отсутствует в digest; кэш/пустой результат оригинального verifier недопустим.
- **Аварии**: `Prepare` создаёт отдельную защищённую `%LOCALAPPDATA%\OPA265-ARCH3w1-093b5ce9-4a90-46fa-b6a5-7cdba61d2f15\` через оригинальную ACL-функцию. Только `original-ten-prepare-intents.json` и `original-operation-journal.jsonl`. Не дописывать, не удалять и не перезапускать `Prepare` после любых partial 1..9, truncated/torn journal. `Review` перечитывает историческое доказательство без Outlook + 10 original journal SHA envelopes с точным payload SHA. `WriterPermit=False`, `ProductionReady=False`, `MoveClaimed=False`, `RealMailMovePerformed=False`, `AutomaticMoveRetryAllowed=False`.
- **Не реализовано и не разрешено**: COM `MailItem.Move`, original `MoveClaimed`, `ProviderInvocation`, запись PST/исходного shared DuplicateIndex, `Archive/Resume/Auto`, production 90GB. ARCH3x требует самостоятельного build+operator approval.

### Если ARCH3w1 Audit блокируется

Не очищать исторические архивы и не модифицировать SHA. Если Part2 отсутствует в списке подключенных Outlook Stores — вручную проверить профиль Outlook и подключение **существующего**, не создавать нового архива. Если Part2 архивное письмо/папка/файл/StoreID отличается, не дописывать Intent и сохранить вывод. Код не умеет устранять неопределённый реальный COM Move и не должен делать это автоматически.

## CI и выпуск

Новые Pester проверки поведения Part1/raw и Part2/semantic, привязки исторического EntryID и witness, подделки семантического SHA, отсутствия новых Move и повторов. Полная CI-сборка Windows PowerShell 5.1 + PSScriptAnalyzer + BOM + ZIP только проекта; **реальное Outlook подключение проверяется отдельно оператором**, не эмулируется GitHub Actions.
