## Irreversible crash-safe fences

The NEW test fixture must be prepared by the existing
New-OPA264Live3SyntheticFixture.ps1 on the expressly approved TEST
Outlook profile and source POP3 PST. This fixture stages one NEW
GUID-scoped message with one complete flushed MailMove Intent, and a
new disposable archive PST. The user should NOT open/read the new
synthetic message before dispatch; BW3 deliberately refuses changed
MailItem.Size, unlike BW2c's read-only size acknowledgment.

- The controller verifies exact marker, request, one durable Intent,
  its SHA256, and ABSENCE of any old attempt, response, crash,
  reconciliation or dispatch evidence.
- It requires -Execute -ConfirmBW3SyntheticMove and EXACT lowercase
  -ExpectedJournalSha256 pinned from independent operator review.
- A durable bw3-dispatch.claim is atomically created using CreateNew
  and Flush(true) *before* the owned child process may start.
- WorkerProtocol allows exactly one BW3SyntheticOneShotMove request
  with a strict 7-field payload and matching WorkerRequestId. Child
  independently validates the durable dispatch claim and fixture.
- Child attaches ONLY to already-running TEST Outlook in native Windows
  PowerShell 5.1 STA; no Outlook.exe start/kill, PST mount/create.
- Child verifies exact POP3 DeliveryStore, source/destination StoreIDs,
  GUID-scoped folders, source=1/archive=0, MailItem.EntryID, Parent,
  Subject, InternetMessageId and **unchanged source size**.
- The child creates/flushes move-attempt.claim using CreateNew/Flush(true)
  immediately before exactly ONE call to MailItem.Move.
- Every error, timeout, crash, lost response and parent exception stops:
  NO automatic retry, NO second Worker, NO rollback, NO fall-through.
  A dispatch claim blocks *all* replay, even a pre-Move failure.
- Any validated Move response is only MoveReturnedNeedsIndependentReview:
  it NEVER appends Completed/Reconciled or infers durable success.
  Independent read-only PST review + separate explicit operator decision
  are still required.
- Legacy LIVE3 direct Worker and LIVE4 crash controller are blocked by
  an existing BW3 dispatch claim. BW3 refuses all old LIVE4 claims.

Do not run steps 2–4 until you explicitly decide to execute another
NEW synthetic fixture and one real Outlook Move. BW3 preparation alone
does not authorize any Outlook mutations.

   attempt claim/response) and FreshFixtureIntentValidated. Save the
   plan.JournalSha256; never edit the Intent or delete scope files.

       .\Core\Diagnostics\Invoke-OPA265BW3SyntheticController.ps1 -RunId $run -SourcePst $source -ExpectedJournalSha256 $plan.JournalSha256 -Execute -ConfirmBW3SyntheticMove -TimeoutSeconds 15 | Format-List

   Expected on valid child response: MoveReturnedNeedsIndependentReview,
   DispatchClaimExists=True, MoveAttemptClaimExists=True,
   AutomaticRetryAllowed=False, RequiresIndependentReconciliation=True,
   JournalCompleted=False, ProductionReady=False.
   On ANY error/timeout, STOP; NEVER repeat step 4 on same RunId.

5. In independent fresh PS5.1 STA session review only:

       .\Core\Diagnostics\Test-OPA264Live3SyntheticMove.ps1 -RunId $run -SourcePst $source -Review | Format-List

   Expected if Move really occurred: SyntheticMoveObserved (0/1,
   AttemptClaimExists=True). Do NOT append a Reconciled journal event
   automatically. This independent observation is not a production grant.

## Explicitly excluded

- Reuse of historical LIVE4/LIVE6a RunIds or their size waivers.
- Any production mail routing through BW3 Worker.
- Automatic Move retry, automatic reconciliation, automatic journal append.
- Existing Inbox or non-synthetic mail.
- Changes to Outlook/PST from CI or build tools.
- Worker runs without the irreversible parent claim.

Release metadata remains ProductionReady=False and
RealMailMoveViaWorker=False for PRODUCTION. BW3 is an operator-only
synthetic test harness, not a production-ready mail migration system.
