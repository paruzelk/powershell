# OutlookPOP3Archive 2.6.4-B DEV — isolated disposable-PST MailMove

## Status

Source-only development increment. NOT production, NOT a standalone verified
preview. Native Windows PowerShell 5.1 full CI and real Outlook testing on
disposable PSTs are still required. The 2.6.4-A Windows CI result does NOT
validate these newly added files.

The main WorkerProtocol allowlist, WorkerHost, FIX13b MailMover, Archive,
Resume and Auto are unchanged and must remain unchanged throughout 2.6.4.
The application version intentionally still reports 2.6.3-PREVIEW1 until
the full 2.6.4 release preparation/version consistency gate.

## New files

- Core/Worker/WorkerTestMove.ps1: derives the only allowed file paths from
  an exact RunId, rejects alternate PST/journal paths, missing or reparse-point
  test files, missing scope markers, reused one-shot claims and responses.
  Requires a matching single durable MailMove Intent (with fingerprint).
  Verifies real mounted StoreID-to-PST mappings, folder and source MailItem
  identity; creates a durable, exclusive, one-shot claim before ONE Move().
- Core/Diagnostics/Invoke-OPA264TestWorker.ps1: separate test-only STA
  PowerShell 5.1 entry point, requiring -Execute. Attaches ONLY to an already
  running Outlook instance; never launches or kills Outlook, never mounts a PST
  and never creates journal completion. Its response is evidence, not proof.
- Tests/Worker/WorkerTestMove.Tests.ps1: offline isolation/intent contract
  tests; does not open Outlook or mutate any real message.

## Hard scope

<OS TEMP>/OPA264-Test-<RunId without dashes>/
  Source.pst
  Archive.pst
  scope.json
  move.operations.jsonl
  request.json
  response.json (created once by the diagnostic Worker)
  move-attempt.claim (created atomically and durably before COM Move)

The RunId and OperationId must be distinct valid GUIDs; marker Purpose
must equal OPA264-Disposable-Pst-Pair. The journal must contain exactly one
complete, integrity-checked, sequence-1 MailMove Intent correlated to the
RunId and OperationId, with SourceEntryId, source StoreID and paths, target
folder path, ArchivePst and a full fingerprint. The response and claim MUST
not exist before the attempt. Only two previously created, mounted,
run-unique, disposal-authorized PST files are permitted.

This phase deliberately does NOT create the fixture or a controller that
launches the test Worker. Fixture creation/approval and controller-bound
fault injection will be added in the next tested increment. Do not handcraft
request/marker files against a production Outlook profile.

## Invariants

- A unique destination fingerprint is not independent Move proof.
- COM Move has exactly one call site in a diagnostic-only module.
- Any COM failure after the durable claim is Indeterminate, NEVER a safe retry.
- Never delete or replace claims, journals or PSTs to make a test repeat.
- The diagnostic worker writes a one-time response, never Completed or
  Reconciled; independent restart reconciliation is subsequent work.
- The ability to mount, initialize, or detach PSTs is NOT exposed by the
  diagnostic Worker. Production Worker allowlist remains unchanged.
- Real test execution requires a separate explicit owner-approved fixture
  and may not be attempted on a production mailbox.
