## New diagnostics, strictly read-only

Core/Diagnostics/Invoke-OPA265BW4k7v1PartialPstReadOnly.ps1

- Requires Windows PowerShell 5.1 in STA, active Outlook profile Outlook, one running Outlook process, and the exact old SuiteId GUID.
- Resolves the test PST only within the original isolated LOCALAPPDATA path, matches a uniquely mounted nondefault store, and refuses missing PST, reparse path and wrong store.
- Original pre-Move manifest may be missing. The diagnostic records presence/hash only, never recreates, repairs or rewrites the old manifest.
- Looks only inside exact GUID-pinned test root and four expected test subfolders: \Inbox, \Sent Items, \Projects\Alpha\2022 and \Projects\Beta. Default 20 items max per folder; stops on larger unexpected folders.
- Reports expected vs observed counts and at most 8 synthetic subject matches. Reads only Class, EntryID, Subject for these folder items; never mail body, recipients, headers or attachments. Unexpected subject is not exposed in the output.
- Optional InspectGetItemFromId performs Namespace.GetItemFromID(EntryID,StoreID) for exact matched synthetic items, records success or COM failure plus HRESULT for each. This is read-only, does not retry a Move or create new object.
- No Items.Add, MailItem.Save, Move, Send, Delete, AddStoreEx, registry changes or new PST/claim/journal/manifest writes.
- Even if all 8 items appear, the old original failed fixture remains excluded from future Move or production. No durable pre-Move evidence can be retroactively asserted by inventing a manifest.
