# 2.6.4-LIVE3 — one synthetic MailItem Move in EXISTING test POP3 PST

## Project goal

Restore focus to the OutlookPOP3Archive roadmap: an age-based POP3
archiver with a bounded working PST and bounded annual archive PSTs,
correct crash recovery and no double Move. The user's CURRENT Outlook
profile named Outlook and its existing POP3 PST are deliberately TEST
data. Do NOT require another profile, another full backup, or perfect
historical inbox count comparison to begin development.

LIVE2 live Outlook test already mounted and detached a temporary
restore copy successfully; its one CountMismatch is plausibly source
mailbox drift and not a LIVE3 gate. The LIVE2B diagnostic improvement
is optional and NOT required for LIVE3.

## LIVE3 new scope

- Existing current POP3 PST: selected by explicit -SourcePst path.
- Exactly one NEW run-unique folder under its root:
  OPA264-LIVE3-<RunId in N format>.
- Exactly one NEW synthetic MailItem created in THAT folder, with
  unique InternetMessageId, Subject, and EntryId identity fields. Do not require SenderEmailAddress or a positive/equal MailItem.Size for unsent synthetic mail.
- Exactly one NEW temporary destination PST under the run-unique system
  TEMP directory, Archive.pst. Does not reuse Archive-2019 or 2020.
- Dedicated archive folder OPA264-LIVE3-Archive-<RunId>.
- One durable Intent and a one-shot claim before the sole MailItem.Move.
- Dedicated test-only Worker, NOT normal Archive/Resume/Auto.
- Independent read-only inspection from a fresh PowerShell session.
- No auto-retry and no automatic journal Completed/Reconciled.

Production archive Worker integration flags remain FALSE.

## Runbook — ONLY after LIVE3 native Windows 5.1 CI passes

1. Download exact LIVE3 project ZIP, compare pinned SHA256.
2. From extracted root run:
       .\Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'
   Expected 517 tests / 37 containers in LIVE3b; zero failures. Earlier LIVE3 507/37 PASS does not cover this revised source.
3. Run Outlook with the existing TEST profile named Outlook. Open the
   mailbox and switch back to the *same non-elevated Windows user*
   PowerShell 5.1 STA session; no Outlook.exe process killing.
4. First **prepare only**, do not execute Move yet:
       $source='C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'
       $fixture=.\Core\Diagnostics\New-OPA264Live3SyntheticFixture.ps1 -SourcePst $source -Execute -ConfirmTestOnlyPst
   Expect SyntheticFixturePrepared, MailMoveExecuted=false, a new
   source folder with one synthetic item, and NEW temp Archive.pst.
   If fixture fingerprint persistence fails, STOP and inspect error.
   Do not edit the synthetic request/journal or use an old RunId.
5. New independent read-only validation:
       $run=[string]$fixture.RunId
       .\Core\Diagnostics\Test-OPA264Live3SyntheticMove.ps1 -RunId $run -SourcePst $source -Review
   Expected SyntheticReadyForOneShotMove, SourceItemCount=1,
   ArchiveItemCount=0; no claim.
6. After manually reviewing the source/target synthetic folders,
   perform the exact ONE test-only Worker Move via a NEW STA
   Windows PowerShell 5.1 process:
       powershell.exe -NoLogo -NoProfile -STA -File ".\Core\Diagnostics\Invoke-OPA264Live3SyntheticWorker.ps1" -RunId $run -SourcePst $source -Execute -ConfirmSyntheticOnlyMove
   This is not a controller-orchestrated crash scenario yet.
   Expect MoveReturnedNeedsReadOnlyReview, never Completed.
7. In a separate fresh STA process perform the read-only check:
       powershell.exe -NoLogo -NoProfile -STA -File ".\Core\Diagnostics\Test-OPA264Live3SyntheticMove.ps1" -RunId $run -SourcePst $source -Review
   Expect SyntheticMoveObserved, SourceItemCount=0,
   ArchiveItemCount=1, SyntheticArchiveMatches=1,
   AttemptClaimExists=true, JournalCompleted=false.
8. If any step fails, do NOT rerun -Move for same RunId, do not
   delete claims or reinterpret error as safe replay. Inspect
   Outlook test folders only; new test requires fresh RunId.
   No need to copy the full mailbox PST again for every test run.
