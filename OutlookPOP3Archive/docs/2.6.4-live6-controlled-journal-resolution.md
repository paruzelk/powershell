## LIVE6 safety design
1. -Review: replay one durable SHA256-enveloped synthetic MailMove Intent, rerun LIVE5 independent read-only Outlook verification. Only MoveConfirmed can be considered.
2. Second fresh exact target-only Outlook COM inspection checks approved already-running TEST profile Outlook, POP3 delivery store, StoreIDs, source/destination folder EntryIDs and paths, source=0, exactly one archive MailItem matching durable InternetMessageId + Subject. Sender and Size checked when recorded in Intent. Capture its current archive MailItem.EntryID.
3. -Execute requires BOTH -ConfirmSyntheticJournalResolution and -ExpectedJournalSha256 copied from the separately reviewed output.
4. Exclusively create and flush durable live6-resolution.claim with RunId/OperationId, pinned prior journal SHA256 and target EntryID BEFORE modifying journal. Interrupted claim with unresolved journal must never be replayed automatically.
5. With exclusive FileShare.None journal handle, recheck exact journal bytes' SHA256 before one durable SHA256-enveloped Sequence=2 Reconciled event is appended and flushed. Original Intent bytes preserved.
6. Replay verifies precisely Intent then Reconciled for one OperationId. Subsequent LIVE6 -Review returns AlreadyReconciled with NO further append.
7. Pre-Move NoMoveObserved, duplicate, missing, uncertain, mismatched or changed evidence is never reconciled.
8. AutomaticRetryAllowed=False, ProductionReady=False always. No automatic Move, retries or process termination.

IMPORTANT: After LIVE6 journal completion on the post-Move RunId, original LIVE4/LIVE5 snapshot scripts (which require SINGLE unresolved Intent) will no longer work on that RunId. Instead use LIVE6 -Review. Preserve original TEMP directory/claims; never delete a claim to reset a run.
