## Что делает ARCH3p

`Core/Archive/ARCH3pIndependentPostRestartOriginalVerifier.ps1` использует ОРИГИНАЛЬНЫЕ `ArchiveVerifier.ps1` / `Test-OPAArchiveMoves` и `Compare-OPA265ARCH2bMailSemanticWitness`. **Ни одна из этих функций не заменена упрощённой проверкой заголовков.**

Сначала читает старый protected ARCH3j Intent и Original OperationJournal с исходными SHA; затем пять связанных ARCH3o writer-файлов: `WriterEntry`, `DestinationReady`, `MoveClaimed`, `ProviderInvocation` и, если существует, `MoveReturned`. Повторно проверяет SHA между этапами, идентификатор исходного письма, назначение, StoreID и полный ORIGINAL ARCH3i witness. При отсутствии claim или ProviderInvocation — STOP, не запускать Move повторно.

В отличие от до-Move `ARCH3n`, ARCH3p **не требует отсутствия Part2**: она должна существовать и быть подключена в Outlook. Архив не создаётся, `AddStoreEx` не вызывается. Новый Outlook процесс обязан иметь другой PID и **более поздний StartUtcTicks**, чем в защищённом MoveClaimed. Из имеющихся Stores разрешается ровно одна Part2 со строгим pinned StoreID; исходная POP3 Inbox из старого store подтверждается отдельно.

По исходному архиву ищется исключительно существующая папка `2020\Входящие` через ОРИГИНАЛЬНЫЙ `Get-OPAFolderByPath`, без создания новых папок. В ней должен быть **ровно один** `MailItem`. Его оригинальный полный semantic witness (Body/HTML/Recipients/Attachments SHA) сравнивается с прежним. `Test-OPAArchiveMoves` затем независимо проверяет отсутствие source EntryID в реальном Inbox, наличие ровно одной копии в нужном архиве и полные semantic поля. К ORIGINAL ArchiveVerifier передаётся **полный** актуальный `FolderPath` из Outlook, включая корень PST, а не только относительная строка `2020\Входящие`.

Если `MoveClaimed` и `ProviderInvocation` записаны, но COM возврат произошёл перед записью `MoveReturned`, ARCH3p может проверить фактически оказавшееся в архиве письмо (одна полная копия, старый source EntryID исчез, новый Outlook процесс) — это **проверка неопределённого результата, НЕ новый Move**. Без ProviderInvocation автоматический повтор также запрещён.

Проверка исходного `DuplicateIndex` (500 записей, исходный SourceEntryId ещё отсутствует) выполняется ДО и ПОСЛЕ оригинального ArchiveVerifier. Старый Part1 должен сохранить размер 271360 bytes. Оригинальный `OperationJournal` должен по-прежнему иметь ровно один `Intent`, исходный SHA256. НИКАКИХ `Reconciled`/`Add-OPADuplicateEntry` в ARCH3p нет. Для изменения исходного журнала и индекса потребуется отдельная транзакция следующего этапа с независимым readback.

## Синтаксис ARCH3p

| Ключ | Тип | Значение |
| --- | --- | --- |
| `-Mode` | `Plan`, `Review`, `Status` | `Plan` по умолчанию. `Plan` и `Status` читают только protected evidence; `Review` также обращается к живому Outlook. Нет `Move`, `Prepare`, `Commit`, `Resume`. |
| `-RunId` | string GUID | Ровно сохранённый ARCH3j RunId. |
| `-IntentSha256` | lowercase SHA256 | Оригинальный SHA256 из ARCH3j Prepare. |
| `-JournalSha256` | lowercase SHA256 | Оригинальный SHA256 `OperationJournal Intent`. |
| `-ExpectedMoveClaimSha256` | lowercase SHA256, необязательный | Ожидаемый независимый MoveClaim SHA, если он получен от ARCH3o Move. При несовпадении STOP. |

## Порядок выполнения после одного реального ARCH3o Move

Перед настоящим переносом используйте предыдущие `ARCH3o Plan/Audit/WhatIf/Status`. **НЕ запускайте ARCH3p Review до выполнения единственного разрешённого оператором `ARCH3o -Mode Move` и настоящего закрытия и повторного открытия Outlook** — без защищённого MoveClaimed он закономерно откажет.

На компьютере оператора после единственного Move: полностью закрыть Outlook, убедиться, что процесс OUTLOOK.EXE завершился, затем снова открыть Outlook с тем же профилем (и убедиться, что новая Part2 подключена). **Не выполнять Move вторично ни при каком результате или исключении.**

```powershell
$pin = @{
    RunId = '9d276dc4-a0e6-4e74-891f-81502fafe7db'
    IntentSha256 = 'f0860d55c5939498094832a8b924dbca9b65532cf53f8234f4aeda97ab631a2b'
    JournalSha256 = 'a19f113a6454b1d17333c9a53fc22d065876754b9fbab3167087487d0b2b981e'
}
.\Invoke-ARCH3p.ps1 -Mode Plan @pin | Format-List
.\Invoke-ARCH3p.ps1 -Mode Review @pin | Format-List
.\Invoke-ARCH3p.ps1 -Mode Status @pin | Format-List
```

**Безопасные команды до реального Move:** `Invoke-ARCH3o.ps1 -Mode Status @pin` (ARCH3p Plan/Review до Move ожидаемо выдают ошибку отсутствующего claim). `Review` ничего не меняет в PST/OperationJournal/DuplicateIndex.

Ожидаемый статус после удачного реального перезапуска: `IndependentRealOutlookRestartOriginalArchiveVerifierSourceAbsentArchiveOneFullSemanticMatch`. Если в оригинальном архиве нет ровно одной копии или семантика отличается — STOP, сохранить диагностику.
