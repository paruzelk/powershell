# BW4j — five-format synthetic suite and read-only MAPI witnesses

## Scope

Five new GUID-based synthetic cases: PlainSmall, UnicodePlain, HtmlBody, Attachment1K and Attachment256K. This build creates an immutable suite manifest, records one source witness per case, and permits read-only post-Move comparisons of exact GUID-bound disposable stores and items.

Subject, SenderEmailAddress, Body, HTMLBody, ReceivedUtcTicks, and each by-value attachment are individually hashed. Attachment bytes are saved temporarily with bounded size, SHA256-computed and deleted; no message text or attachment contents are stored in the witness JSON. MAPI Size is compared separately, never automatically waived.

NO Outlook Send, Move, draft-generation, journal writer, attempt-claim writer, retry or production Archive/Resume/Auto Worker. Keep original BW3a Intent, seven historical evidence files, old BW4g/BW4i claims and both historical PSTs unchanged.

## Local PowerShell 5.1 STA

Extract ZIP and run .\Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'.

Create a new five-fixture plan (no Outlook mutation):

```powershell
powershell.exe -NoLogo -NoProfile -STA -File .\Core\Diagnostics\Invoke-OPA265BW4jSuiteReadOnly.ps1 -Mode NewPlan
```

Record SuiteId, PlanPath, PlanSha256 and five unique Subject/TestId pairs. Never reuse the previous BW4i/BW4g TestIds.

Create emails manually matching each exact Subject and including its exact Body marker: 'OPA265 BW4j disposable synthetic test. TestId: <TestId>'. UnicodePlain requires Cyrillic text; HtmlBody requires real HTML; Attachment1K and Attachment256K require exactly one genuine by-value file of at least 1024 and 262144 bytes respectively. Only disposable synthetic data, no customer messages. Receive each email in the actual POP3 Inbox.

Find the exact received source MailItem EntryID and its parent Inbox EntryID in the running Outlook profile, checking the TestId, Subject and POP3 store. Do not guess IDs.

```powershell
$scriptPath=Join-Path (Get-Location).Path 'Core\Diagnostics\Invoke-OPA265BW4jSuiteReadOnly.ps1'
$arg=@('-NoLogo','-NoProfile','-STA','-File',$scriptPath,
    '-SuiteId','<NEW SuiteId>',
    '-TestId','<EXACT case TestId>',
    '-ExpectedPlanSha256','<64-char lowercase PlanSha256>',
    '-SourcePst','C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst',
    '-ExpectedProfileName','Outlook',
```

After successful SourceReview, one-shot immutable source witness:

```powershell
& powershell.exe @arg -Mode SourceCapture -ConfirmCaptureSourceOnce
if($LASTEXITCODE -ne 0){throw 'BW4j capture uncertain; never blindly repeat.'}
```

Preserve the returned EvidenceSha256 separately from the JSON file.

## DestinationReview (read-only, future use only)

This build intentionally DOES NOT implement the mandatory irreversible one-shot attempt claim or any Move. Do not manually move the planned fixtures to bypass that gate. A future independently approved controller must create the claim before each one-time Move.

For an independently authorized and completed future Move, DestinationReview accepts -DestinationPst, -DestinationFolderEntryId, -DestinationEntryId and -ExpectedSourceEvidenceSha256. The target PST must be named OPA265-BW4j-<SuiteId:N>-<TestId:N>.pst, with a folder named OPA265-BW4j-<TestId:N>. It verifies source-zero/destination-one exact InternetMessageId matches and compares every field without a writer permit.

Every status retains CanRetryMove=False, CanWriteHistoricalJournal=False and ProductionReady=False. Physical PST byte durability and full MAPI binary equality remain unproven.
