## Future writer design contract (NOT implemented, NOT authorized)

The only theoretical journal resolution for this one run would be
sequence 2, Phase Reconciled, with exact original RunId/OperationId,
archive EntryID and archive PST identity. It MUST NOT execute another
Outlook Move. A future separately designed and separately authorized
writer would need all of the following:

- An explicit one-run, one-event human authorization **distinct**
  from the BW3g1 +8-byte approval.
- Independent BW3 evidence and original one-Intent SHA256 recheck
  immediately before committing; enforce all seven durable hashes.
- A reserved CreateNew one-shot resolution claim. Existing, partial,
  symlink or conflicting legacy claim must cause hard STOP, never
  cleanup/retry.
- An exclusive, held-through-append journal FileStream lock, byte
  equality to the pinned original hash while locked, strict existing
  one-Intent terminal state guard, and a complete append flush(true).
- No rollback/retry of the irreversible claim/append crash gap.
  Crash after claim and before append => manual investigation ONLY;
  crash after append before verification => manual review ONLY.
- Postwrite independent journal schema/replay/claims verification,
  separate original evidence snapshot preservation, and production
  flags remaining disabled.
- A separate safety assessment for concurrent writers, tampered
  claims, TOCTOU, partial append and access failures.

None of these future write steps is executed by BW3j. Existing LIVE6
implementation is not an acceptable substitute for BW3-specific
authorization and worker provenance.
