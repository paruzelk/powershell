## Three modes

Plan: Computes a new SuiteId GUID, new test PST path and eight fabricated fixture descriptions without using Outlook or writing files.

Create: Requires explicit approval and Outlook 2019 profile Outlook running. Creates NEW Unicode PST in %LOCALAPPDATA%\OutlookPOP3Archive-BW4k7v-Isolated\suite-GUID\OPA265-BW4k7v-GUID.pst and mounts only that PST with Namespace.AddStoreEx(path,3). Adds one isolated fixture root with four source leaf folders: \Inbox, \Sent Items, \Projects\Alpha\2022, \Projects\Beta. Uses Folder.Items.Add('IPM.Note'), NOT Application.CreateItem, so that new unsent synthetic messages originate inside the isolated test PST, never the default user mailbox. Creates 8 saved synthetic messages: Inbox 4, Sent-named folder 2, custom folders 2, including Unicode, HTML, To/Cc/Bcc and raw deterministic 1 KiB/256 KiB attachments. No Move, Send or Delete.

NOTE: These are UNSENT draft-like messages, even if stored in a Sent Items-named folder. Synthetic year 2020-2025 is stored in custom user property OPA265BW4k7vArchiveYear and is NOT proved by actual MAPI ReceivedTime/SentOn. This stage cannot validate genuine historical sent/received transport data or real year-based dates. Future BW4k7w requires distinct real semantic fixture coverage if these are important for archiving.

Create then performs two independent reads of all eight saved items, including body, HTML, subject, To/Cc/Bcc/recipient rows, categories, read status, archive-year tag and attachment byte SHA256. It writes one original pre-Move manifest named premovereadonly-manifest.json with FileMode.CreateNew, Flush(true), returns its SHA256 and refuses overwrite. In case of a partial Create failure, the new suite directory/PST may remain without a manifest; do NOT retry the same GUID or delete anything automatically.

Verify: Requires same SuiteId and exact 64-hex SHA256 of the sealed original manifest, and Outlook CLOSED and RESTARTED after Create (new PID and start time). Reopens the exact mounted isolated PST/store/root and all eight original entries. Performs two fresh semantic and attachment hash reads per message, compares the same original witness SHA256s and checks exact role folders and item counts. Does NOT write Outlook mail, registry, PST claims or new manifest. Attachment SHA verification uses per-run unique temporary files inside the suite transient directory and removes only those temporary files; it is not a zero-filesystem-write operation. Outlook itself may update PST provider metadata upon mounting; no physical bitwise PST equivalence claim.

## Safety limitations

BW4k7v does NOT execute MailItem.Move, .Send or .Delete, does not touch original POP3/IMAP/old test PSTs or previous Evidence/Claim, does not rewrite PST registry limits, does not grant any production, recovery or automatic retry permission. It DOES create a brand new isolated PST and eight fabricated messages only in Create mode with explicit approval, and this PST stays attached to the current Outlook profile until manually removed later. It does not create a Move intent or Claim, and does not prove physical crash durability, full year-based MAPI date correctness, actual Sent Items transport semantics or class-specific nonMail preservation. Keep this fixture for future separately gated tests. Never retry old BW4k7m one-shot.

All new PowerShell source must be UTF-8 with BOM. Windows PowerShell 5.1 CI PSScriptAnalyzer/Pester, JSON exact safety checks, old BW4j6 and BW4k7u synthetic gates, project-only versioned public DEV ZIP with SHA256.
