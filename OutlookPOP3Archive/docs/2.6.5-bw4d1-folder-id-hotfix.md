# BW4d1 — strict Outlook folder/StoreID identity diagnostic hotfix (DEV only)

BW4d GitHub CI passed 1630 tests / 66 containers. On the operator's Windows
Outlook, the selected folder was independently confirmed as belonging to
the exact POP3 source PST, yet BW4d -> BW4c dual readback rejected
GetFolderFromID with an ambiguous "folder lookup did not match" error.

BW4d1 changes ONLY the read-only Outlook hex identity comparison and
failure diagnostics. Actual Outlook EntryID and StoreID values are encoded
binary identities represented by hexadecimal text. The A vs a case is
the same hex digit. Test-OPA265BW4cOpaqueIdMatch checks exact ordinal
equality first; it accepts case-insensitive comparison ONLY when both
strings are hexadecimal, have equal length, and contain an even number
of characters. Nonhex identities require exact ordinal equality.

GetFolderFromID now distinguishes COM resolution failure, null folder,
resolved folder EntryID mismatch and resolved StoreID mismatch. It
prints identity lengths, not full mailbox IDs. There is no fallback to
different PST, folder, store or account.

Retrieved MailItem, Parent, POP3 account DeliveryStore, and bounded folder
enumeration reuse the strict identity predicate. Six new native Windows
PowerShell 5.1 tests cover hex-case stability, real identity mismatches
and null folder lookup.
