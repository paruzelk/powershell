# OutlookPOP3Archive — короткий роадмап до стабильного архиватора

**Владелец решения:** разработка проекта. **Начало новой линии:** 2026-11-11, `2.6.5-ARCH1`. При потере контекста прочитать [handoff](PROJECT-HANDOFF-ARCH1.md) и [ADR](ADR-ARCH1-OUTLOOK-COM-BOUNDARY.md). **Запрет** превращать провайдерный `Size` / `PR_MESSAGE_FLAGS` drift в бесконечные ветки.

## Exit criteria — что значит «готово»

Надёжно обрабатывать тестовый POP3 PST с реальными типами писем, включая письма с HTML, Unicode и вложениями; доказать проверкой байтов вложений и пользовательских полей сохранность в архиве; гарантировать, что до завершённой проверки невозможно незаметно удалить последний оригинал; при сбое/неопределённом исходе не делать слепой retry и явно требовать reconciliation. Отдельные годовые PST/части, вложенные папки, область Inbox/Sent/Custom + исключённый Outbox, Resume, дубликаты, `-WhatIf`, отчёты и контролируемые лимиты PST. Только после этого — постепенная работа с 90 ГБ и резервными копиями.

| Этап | Результат | Чёткий критерий выхода | Статус |
|---|---|---|---|
| ARCH1 — аудит и архитектурный поворот | Реальный source inventory, фиксированные ADR/handoff/SEM stop-rule, автоматический read-only audit | Нет новых Move; DEV CI/ZIP PASS; список блокеров подтверждён исходным кодом | Выполняется в этом билде |
| ARCH2a — durable Move claim / no-blind-retry | Исправить COM catch/continue и блокировать неразрешённый Resume, закрыть mutating DEV CLI | Source & synthetic CI PASS, никаких Outlook/PST изменений; writer не активирован | Выполняется |
| ARCH2b — semantic verifier integration | BW4k witness в основной ArchiveVerifier, Body/HTML/recipients/attachment byte SHA + crash windows | Не удалять/не отмечать завершённым без полного pre/post witness; после isolated real Outlook test | Следующий |
| ARCH2 — один безопасный шаг архивации | Исправить ambiguous `MoveFailed`, durable claim, read-only reconcile; интегрировать semantic/attachment SHA из уже сделанных BW4k свидетелей в основной код; оценить Move против Copy/Verify/Delete | Сбой в любом окне не даёт автоматического повторного Move или незаметного удаления; содержимое подтверждено | Следующий |

| ARCH4 — Resume, дедупликация, долгие пачки | Свести основной транзакционный журнал/дедупликацию с recovery-политикой и отчётом, безопасный лимит | Прерывание после каждого шага, повторный запуск без невидимых дублей/потери; полный journal match | После ARCH3 |

| RC и 90GB | Релиз с контролируемым развёртыванием и резервной копией источника | Успешный ограниченный прогон + независимая сверка и план восстановления | Конечная цель |

## Измеримые требования

- **Содержимое:** поля семантической модели из SEM-001; вложения в точности по SHA-256 исходных байтов. Если что-то значимое недоступно, статус **Blocked**, а не молчаливый успех.
- **Транзакции:** write-once claim и состояние `Indeterminate` для таймаута/crash/COM-неясности, никакого blind retry. Согласованные source/target identity, оригинальный `EntryID`, `StoreID`, архивная папка.
- **Папки:** `Inbox`, POP3 Sent (даже если сейчас 0), пользовательские вложенные папки; Outbox, Delete, Drafts, Junk — только по явно утверждённой политике.
- **Годы:** отдельный Unicode PST на год, при необходимости `Archive-YYYY-partN.pst` по ограничению ёмкости, не обещать безграничный PST.
- **Объём:** 90GB — размер исходного набора, **не** разрешение на массовый Move без RC.
- **Внешние критерии:** PS5.1 + BOM + PSScriptAnalyzer + Pester + JSON gates + SHA256 ZIP. Исходный основной `RELEASE.Build=2.6.3-PREVIEW1` необходимо синхронизировать с новым release line **после** фактической готовности runtime, не обманывать совместимость метаданных.

## Стоп-правило исследований

При недоказанной низкоуровневой MAPI особенности **не порождать новый BW/forensic-билд**, если не обнаружено конкретной пользовательской потери/дубликата/небезопасного recovery. Допускается один ограниченный диагноз, затем решение: изменить последовательность COM, исправить проверку, изолировать тип письма, документировать неподконтрольный provider drift или отложить production только для затронутого сценария. Не возвращать нас к началу пятиформатных опытов.

**Следующее инженерное изменение после ARCH1: основной `Core/Archive/MailMover.ps1` + `ArchiveVerifier.ps1`, а не новый `Core/Diagnostics/BW4k7v2a*.ps1`.**
