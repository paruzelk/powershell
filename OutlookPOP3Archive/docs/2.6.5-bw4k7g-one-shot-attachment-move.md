## Architecture

1. `Core/Worker/BW4k7gOneShotAttachmentGuard265.ps1`: strict original **semantic** source witness equality except exact accepted 512-byte `MailItem.Size` difference; compares original sender, subject, full Body, HTMLBody, InternetMessageId, search key, date and binary attachment count/name/byte length/SHA256; full source To/Cc/Bcc digest, significant user state SHA. One immutable Claim written with **FileMode.CreateNew, UTF-8 BOM and Flush(true) BEFORE the single MailItem.Move**. Writes into **existing BW4k1 claim path** `%LOCALAPPDATA%\OutlookPOP3Archive-BW4k1-Claims\suite-<SuiteId>\fixture-<TestId>.json`, so BW4k1 and BW4k7f **already refuse all future retries**. All previous original claims, journals and evidence remain untouched. Claim uniquely pins source/destination store ID digests, exact folder and item identity, original source evidence and source-size decision SHA, source semantic snapshot SHA and 1024-byte attachment SHA.
2. `Core/Diagnostics/Invoke-OPA265BW4k7gOneShotAttachmentMove.ps1`: `Mode=Review` and `Mode=Execute -WhatIf` **never** write a Claim or move mail. Both run full independent BW4k7f preflight, two extra original content and recipients/flags witness pairs, target folder EntryID and empty-folder revalidation, and a second complete BW4k7f preflight. `Mode=Execute` requires explicit `-ConfirmOneShotAttachmentMove` and exact approval phrase `MOVE EXACT ONE BW4K7G ATTACHMENT1K DISPOSABLE MAIL`. The only mutating path writes one irreversible Claim and calls `MailItem.Move` **exactly once**. If the process crashes before/during/after Move, the Claim is never deleted; **no automatic or manual retry** of Execute. An ambiguous Move return can only be resolved by a separate read-only audit.
3. `Core/Worker/BW4k7gPostMoveSemanticReadOnly265.ps1` and `Core/Diagnostics/Invoke-OPA265BW4k7gPostMoveReadOnly.ps1`: independently verify pinned Claim SHA, original file-level plan/evidence, manual decision and immutable semantic source snapshots. Must independently observe `source-zero, destination-one`, uniquely match exact InternetMessageId and returned target EntryID and folder/store. Double-read archived content and byte-exact attachment SHA, and separately recalculate all recipients (To/Cc/Bcc) and user-state SHA with the same canonical encoding as BW4k7d. Report any content/recipient/flag differences without waiver; store-computed `Size` remains informational, not required byte equal. Audit never calls Move, modifies claim/journal, declares physical PST durability or production readiness.
4. New development code remains UTF-8 BOM. Full GitHub Actions Windows PowerShell 5.1 CI (PSScriptAnalyzer/Pester, existing BW4j6 5/5 synthetic matrix, release metadata, project-only ZIP, SHA256). **GitHub Actions cannot run real Outlook; real Move is ALWAYS manually operator initiated on disposable PST.**

## WhatIf and Execute: separate operator decisions

Only **after** Review PASS, change `$params.Mode='Execute'`, add `$params.ConfirmOneShotAttachmentMove=$true` and `$params.ApprovalText='MOVE EXACT ONE BW4K7G ATTACHMENT1K DISPOSABLE MAIL'`, then explicitly call with `@params -WhatIf`. Expected `WhatIfNoClaimNoMove`. This **cannot** authorize actual Move.

Only after reviewing a separate real WhatIf result and agreeing to the irreversible **one** disposable mail Move should an operator call without `-WhatIf`; once Claim exists, never reissue Execute, even on any error. Preserve output `ClaimSha256`, `DestinationEntryId`, `DestinationFolderEntryId`.

## Postmove read-only audit: no automatic replay

Use `Invoke-OPA265BW4k7gPostMoveReadOnly.ps1` only with exact three returned pins `ExpectedClaimSha256`, `ExpectedDestinationEntryId`, `ExpectedDestinationFolderEntryId`, and unchanged original parameters. Audit does **not** require original source mail to remain in Inbox; it verifies source absence. Any mismatch requires operator manual review, not an automatic or second Move.

## Still required for stable ~90GB POP3 archiver

The BW4k7g disposable-mail experiment does not establish safe source-PST compaction, crash-safe archival journal/resume for batches, yearly Archive-YYYY rollover/capacity, production Sent Items, user folders, recipient behavior across message classes, physical PST file durability or 90GB unattended runtime. These are separate production gates and are not silently enabled by BW4k7g.
