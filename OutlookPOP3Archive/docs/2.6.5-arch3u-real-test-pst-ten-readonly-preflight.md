# ARCH3u — контролируемый real TEST-PST batch-10: только предварительная проверка

19 ноября 2026 г. **DEV / read-only preflight, без реального Move**. Цель — получить точную предварительную партию из **10 писем в одной годовой группе** из существующего тестового POP3 PST `info@stios.ru.pst` и не повредить ранее подтверждённые ARCH3o–ARCH3t.

## Полный синтаксис и команды запуска

Требуются **Windows PowerShell 5.1 (STA)**, запущенный Outlook профиля `Outlook` с подключённым тестовым PST для `Inventory`.

```powershell
# Запуск в корне распакованного OutlookPOP3Archive-2.6.5-ARCH3u-dev:
$run = [guid]::NewGuid().ToString('D')
$source = 'C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'

# Только план, НЕТ Outlook и обращений к PST
.\Invoke-ARCH3u.ps1 -Mode Plan -RunId $run -SourcePst $source | Format-List

# Реальное чтение Outlook Inbox и Original DuplicateIndex,
# без каких-либо изменений PST, журнала, индекса
powershell.exe -NoLogo -NoProfile -STA -File .\Invoke-ARCH3u.ps1 -Mode Inventory -RunId $run -SourcePst $source | Format-List

# В интерактивной уже запущенной PowerShell -STA:
$inventory = .\Invoke-ARCH3u.ps1 -Mode Inventory -RunId $run -SourcePst $source
$inventory | Format-List
$inventory.Rows | Format-Table SourceEntryId, ArchiveDate, ArchiveYear, AttachmentCount, TargetFolderPath -AutoSize
```

| Параметр | Обязателен | Значение |
| --- | --- | --- |
| `-Mode` | Да | `Plan` — проверка аргументов без Outlook и файлов; `Inventory` — чтение исходного POP3 Inbox и DuplicateIndex. **Нет** `Move`, `Prepare`, `Resume`, `Auto`. |
| `-RunId` | Да | Новый GUID в нижнем регистре, формат `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`; идентификатор только для предварительного плана, файлы свидетельств не создаются. |
| `-SourcePst` | Нет | По умолчанию точно `C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst`. Иной локальный путь допустим только с **точным** именем файла `info@stios.ru.pst`; UNC/reparse запрещены. |

## Использование оригинальных компонентов

1. Исходная `Open-OPA265ARCH2dSession` подтверждает **один процесс Outlook** в текущем Windows-сеансе, профиль `Outlook`, **POP3 AccountType=2**, точное сопоставление `SourcePst` и `StoreID`, не-default Store и единственный Inbox.
2. `Get-OPAArchiveCandidates -Limit 128 -Diagnostics` читает исходную папку **Входящие**, выбирает сообщения по исходным датам и EntryID. При ошибке селектора, отсутствии сортировки или менее чем 10 кандидатах — STOP. Это **ограниченная выборка**, не полная инвентаризация ~26 тыс. писем.
3. Исходный `Import-OPADuplicateIndex` применяется **только после** чтения и проверки исходного JSONL: весь файл должен оканчиваться переводом строки, не содержать неверного JSON и повторного `SourceEntryId`. Если общего оригинального индекса нет — STOP; **не создавать новый**. До и после проверки индекс привязан к SHA-256.
4. Из выборки исключаются уже индексированные SourceEntryId; выбираются ровно **10** писем одного самого раннего года, в котором хватает десяти допустимых кандидатов. Все из того же исходного Inbox; смешивать разные годы/папки запрещено.
5. Файлы существующих годовых частей считываются с диска исходным `Get-OPAArchivePstPartsOnDiskAll`. `Get-OPA265ARCH3gPartPlan` проверяет занятые части и предлагает **следующую свободную** часть (например, часть 03 при существующих 01/02). План не создаёт, не монтирует и не резервирует будущую часть.
6. Исходный `New-OPA265ARCH3bBatchPreview` вызывает оригинальные `Get-OPAArchivePartPath` и `Get-OPAArchiveTargetPath` через ранее зафиксированные контракты. Никакого стороннего архиватора.
7. Для каждого выбранного EntryID отдельно выполняется `Namespace.GetItemFromID`: должны совпасть `Class=43`, `EntryID`, Inbox `Parent.EntryID`, `StoreID`, дата архивации. Читаются число вложений и SHA-256 текста темы (но **не содержимое вложений**). Индекс перечитывается по SHA-256. Любой дрейф — STOP.

Поля `Rows` возвращают точные SourceEntryID, исходную дату и предварительный target, а `PreviewSha256` привязывает выбранные исходные контракты, RunId, StoreID, Inbox EntryID и SHA-256 существующего индекса. Однако это **не долговечная печать содержимого сообщений**; `FullOriginalSemanticWitnessesCaptured=False`.

## Критерии успешного Inventory

```text
Status                               : TenOriginalInboxCandidatesAndNextUnusedYearPartReadOnlyNoMove
BatchSize                            : 10
OriginalMailMoverContractsUsed       : True
OriginalDuplicateIndexConsulted      : True
Rows                                 : {10 элементов}
FullOriginalSemanticWitnessesCaptured: False
OriginalOperationJournalWritten      : False
OriginalDuplicateIndexWritten        : False
ArchivePstCreated                    : False
RealMailMovePerformed                : False
AutomaticMoveRetryAllowed            : False
WriterPermit                         : False
ProductionReady                      : False
```

**Не интерпретировать `TargetPstPreview` как согласованное разрешение на запись.** В существующем тестовом PST уже есть годовые архивы и общий индекс. Файл частей или индекс могут измениться после preflight — каждый будущий writer обязан проверять их **снова** и создать собственный защищённый полно-семантический witness, durable Intent/Claim до `Move`.

## Следующая контрольная точка

После операторского `ARCH3u Inventory` и анализа реальных 10 `Rows`: самостоятельный **ARCH3v** — полная исходная ARCH2b semantic Body/HTML/recipient/attachment-byte SHA и защищённый pre-move evidence/Intent **без реального Move**. Только отдельный узко разрешённый этап может попытаться выполнить ровно десять реальных COM Move через оригинальный MailMover: независимый **реальный** Outlook restart, исходный ArchiveVerifier всех десяти, лишь затем original Reconciled+shared DuplicateIndex. При неопределённом исходе — никакого автоматического повторения. `Archive/Resume/Auto` и эксплуатационные ~90 ГБ остаются закрытыми.

## Тесты

**18 новых Pester** в одном контейнере: десять оригинальных контрактов, выбор незадублированных сообщений, год/части, SHA, отсутствие частичной партии, смешения папок, конфликт годовых частей и ошибочных ключей, проверка `Plan`, отсутствие writer-вызовов и UTF-8 BOM. Полный ожидаемый счётчик после добавления: **4569 тестов в 155 контейнерах** на Windows PowerShell 5.1. CI не подключается к реальному Outlook.
