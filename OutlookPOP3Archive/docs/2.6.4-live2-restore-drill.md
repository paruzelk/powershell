## Scope

- New pure scope validator: Core/Worker/ExistingPstRestoreGuard.ps1.
- New test-only CLI: Core/Diagnostics/Invoke-OPA264ExistingPstRestoreProbe.ps1.
- New offline tests: Tests/Worker/ExistingPstRestoreProbe.Tests.ps1.

The CLI offers THREE separate opt-in actions:
1. -Review: validate backup path, source length and pinned SHA256,
   calculate a one-shot RunId-unique TEMP path. No file/profile writes.
2. -PrepareClone: while Outlook is fully CLOSED, copy the reference
   backup to NEW TEMP/OPA264-Restore-{RunId}/RestoreCopy.pst, verify size
   and SHA256, then create one scope marker. It NEVER overwrites the
   backup or the original source PST.
3. -ProbeClone: with the EXISTING test profile already open, check
   the unique POP3 DeliveryStore association and nondefault source,
   claim the experiment ONCE, mount ONLY the verified TEMP clone
   with Unicode AddStoreEx, read relative folder structure/item counts
   for source and clone, detach ONLY the uniquely identified clone,
   verify unchanged account/default-store metadata, emit a report.

There is NO mail Move, delete, copy, marking or journal terminal event.
A missing claim/report, changed store identity, bad count, or exception
blocks authorization. A failed or interrupted test MUST NOT be retried
under the same RunId. Preserve the reference backup and evidence.

## Operator procedure

1. Run Windows PS5.1 CI from exact package:
       .\Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'
   Expect 490/36 PASS.
2. Capture a FRESH RunId:
       $run=[guid]::NewGuid().ToString('D')
3. Use the SAME $source and $backup paths from successful LIVE1.
   The backup path must remain a reference copy, never a mount target.
       $args264=@{
           RunId=$run
           SourcePst=$source
           BackupPst=$backup
           ExpectedBackupSHA256='25d52c52c654c096f758c14518720d1d3ca73f317c769864e6bc93a414ab980f'
           ExpectedSizeBytes=7550772224
       }
       .\Core\Diagnostics\Invoke-OPA264ExistingPstRestoreProbe.ps1 @args264 -Review
4. Confirm read-only status ReadyForExplicitClonePreparation.
5. Shut down Outlook COMPLETELY. With positive evidence that process
   OUTLOOK.exe has exited, explicitly run:
       .\Core\Diagnostics\Invoke-OPA264ExistingPstRestoreProbe.ps1 @args264 -PrepareClone -ConfirmCurrentTestProfile -Confirm
   Expect VerifiedDisposableClonePrepared and matching clone SHA256.
6. Start the SAME user-designated test profile Outlook. After human
   review/approval, run:
       .\Core\Diagnostics\Invoke-OPA264ExistingPstRestoreProbe.ps1 @args264 -ProbeClone -ConfirmCurrentTestProfile -Confirm
   Expect RestoredCloneStructureMatches, CloneDetached=true,
   ExistingPstMoveAuthorized=false and ProductionReady=false.
7. If any scope check fails, stop and preserve clone/claim/report
   evidence for manual review; never reissue one-shot -ProbeClone.
8. LIVE3: only after the verified restore test, prepare a NEW uniquely
   named synthetic folder and test-only message in the existing PST,
   with separate opt-in and a disposable destination PST. Never move
   user Inbox/Sent messages or use historic archive PSTs.

## Limitations

Same relative folder paths and item counts is a functional Outlook
OPEN/READ smoke test, NOT a complete PST integrity check. It does not
prove every item or attachment, a full disaster-recovery restore, or
safety of automatic MailMove retries. All production Worker flags remain
disabled and release remains blocked pending real crash/identity tests.
