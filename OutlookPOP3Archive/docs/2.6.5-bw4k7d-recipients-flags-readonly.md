## Features

1. `Core/Worker/BW4k7dRecipientFlagWitness265.ps1` reads only `MailItem.Recipients` in Outlook, bounded to 1..256, captures exact ordered recipient Type (1=To, 2=Cc, 3=Bcc), Name and Address using canonical length-prefixed UTF-8 strings and SHA-256. No raw recipient addresses in console output. Empty required `Address` or uncertain cardinality: fail closed.
2. Captures `MailItem.To, CC, BCC, UnRead, Categories, Importance, Sensitivity, FlagStatus, FlagRequest, ReminderSet` as an exact user-state SHA-256; separately retains read status, raw `PR_MESSAGE_FLAGS`, source attachment count and semantic READ/HASATTACH mask 0x11. Inconsistency is a STOP, not a waiver. Significant flag coverage is **not** yet certified for all production message types.
3. Two separate live read-only captures of the *same exact MailItem* must be identical. No `MailItem.Save()`, `MailItem.Move()`, PST create/mount, historical journal mutation, claim creation or decision re-write.
4. `Core/Diagnostics/Invoke-OPA265BW4k7dRecipientFlagsReview.ps1` verifies the **existing** immutable BW4k7c decision SHA with original BW4k7a/BW4k7b source content and all three prior Claims before **and after** new readings. Exact source PST, POP3 profile, Inbox, folder and source EntryID only; no alternate lookup. If any verification fails, stop.
5. No original pre-Move recipient snapshot existed in BW4j witness schema. A successful current read reports `SourceSemanticSnapshotPersisted=False` and `FuturePostMoveContentVerified=False`; a later separate source Capture may be designed only after operator review, with an immutable separate evidence file. This read-only build does not rewrite original evidence or alter the +512 decision.
