# ARCH3x1a — безопасная диагностика роста исходного PST

**23 ноября 2026. DEV, тестовый PST, Windows PowerShell 5.1 STA, профиль Outlook.**

## Причина

После ARCH3w1 Prepare и Review оператора оригинальный ARCH3x1 Plan был успешным, но Audit останавливался с текстом «ARCH3v immutable original operator ARCH3u pins/Part3 have drifted. STOP».

Точечная диагностика подтвердила: исходные PreviewSha256, POP3 StoreId SHA, общий DuplicateIndex SHA, десять исходных EntryID, год и номер части архива совпадают. Только длина исходного PST возросла с 7735903232 до 7756473344 байт (на 20570112). Новый Part3 отсутствует.

## Изменение

Опциональная `-ARCH3x1aAllowSourcePstLengthGrowth` доступна **только внутри оригинальной функции** `Get-OPA265ARCH3vFullReadOnlyAudit`, но не предоставляется вызываемому пользователем оригинальному ARCH3v Plan/Audit/Seal. Исходный строгий контракт ARCH3v по умолчанию не меняется.

Разрешено лишь увеличение длины исходного PST до 256 МиБ от запечатанного исторического значения и только при исходном RunId `093b5ce9-4a90-46fa-b6a5-7cdba61d2f15`. Уменьшение, отсутствие файла и рост свыше лимита — STOP. Размер проверяется **до и после** всех десяти реальных полных семантических witness.

После индивидуальных проверок Body, HTML, recipients, flags и фактических SHA-256 байтов каждого вложения исходная неизменная ARCH3v `AuditSha256` пересчитывается по **историческому размеру лишь в памяти**, для точной сверки с оригинальным ARCH3w1 манифестом. Исходные файлы/хэши/запечатанные свидетельства НЕ исправляются и не переписываются.

Текущий физический размер сохраняется отдельно в новом `Audit` (`ObservedSourcePstLengthBytes`) и включён в новый `PreflightDigest`. Следующий `Move`, если он будет разрешён отдельно, обязан повторить весь Audit и сверить не только digest, но и живую длину файла ДО защищённого writer-entry/создания Part3. Общий DuplicateIndex и Original Journal Reconciled не изменяются; отдельная послеперезапусковая верификация обязательна.

## Команды

Скачайте ТОЛЬКО подтверждённый GitHub Release ARCH3x1a. Распакуйте в отдельный каталог, используйте Windows PowerShell 5.1 STA.

~~~powershell
$pin=@{
  RunId='093b5ce9-4a90-46fa-b6a5-7cdba61d2f15'
  SealSha256='d071afbff028d4cbadcea69318a6d68009242ac401cd2a91abf08b5ffe9f6799'
  ManifestSha256='7568fb8cad7f89ced44d11d1117d4ef3e53e193f9269abee2b7f0e5f7b44b7e5'
  JournalSha256='a70fc0a419d44818bdeb3f306a1bbd6076ee39074a53101dd2ba274c4d5cf74e'
}

# Без Outlook; только реальный защищённый журнал, без записей:
.\Invoke-ARCH3x1.ps1 -Mode Status -RunId $pin.RunId | Format-List
.\Invoke-ARCH3x1.ps1 -Mode Plan @pin | Format-List

# Живой read-only original ARCH2b FullWitness 10 / 12 вложений:
$audit= .\Invoke-ARCH3x1.ps1 -Mode Audit @pin
$audit | Format-List

# Подтверждение безопасности без запуска Outlook Move:
.\Invoke-ARCH3x1.ps1 -Mode Move @pin -ExpectedPreflightDigest $audit.PreflightDigest -ConfirmTenRealMoves -WhatIf | Format-List
~~~

Ожидаем: `Status=TenOriginalRealSourceFullWitnessAndHistoricalYearPartsReadOnlyReady`, `OriginalFullWitnessCount=10`, `OriginalAttachmentCount=12`, `SourcePstLengthGrowthBytes=20570112` (если размер больше не менялся), `HistoricalAuditShaPreserved=True`, и новый SHA256 `PreflightDigest`.

**Реальный `Move` НЕ запускать без явного отдельного разрешения после изучения отчётов.** Повторный ARCH3w1 Prepare или повторная генерация старых Seal запрещены. Любое не совпавшее семантическое свидетельство — STOP.
