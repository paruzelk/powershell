## Design

`Core/Worker/BW4k7iReopenIntegrity265.ps1` rejects every change to original Claim/SHA/source-zero/target-one/body/attachment/recipients/ten user fields/both changed raw flag bits. It records the exact unique **OUTLOOK.EXE ProcessId and StartTime UTC ticks** before restart, never merely a new COM pointer or folder handle. A separate immutable read-only evidence JSON is written ONCE with UTF-8 BOM / FileMode.CreateNew / Flush(true), under `%LOCALAPPDATA%\OutlookPOP3Archive-BW4k7i-ReopenBaselines\suite-<SuiteId>\fixture-<TestId>.json`. **This is the only new persistent write**; no claim, journal or PST writes.

`Core/Diagnostics/Invoke-OPA265BW4k7iReopenIntegrityReview.ps1` provides `Review` (zero writes), `Capture -WhatIf` (zero writes), explicitly confirmed `Capture` (writes ONLY the immutable evidence JSON), and `VerifyAfterReopen -ExpectedBaselineSha256` (zero writes). In every mode the same exact original SHA-fenced BW4k7g and BW4k7h read-only audits run; these may create/delete short-lived temporary attachment copies only. Both readings must be stable within one real Outlook process.

`VerifyAfterReopen` MUST see a new OS `OUTLOOK.EXE` StartTime after the captured original StartTime. It reopens the archived message by exact pinned target entry/store ID, independently rereads contents/attachments/recipients/state and repeats comparison to unchanged baseline. A successful result establishes **logical Outlook reread across real process termination/restart**, not complete physical PST durability, compaction, unknown-flag acceptance, production readiness or general batch-archiving correctness.
