# ARCH3s — оригинальный ArchiveVerifier на 10 синтетических Outlook MailItem

19 ноября 2026. DEV, CI-only; **никаких реальных переносов Outlook/PST**, `WriterPermit=False`, `ProductionReady=False`.

## Источник и контрольная точка

ARCH3r успешно пройден оператором: исходный реальный `ARCH3q` имеет один независимый postrestart проверенный `Move()` и полностью завершённый original `OperationJournal Intent → Reconciled`, исходный общий индекс **501 запись**, historical `OriginalOperationJournalSha256 = 6c0a0fc58935fe2bb1b5350b1e9d21400cbaccebcdfe40722aa95a3fa08d7d58` и `OriginalSharedIndexSha256 = 5ada35eb30f34ff60dc4b89f23aa071b72cc0b98e5ff57299d61f1714b13d7ae`. ARCH3s НЕ меняет эту контрольную точку, не повторяет старые ARCH3o Move или ARCH3q Commit.

## Что реально исполняет ARCH3s

Создаётся fake Outlook Object Model из десяти `MailItem` класса 43 с разными SourceEntryId/ArchiveEntryId, папками fake POP3 `Входящие` и fake Year 2020 `Входящие`, fake `Namespace.GetItemFromID`, fake `Store.GetRootFolder`, fake `Items.Item(index)` и fake `PropertyAccessor.GetProperty` для InternetMessageId. **Исполняется НЕПОДМЕНЁННАЯ оригинальная функция `Test-OPAArchiveMoves` из `ArchiveVerifier.ps1`** со switch `-RequireSemanticWitness` и десятью ORIGINAL ARCH3r full pre-Move witness. `Test-OPAArchiveMoves` самостоятельно наблюдает источник, проверяет уникальные EntryID, существование папки, физическое количество элементов, direct/fallback поиск и вызывает ОРИГИНАЛЬНЫЙ `Test-OPAArchiveItemFingerprint`.

Для каждого fake MailItem ОРИГИНАЛЬНЫЙ `Get-OPA265ARCH2bMailSemanticWitness` восстанавливает и хеширует subject, sender, To/Cc/Bcc, получателей, Body, HTML, даты, пользовательские флаги и attachment bytes. Fake `SaveAsFile` записывает только временную копию в оригинальное приватное `ARCH2c2` TEMP-подпространство, после чего исходный ARCH2b хеширует фактические байты SHA-256. Никакой Pester `Mock Test-OPAArchiveMoves`, подмены оригинального компаратора или заранее установленного verdict нет.

Успех требует **ровно 10** отдельных записей назначения, отсутствия всех 10 source ID, 10 проверенных оригинальных witnesses, отсутствия MissingEntryIds и запрета неожиданных предупреждений. Допускается только первоначально предусмотренное оригинальным verifier одиночное `STALE_ARCHIVE_ENTRYID_VERIFIED_BY_FINGERPRINT` при *уникальном* совпадающем содержимом в правильной папке. Две копии или одиннадцатый mail — FAIL. Хотя модель включает fake Outlook object facades, она **не является реальным Outlook COM тестом** и не доказывает сохранность физических PST после перезапуска.

## Режимы

- **`VerifierOnly`** (по умолчанию): вызывает original `ArchiveVerifier` на десяти fake MailItems. Никакого `OperationJournal`/`DuplicateIndex` не создаёт и не изменяет. Работает только с fake OS TEMP.
- **`Integration`**: сначала original `Test-OPAArchiveMoves` на fake Outlook. Только если он подтверждает все десять, запускает независимо ORIGINAL ARCH3r TEMP-only `OperationJournal`/`DuplicateIndex` симуляцию: десять `Intent`, десять fake durable `MoveClaimed` + `ProviderInvocation` (без COM), десять original full semantic compares, десять `Reconciled` и десять append-only index entries, независимый readback. При отказе original verifier журнал и индекс вообще не пишутся.

## Полный синтаксис

```powershell
.\Invoke-ARCH3s.ps1 [-Mode VerifierOnly|Integration] [-VerifierFault None|SourceStillPresent|DestinationMissing|ExtraDestination|HtmlDrift|BodyDrift|RecipientDrift|AttachmentDrift|MissingOriginalWitness|DuplicateSourceSelector|DuplicateArchiveSelector|WrongTargetFolder|StaleArchiveIdUnique|StaleArchiveIdAmbiguous] [-JournalFault None|AfterJournalReconciled|AfterIndexAppend] [-FaultAt 1..10] [-SyntheticTempRoot <существующий_каталог_внутри_OS_TEMP>]
```

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `-Mode` | `VerifierOnly` | `VerifierOnly`: только original verifier; `Integration`: original verifier → оригинальные TEMP journal/index при полном PASS. |
| `-VerifierFault` | `None` | Ошибка fake Outlook: исходный ID всё ещё виден, нет/лишний архивный MailItem, Body/HTML/Recipients/AttachmentSHA mismatch, отсутствует witness, дубли selectors, чужая папка, stale ArchiveEntryId с уникальным или неоднозначным fingerprint. |
| `-JournalFault` | `None` | Только при `-Mode Integration`: после N-го `Reconciled` или N-й записи в shared TEMP index. Одновременный verifier и journal fault не допускаются. |
| `-FaultAt` | `4` | Позиция ошибки 1–10. Для `AttachmentDrift` выбирайте номер с вложениями (по умолчанию 4). |
| `-SyntheticTempRoot` | OS TEMP | Сам OS TEMP или существующий каталог строго внутри него; создаётся уникальная `OPA265-ARCH3s-FAKE-<guid>` папка; real PST path запрещён. |

## Команды Windows PowerShell 5.1

```powershell
# НЕ нужен настоящий Outlook и не используется операторский @pin
.\Invoke-ARCH3s.ps1 -Mode VerifierOnly | Format-List
.\Invoke-ARCH3s.ps1 -Mode Integration | Format-List
.\Invoke-ARCH3s.ps1 -Mode Integration -VerifierFault HtmlDrift -FaultAt 4 | Format-List
.\Invoke-ARCH3s.ps1 -Mode Integration -VerifierFault AttachmentDrift -FaultAt 4 | Format-List
.\Invoke-ARCH3s.ps1 -Mode Integration -VerifierFault SourceStillPresent -FaultAt 4 | Format-List
.\Invoke-ARCH3s.ps1 -Mode VerifierOnly -VerifierFault StaleArchiveIdUnique -FaultAt 4 | Format-List
.\Invoke-ARCH3s.ps1 -Mode Integration -JournalFault AfterJournalReconciled -FaultAt 3 | Format-List
.\Invoke-ARCH3s.ps1 -Mode Integration -JournalFault AfterIndexAppend -FaultAt 2 | Format-List
```

Ожидаемый успешный `VerifierOnly`: `OriginalArchiveVerifierTenFakeMailItemsFullSemanticContentMatched`, `OriginalArchiveVerifierPassed=True`, `OriginalArchiveVerifierUsed=True`, `ExpectedMoved=10`, `ObservedSourceCount=0`, `ObservedArchiveFolderCount=10`, `OriginalJournalIndexIntegrationExecuted=False`.

Ожидаемый успешный `Integration`: `OriginalArchiveVerifierTenThenOriginalJournalIndexTenFullReadbackNoLiveWriter`, `OriginalJournalEventCount=20`, `OriginalJournalReconciledCount=10`, `OriginalSharedIndexEntryCount=10`. При ошибке verifier нет даже синтетического commit. При ошибке `JournalFault` возвращается состояние частичного journal/index и `AutomaticMoveRetryAllowed=False`. Файлы остаются только в `SyntheticWorkspace`/`OriginalJournalWorkspace` для повторного read-only анализа.

## CI и следующий барьер

23 новых Pester, целевой полный набор **4536 тестов в 153 контейнерах** плюс PSScriptAnalyzer, проверка UTF-8 BOM, project-only ZIP и SHA-256. CI выполняет fake Outlook и original ARCH2b SaveAsFile SHA на изолированных временных байтах. **Не работает с реальными PST, Outlook, сетью, основным Journal или DuplicateIndex.**

**Остаётся для следующего этапа:** полностью доказанное восстановление частичного десятиписьменного original index без Move, затем отдельный явно подтверждённый реальный тестовый batch-10 на `info@stios.ru.pst` с независимым перезапуском Outlook. Production writer 90 ГБ всё ещё закрыт.
