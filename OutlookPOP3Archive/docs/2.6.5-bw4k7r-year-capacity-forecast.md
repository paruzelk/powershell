## Technical behavior

New worker Core/Worker/BW4k7rYearCapacityPlan265.ps1 contains pure in-memory data accumulation and conservative capacity estimates, never Outlook operations.

New controller Core/Diagnostics/Invoke-OPA265BW4k7rPop3YearCapacityReview.ps1:
- Runs original BW4k7q exact POP3-only classification before and after scan, checks complete folder identity/EntryID/disposition/count stability, exact profile and POP3 DeliveryStore, source file length and OUTLOOK.EXE process ID/start time.
- Opens only BW4k7q IncludedInProposedPop3Scope=True folders via NameSpace.GetFolderFromID with exact StoreID; rejects reserved test folders, system folders, Outbox, other POP3 or IMAP stores.
- Forward-only Outlook Items.GetFirst/GetNext, reading only Item.EntryID (duplicate guard), Class, ReceivedTime/SentOn and MailItem.Size. NO bodies, recipients, headers, attachment metadata or bytes; NO Save, Move, Delete, PST creation, registry edit, Evidence/Claim/journal write.
- Counts per year + Inbox/Sent/UserMail and per original folder/year. Sent prefers SentOn, others ReceivedTime; fallback dates and undated mail explicitly counted; nonmail classes excluded. Year range 1990–2100; no fabricated year or automatic fallback waiver.
- Emits Write-Progress every 250 items (configurable).
- Defaults MaxTotalItems=5000 and MaxItemsPerFolder=5000. Such a scan is PARTIAL with the prior 26605-message Inbox, and its yearly values are only observed lower bounds. To enumerate the prior 26605 candidate items in one run, request both caps 50000. Interrupted scans must restart from beginning; there is NO durable resume checkpoint, NO cross-run accumulation or atomic PST snapshot claim. A stable folder count does not prove no same-count edits.
- YearDistributionComplete=True requires all included candidate items enumerated AND no undated mail. Fallback dates get separate review status even when every item is read. This still does not prove content equality, physical PST integrity or production writer safety.
