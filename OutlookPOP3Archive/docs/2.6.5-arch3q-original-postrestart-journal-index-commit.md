## Реализовано

`ARCH3qState.ps1` читает оригинальные свидетельства и оригинальный журнал/индекс **на чтение**, поддерживает строго `Intent` (1 event) и `Intent → Reconciled` (2 events); в последнем случае побайтово проверяет SHA первого исходного Intent-записи даже после append. Индекс допустим только с 500 исходными записями или с 501 записью для завершения/восстановления и строго закреплённым новым EntryID/Part2. Чужие файлы или reparse points в защищённом evidence-каталоге запрещены.

`ARCH3qEvidence.ps1` проверяет **точные исходные SHA** всех пяти immutable ARCH3o-файлов и sealed оригинального full ARCH3i witness. Вызывает исходный `Invoke-OPA265ARCH3pIndependentRestartReview`, который требует реального перезапуска Outlook и оригинальный `Test-OPAArchiveMoves`. При переходе журнала в `Reconciled` создаёт безопасный путь прямой повторной верификации без устаревшего ARCH3p Intent-only входа.

`Invoke-ARCH3q.ps1` имеет только шесть режимов:

| Режим | Назначение | Запись |
| --- | --- | --- |
| `Plan` / `Status` | Читает текущий журнал, индекс и evidence; показывает 500/501 и стадии | Нет |
| `Seal` | Независимо повторяет настоящий Outlook + original ArchiveVerifier, сохраняет `ARCH3q-IndependentReview.json` через CreateNew+Flush(true) | Только защищённое evidence |
| `Commit` | Повторяет оригинальную реальную верификацию, пишет необратимый `ARCH3q-CommitClaim.json`, затем **один** original `Write-OPAOperationJournalEvent -Phase Reconciled`, readback, затем **один** original `Add-OPADuplicateEntry` в shared append-only JSONL и readback 501, финальный seal | Да: настоящий journal/index |
| `Recover` | Только после *существующего* `Reconciled` и незавершённого финального index-seal. С индексом 500 повторно проверяет оригинальным verifier, дописывает одну запись. С индексом 501 только проверяет её и завершает seal; **не пишет второй Reconciled и никогда не вызывает Move** | Возможно только недостающая index-запись/seal |
| `Review` | Независимо считывает final SHA исходного Reconciled, индексную JSONL и проверяет точные 501 записей | Нет |

На любом несоответствии — STOP, preserve all protected evidence; не повторять `ARCH3o -Mode Move`. Частичный оригинальный journal без полного Reconciled не подлежит автоматической коррекции.

## Полный синтаксис

```powershell
.\Invoke-ARCH3q.ps1 [-Mode Plan|Seal|Commit|Recover|Status|Review] -RunId <string> -IntentSha256 <SHA256> -JournalSha256 <SHA256> [-ReviewSha256 <SHA256>] [-CommitClaimSha256 <SHA256>] [-CommitSealSha256 <SHA256>] [-ConfirmSeal] [-ConfirmVerifiedCommit] [-ConfirmRecovery] [-WhatIf] [-Confirm:$false]
```

Ключи `-ReviewSha256`, `-CommitClaimSha256`, `-CommitSealSha256` должны быть взяты из **предыдущих фактических результатов этапов**, не придумывать и не менять. Явное подтверждение каждого изменяющего режима обязательно: `-ConfirmSeal`, `-ConfirmVerifiedCommit`, `-ConfirmRecovery` соответственно. `-Confirm:$false` лишь отключает дополнительный интерактивный запрос PowerShell и не заменяет обязательные подтверждения. Windows PowerShell 5.1 STA обязателен для `Seal`, `Commit`, `Recover`.

## Рекомендуемая последовательность на тестовом Outlook

```powershell
$pin = @{
    RunId = '9d276dc4-a0e6-4e74-891f-81502fafe7db'
    IntentSha256 = 'f0860d55c5939498094832a8b924dbca9b65532cf53f8234f4aeda97ab631a2b'
    JournalSha256 = 'a19f113a6454b1d17333c9a53fc22d065876754b9fbab3167087487d0b2b981e'
}
.\Invoke-ARCH3q.ps1 -Mode Plan @pin | Format-List
.\Invoke-ARCH3q.ps1 -Mode Status @pin | Format-List
.\Invoke-ARCH3q.ps1 -Mode Seal @pin -ConfirmSeal -WhatIf | Format-List
```

Только после проверки этих результатов выполняется реальный **только evidence** Seal:

```powershell
$sealed = .\Invoke-ARCH3q.ps1 -Mode Seal @pin -ConfirmSeal -Confirm:$false
$sealed | Format-List
```

Проверьте вывод `ReviewSha256`, убедитесь, что `OriginalIndexEntries=500`, исходный Journal `Intent`, и только после отдельного операторского решения выполняйте:

```powershell
$committed = .\Invoke-ARCH3q.ps1 -Mode Commit @pin -ReviewSha256 $sealed.ReviewSha256 -ConfirmVerifiedCommit -Confirm:$false
$committed | Format-List
.\Invoke-ARCH3q.ps1 -Mode Review @pin -ReviewSha256 $sealed.ReviewSha256 -CommitClaimSha256 $committed.CommitClaimSha256 -CommitSealSha256 $committed.CommitSealSha256 | Format-List
```

**При ошибке Commit не повторять Commit, не выполнять Move.** Для расследования использовать только `Status`. Если статус показывает `Reconciled`, завершение индекса возможно через строго проверяемый `Recover` с `-ReviewSha256` и `-CommitClaimSha256`, после независимого анализа. Не выполнять Recover с другим журналом или неясным индексом.
