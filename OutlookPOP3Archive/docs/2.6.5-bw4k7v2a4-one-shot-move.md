# BW4k7v2a4 — one NEW synthetic default Draft and ONE manually approved Outlook MailItem.Move

## Verified reason for the experiment

The old BW4k7v2a1 SuiteId `2c15cb7c-4c09-4bcf-bca1-9fec458af3a5` was found in `\\bogoderov_e@stios.ru\Drafts`, not in the newly attached intended test PST. The independent BW4k7v2a3 read-only operator observation checked all 9 stores and found exactly one matching `MailItem` (Class=43) in the **default** store Drafts (StoreIndex 1), with exact by-ID identity and zero matches in the disposable test PST Drafts. The old fixture and evidence **MUST NOT** be retried, modified, detached, deleted or moved by this stage.

Microsoft Outlook explicitly documents that `MailItem.Save()` saves a new message to the default folder for the item type, while `MailItem.Move(targetFolder)` moves an existing object to a specified folder and returns the moved object. Source: https://learn.microsoft.com/en-us/office/vba/api/outlook.mailitem.save and https://learn.microsoft.com/en-us/office/vba/api/outlook.mailitem.move.

BW4k7v2a4 deliberately creates a **new unique SuiteId** and **one new synthetic unsent message in the existing default Drafts**, confirms its actual StoreID/FolderID/EntryID, attaches **one fresh Unicode disposable PST**, creates the exact destination folder, seals one immutable pre-Move semantic witness and requires a **separate explicit Move approval**.

**Important risk:** The default `Drafts` location observed on the operator system is `\\bogoderov_e@stios.ru\Drafts`, which can be server-synced if the account is IMAP. `CreatePilot` intentionally creates one new synthetic Draft there and `MovePilot` subsequently removes that specific synthetic Draft by moving it into the new disposable PST. These are actual mail-store writes, not only file operations on the disposable PST. Confirm this is acceptable before invoking either writer step. The script does not touch any other messages in that default Drafts folder and does not access the original POP3 delivery PST mail.

## Intended operator sequence

Extract the project-only DEV ZIP to a **new** folder. Open the existing `Outlook` profile (only one OUTLOOK.EXE process). Use native Windows PowerShell **5.1 STA**; Pester and PSScriptAnalyzer must be installed for the first command.

```powershell
.\Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'

$script = '.\Core\Diagnostics\Invoke-OPA265BW4k7v2a4OneShotMove.ps1'
$plan = & $script -Mode Plan
$plan | Format-List
& $script -Mode Prepare -SuiteId $plan.SuiteId -Confirm:$false
$inspect = & $script -Mode Inspect -SuiteId $plan.SuiteId
$inspect | Format-List
```

Require `ExistingProfilePop3AndDefaultDraftsVerifiedFreshTestPstAbsent`. Confirm the actual `DraftsFolderPath` in this output and that the PST is fresh. No default mail/PST changed during Plan, Prepare (except suite folder), or Inspect.

### First separate approval: create exactly one disposable synthetic Draft

```powershell
$created = & $script -Mode CreatePilot -SuiteId $plan.SuiteId `
  -AllowDefaultDraftsSyntheticWrite `
  -ApprovalText ('CREATE BW4K7V2A4 DRAFT ' + $plan.SuiteId) -Confirm:$false
$created | Format-List

$preMove = & $script -Mode ReviewPilot -SuiteId $plan.SuiteId `
  -ExpectedManifestSha256 $created.ManifestSha256
$preMove | Format-List
```

Require both `OneSyntheticDraftSavedInDefaultStoreAndSeparateEmptyPstSealed` and `ExactSyntheticDraftOneTargetZeroOriginalManifestVerifiedNoMove`. The source witness is SHA-256 over synthetic `Class`, `Subject`, `Body`, `To`, `Unread`; raw `PR_MESSAGE_FLAGS` and message Size are recorded **separately**. No actual Calendar-year provenance or full production message semantics is proven.

### Second separate approval: ONE irreversible Move

Only after verifying the previous output, explicitly authorize this one new synthetic message (not the old fixture). This is a **different command and approval**.

```powershell
$moved = & $script -Mode MovePilot -SuiteId $plan.SuiteId `
  -ExpectedManifestSha256 $created.ManifestSha256 `
  -ConfirmOneShotMove `
  -ApprovalText ('MOVE BW4K7V2A4 ONCE ' + $plan.SuiteId) -Confirm:$false
$moved | Format-List
```

**Before the COM `MailItem.Move` call**, a durable `one-shot-move-claim.json` is written with `FileMode.CreateNew` and `Flush(true)`. This records the original source EntryID, store, target and witness. The code issues exactly **one Move call**, and does not retry even if the COM call fails or the worker crashes. `SingleOutlookMoveReturnedRequiresIndependentReconciliation` is **not** proof of successful semantic preservation or durability.

Completely close Outlook, confirm no OUTLOOK.EXE remains, then reopen the **same Outlook profile**.

```powershell
$result = & $script -Mode Reconcile -SuiteId $plan.SuiteId `
  -ExpectedManifestSha256 $created.ManifestSha256 `
  -ExpectedClaimSha256 $moved.ClaimSha256
$result | Format-List
$result.Reconciliation | Format-List *
```

Expected **only after real provider verification**: `OneShotMoveReconciledSyntheticContentMatchSEM001ManualReview` with source matching subject count **0**, destination count **1**, pinned StoreID/FolderID and synthetic content witness. Review `SourceRawMapiFlags` vs `DestinationRawMapiFlags`, source/destination message sizes, and flags presence manually. Do **not** silently waive any changes.

If `MovePilot` throws **after the claim file exists**, do **not** retry. Instead obtain claim SHA256 from the original file:

```powershell
Get-FileHash -LiteralPath (Join-Path $plan.SuiteDirectory 'one-shot-move-claim.json') -Algorithm SHA256
```

Then use **Reconcile** with the returned lowercase SHA256 after fully restarting Outlook. Do not reconstruct or edit old evidence. If `CreatePilot` fails, keep its PST and `create-intent.json`; use a fresh SuiteId only following separate failure review. Do not delete the original prior test letter in default Drafts.

## Boundaries and release safety

- New tests use existing profile `Outlook` and require POP3 account `info@stios.ru`, but **forbid** using that POP3 delivery store as the default synthetic Drafts source or target. This isolates from original POP3 mail; it does not make the default IMAP mailbox disposable.
- One GUID-scoped new Unicode PST; one new synthetic Draft, one target folder and a single `MailItem.Move` from exact pinned source EntryID. No other MailItem move, no Sent, Outbox, Inbox or old forensic fixtures touched.
- CreateIntent, original pre-Move Manifest, MoveClaim, optional MoveReturn observation are separate immutable write-once UTF-8 JSON files with SHA-256. A Move call is forbidden until its claim is durably sealed.
- `-WhatIf` causes no Outlook contact or files written. No automatic retry, cleanup, fallback, source Draft deletion, Move reissue or journal completion claim.
- The destination may have another `EntryID`, `MailItem.Size` and raw `PR_MESSAGE_FLAGS` after Move. This stage collects evidence, does not grant SEM-001 metadata/flag risk acceptance and does not prove full MAPI/attachment content equality, production POP3 archive, crash durability or PST rollover.
- New/changed PowerShell source UTF-8 BOM; original CI PS5.1 Pester/PSScriptAnalyzer/JSON/legacy BOM exception and BW4j6 fault matrix mandatory. Synthetic CI **cannot** run Outlook COM.
- `ProductionReady=False`, `WriterPermit=False`, Archive/Resume/Auto worker integration remains off.

Target: **3480 Pester tests in 118 containers** plus the original BW4j6 matrix.
