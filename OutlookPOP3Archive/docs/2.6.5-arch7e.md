# ARCH7e DEV — Auto для всех POP3, отбор по возрасту

ARCH7c/d приняты по реальному тесту ARCH7d2, [доказательства](2.6.5-arch7d.md). Повторять не требуется.

## Тестовый режим

~~~powershell
.\OutlookPOP3Archive.ps1 -Mode Auto -ConfirmDevAutoArchive [-ProfileName <string>] [-Limit <0..10>] [-AutoDevMaxBatches <1..100>] [-OlderThanMonths <1..1200>] [-ArchiveGrouping <Year|YearQuarter|YearMonth>] [-IncludeRootMail] [-DisableStoragePolicy] [-DisableArchivePstSizeLimit] [-DurabilityMode Safe] [-AutoMaxResumeAttempts <1..10>] [-WhatIf]
~~~

| Параметр | Default DEV Auto | Назначение |
|---|---|---|
| Mode | Auto явно | Legacy Auto не открывается |
| ConfirmDevAutoArchive | False | согласие на изменение ВСЕХ обнаруженных POP3 delivery PST; каждый должен быть тестовым |
| ProfileName | текущий | AttachOnly, без смены профиля |
| Limit | 0 → 10 | размер партии 1–10; не суммарный лимит |
| AutoDevMaxBatches | 100 | число вызовов контроллера на PST, включая проверку исчерпания |
| OlderThanMonths | 12 | только возраст, не размер источника |
| ArchiveGrouping | YearQuarter | годовой PST, квартальные папки |
| IncludeRootMail | True | корневые письма; можно явно False |
| DisableStoragePolicy | True | политика 40/35 GB не участвует |
| DisableArchivePstSizeLimit | True | cap утилиты отключён; Outlook/FS и контроль места сохраняются |
| DurabilityMode | Safe | нельзя Fast |
| AutoMaxResumeAttempts | 3 | 1–10 на вызов контроллера |
| WhatIf | False | проверка конфигурации без COM, дисковых записей и discovery |

Mode без подтверждения остаётся закрытым; default основного скрипта пока Analyze. Параметры SourcePst, IncludeFolderPath, Transaction, IgnoreAge, historical import/faultpoint, worker pilot и legacy policy не разрешены в этом Auto.

## Первое испытание после CI PASS

Проверить, что все POP3 ящики текущего Outlook являются тестовыми. Оставить Outlook открытым. Начать с одного вызова контроллера на каждый PST:

~~~powershell
$before=Get-Process OUTLOOK | Select-Object Id,StartTime
$opts=@{Mode='Auto';ConfirmDevAutoArchive=$true;AutoDevMaxBatches=1}
.\OutlookPOP3Archive.ps1 @opts -WhatIf
~~~

После NoOutlookOrPersistentWrites и подтверждения всех POP3:

~~~powershell
$result=.\OutlookPOP3Archive.ps1 @opts
$result | Format-List
$result.Sources | Format-List
$result.Sources | ForEach-Object {$_.LastResult | Format-List}
$before
Get-Process OUTLOOK | Select-Object Id,StartTime
~~~

Ожидается обнаружение только POP3, сохранение Outlook PID/start, отдельный результат источника. BatchLimitReached / PartialOrBlocked при лимите первого теста ожидаем, не означает полную архивацию. AllSourcesExhausted только после подтверждённого исчерпания каждого источника; Deferred учитывается отдельно. NoPop3Sources не создаёт Archive worker. Если ошибка, не повторять автоматически; сохранять Pending и логи. Не использовать с производственными PST. Для доказательства многопочтовой работы нужен профиль с двумя уникальными тестовыми POP3; при одном POP3 проверяется только обнаружение/маршрутизация одного и исключение IMAP.

## Архитектура и границы

AttachOnly discovery берёт только прямой AccountType=2 DeliveryStore, уникальные StoreID и нормализованные существующие локальные .pst; исключены IMAP/архивные файлы, неоднозначное совместное владение, fallback по DisplayName. Не создаёт Outlook и не переключает профиль. Передаёт простые строки/идентификаторы, закрывает COM session перед дочерними worker. Auto dispatcher mutex отдельный от исходного worker mutex.

Каталоги транзакций не мигрируются. ARCH4.pending/lease являются общими для PST в одном физическом каталоге. Владелец Pending определяется по SourcePst, StoreID, Profile, сначала восстанавливается; чужой/невалидный Pending блокирует весь общий каталог. Один источник за раз, отсутствие перезаписи чужих журналов. После подтверждённой партии следующая селекция заново использует возраст и существующий deferred ledger; не повторяет неопределённые Move. Остановка при отсутствии прогресса, burst export errors, неизвестном коде выхода, активном зависшем worker, исключении supervisor. При известной завершённой ошибке с Pending блокируются соседи общего каталога; независимые каталоги могут продолжать. При неизвестном состоянии worker останавливается весь Auto. Перечень источников фиксируется на запуск. Обнаружение новых ящиков при следующем запуске.

DEV cap 10 писем, до 100 вызовов на источник, не 500/unlimited. Независимые физические pending для PST в одном каталоге, постоянный retry budget между логинами, защита от всех внешних ручных запусков, quiet/log retention/throttle/RDS и 90+ GB остаются будущими этапами. Не доказана физическая сохранность кэша Outlook при power loss. ProductionReady=False. Не устанавливать как задачу RDS.

CI использует синтетические stores, реальные дочерние STA процессы со stub и копию реального публичного Auto entry/controller; настоящий Outlook в CI не запускается. 95 focused / 4909 total expected, 165 containers.
