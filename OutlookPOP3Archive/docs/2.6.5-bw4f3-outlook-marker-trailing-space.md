# BW4f3 — strict Outlook-added single trailing ASCII space on synthetic marker lines (DEV)

## Root cause proven from operator's actual test POP3 MailItem

Selected message in source POP3 PST Inbox:
- Subject: OPA265 BW4e1 FRESH TEST 98bef817-0fb5-478a-b869-33f02fda59d3
- EntryID: 00000000E1878292411BC64291BD506DCEFD2A35C4613C00
- BodyLength=250, NormalizedLength=243, CR=7, LF=7, CRCRLF=0
- HeaderPresent=True; TestIdPresent=True; Attachments.Count=0.
- Every nonempty line printed via ConvertTo-Json ends with a literal
  ASCII SPACE U+0020 immediately before the CRLF delimiter, e.g.:
  "OPA265 BW4e1 disposable synthetic test. "
  "TestId: 98bef817-0fb5-478a-b869-33f02fda59d3 "

BW4f2 had already normalized CRLF correctly but required the marker
regex to terminate immediately after "." and GUID. It therefore
classified the correct test mail as IsExactOperatorFixture=False.

## Minimal BW4f3 repair

The two marker regexes accept zero or EXACTLY ONE literal ASCII space
before normalized LF/EOL. No global Trim, no whitespace wildcard and
no normalization of content itself. Reject:
- 2+ spaces, tabs, NBSP or Unicode invisible code points;
- missing header, wrong subject or unequal TestId, duplicate TestId,
  invalid GUID, any attachments or unreadable Attachments collection;
- unknown/previously used Live3/BW3a operation, mutated historical
  evidence, forged Worker/Move permit.

The actual MailItem.Body and existing BW4c content fingerprint SHA256
are unchanged. Preserve the original single unresolved Intent and all
seven pinned historical evidence SHA256 values. Production Archive/
Resume/Auto Worker remains disabled. This is read-only classification
only, NOT a new authorization to Move.
