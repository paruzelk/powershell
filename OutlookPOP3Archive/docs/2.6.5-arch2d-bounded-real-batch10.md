# ARCH2d — проверяемая партия из 10 реальных писем POP3

**Состояние:** DEV. Исполнение в Outlook проводит оператор; GitHub Actions не подключается к Outlook/PST. Предыдущий ARCH2c4a `RunId=18585296-c1f6-4859-97d1-1f9d272b9e07` успешно проверен, его манифесты/заявки/архив сохраняются неизменными. **Новый этап использует новый RunId и новую папку ARCH2d**, а не переиспользует и не очищает старый архив.

## Что реализовано

- Используется **тот же существующий POP3 PST** `C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst`, только реальные `MailItem` из его папки `Inbox`. Профиль строго `Outlook`, POP3 учётная запись `info@stios.ru`, её `DeliveryStore` должен точно совпасть с PST. Источник не может быть default store.
- Пять операций `Plan`, `Inventory`, `Prepare`, `MoveBatch`, `Reconcile`. `Plan` не обращается к Outlook. `Inventory` только читает; показывает до 16 кандидатов из первых 128 сообщений, максимум 10 выбирается оператором.
- **Строго десять** уникальных операторских `EntryId`, никаких резервных кандидатов или незаметной замены писем. Каждому сопоставлен SHA-256 исходного `Body`, `HTMLBody`, sender, `To/Cc/Bcc`, упорядоченных адресатов, временных меток, категорий, состояния `UnRead` и фактических байтов вложений (`Attachment.SaveAsFile` с защищённым TEMP из ARCH2c2). Для неподдерживаемых типов вложений `Prepare` остановится без создания нового PST; прикладной `MailItem.Size` только диагностический.
- **Ровно один** новый PST как **назначение архива**: `%LOCALAPPDATA%\OutlookPOP3Archive-ARCH2d-RealBatch10\run-<RunId>\OPA265-ARCH2d-<RunId>.pst`. Никаких новых синтетических исходных PST/писем.
- При `Prepare` исходные десять SHA256 снимаются до какого-либо создания целевого PST; затем пишется `prepare-intent.json` с create-new + `Flush(true)`, создаётся назначение через `AddStoreEx`, папка и immutable `pre-move-manifest.json`. При аварии внутри `Prepare` **тот же RunId не повторять**.
- Перед `MoveBatch`: второй полный read-only semantic preflight *всех 10*, проверка неизменности StoreID/FolderID и того же Outlook PID и процесса старта, пустого назначения, исходного sealed manifest SHA256, отсутствия любого старого batch claim. Только после отдельного подтверждения оператором пишется глобальная неизменяемая `ARCH2d-BATCH-ONCE-CLAIM.json`, затем для каждого письма **перед `MailItem.Move()`** пишется и force-flush-ится его `move-01-claim.json`, …, `move-10-claim.json`; успешный ответ Outlook отдельно фиксируется `move-01-return.json`, … . При ошибке, плохом исходном witness, несоответствии количества писем или exception — **немедленный STOP**, без `continue`/повтора/автовосстановления. Сам глобальный claim запрещает повторную партию даже с новым RunId.
- После **полного перезапуска Outlook** режим `Reconcile` читает immutable manifest + глобальный claim, сверяет каждое исходное EntryId и десять исходных semantic witness с элементами архива. Дубли по подписи, неизвестные объекты, нехватка original Entries, неизвестный COM исход — ручная проверка. `Reconcile` не создаёт/монтирует PST, не изменяет письма/журнал и никогда не разрешает повторный Move.
- **Production `OutlookPOP3Archive.ps1 -Mode Archive/Resume/Auto` заблокированы ARCH2a**, включая `-WhatIf`; этот DEV пилот не активирует пакетное производство.
- При `-WhatIf` для `Prepare` и `MoveBatch` нет контакта с Outlook, создания PST или журналов.

## Операторский сценарий: выполнять последовательно, после проверки каждого результата

Распакуйте только опубликованный ZIP ARCH2d; в Windows PowerShell 5.1 STA из корня `OutlookPOP3Archive-2.6.5-ARCH2d-dev-g<commit>`, при работающем Outlook `Outlook`.

### 1. Plan и Inventory (без изменений PST)

```powershell
$source='C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'
$run=[guid]::NewGuid().ToString('D')
$cmd='.\Invoke-ARCH2d.ps1'
& $cmd -Mode Plan -RunId $run -SourcePst $source | Format-List

$inventory=& $cmd -Mode Inventory -RunId $run -SourcePst $source
$inventory | Format-List
$inventory.Candidates | Format-Table -AutoSize
```

Ожидаем `BoundedTenRealPop3SourcePlanNoOutlookNoWrites`, затем `ReadOnlyTenCandidatePop3InboxInventory`. Выберите **ровно 10** уникальных `EntryId`, без повторов, только из выведенных кандидатов. Например:

```powershell
$entries=@($inventory.Candidates | Select-Object -First 10 -ExpandProperty EntryId)
$entries.Count
```

### 2. Prepare (создаёт **только целевой** PST и неизменяемые записи)

```powershell
& $cmd -Mode Prepare -RunId $run -SourcePst $source -SourceEntryIds $entries -WhatIf | Format-List

$prepared=& $cmd -Mode Prepare -RunId $run -SourcePst $source -SourceEntryIds $entries `
    -ConfirmBatchPreparation -ApprovalText ('PREPARE ARCH2D '+$run) -Confirm:$false
$prepared | Format-List
```

Ожидается `TenOriginalSemanticWitnessesSealedFreshArchivePreparedNoMove`, `PreparedCount=10`, `MoveAlreadyAttempted=False`. Сохраните `ManifestSha256`. Если исключение при `Prepare`, **не повторяйте Prepare** до анализа файлов, даже если кажется, что операции не было.

### 3. MoveBatch (реальное необратимое действие на 10 писем)

**Не перезапускайте Outlook** после успешного `Prepare` и до `MoveBatch`. Если Outlook перезапущен, пилот fail-closed; нельзя вручную обходить проверку процесса.

```powershell
$manifestSha=[string]$prepared.ManifestSha256
& $cmd -Mode MoveBatch -RunId $run -SourcePst $source -ManifestSha256 $manifestSha -WhatIf | Format-List

$batch=& $cmd -Mode MoveBatch -RunId $run -SourcePst $source -ManifestSha256 $manifestSha `
    -ConfirmBatchMove -ApprovalText ('MOVEBATCH ARCH2D '+$run) -Confirm:$false
$batch | Format-List
```

Ожидается `TenOutlookComMovesReturnedIndependentRestartVerificationRequired`, `Claimed=10`, `MoveReturned=10`, `IndependentlyVerified=0`. **НИКОГДА** не повторять `MoveBatch`, в том числе если PowerShell/Outlook упал после первого письма, не пытаться начать новую партию, стирать claim или удалять архивацию.

### 4. Reconcile (только после перезапуска Outlook)

Штатно закройте Outlook и убедитесь, что `OUTLOOK.EXE` завершился; откройте снова. На время запроса верните фокус в PowerShell, чтобы `GetActiveObject` увидел Outlook COM.

```powershell
$batchClaimSha=[string]$batch.BatchClaimSha256
$review=& $cmd -Mode Reconcile -RunId $run -SourcePst $source `
    -ManifestSha256 $manifestSha -BatchClaimSha256 $batchClaimSha
$review | Format-List
$review.Items | Format-Table -AutoSize
```

При полном успехе ожидается `AllTenIndependentPostRestartSemanticMatches`, `VerifiedMoved=10`, `NotAttempted=0`, `TargetFolderItemCount=10`, `UnknownDestinationItems=0`, `DuplicateSemanticSelectors=0`, `OutlookRestartConfirmed=True`. Поля `OriginalMoveMayBeRetried=False` и `ProductionReady=False` останутся.

Если ошибка выполнения `MoveBatch` не вернула объект `$batch`, для **read-only** Reconcile можно получить SHA существующего глобального claim (не создавать/не изменять):

```powershell
$globalClaim=Join-Path (Join-Path $env:LOCALAPPDATA 'OutlookPOP3Archive-ARCH2d-RealBatch10') 'ARCH2d-BATCH-ONCE-CLAIM.json'
if(Test-Path -LiteralPath $globalClaim -PathType Leaf){
    $batchClaimSha=(Get-FileHash -LiteralPath $globalClaim -Algorithm SHA256).Hash.ToLowerInvariant()
}
```

Любая ошибка, неполная партия, нераспознанное письмо — сохранять все свидетельства и остановиться. Переходить к 100 письмам только после предметной ручной проверки результатов.

## Ограничения

- Один запуск ARCH2d — строго 10 реальных писем **только Inbox**, не Sent/custom; не полноценное архивирование по годам.
- Глобальный claim необратим по дизайну: ARCH2d не выполняет автоматический Resume после crash. Разработка отдельного проверенного механизма recovery — следующий этап.
- Не производится реальный fault injection с отключением питания; CI использует эмуляции и не подтверждает crash consistency Outlook PST на 90 ГБ.
- Проверка отсутствия исходного **старого EntryID** не является полным перебором всех возможных копий под другими ID.
- Подлинные письма с вложениями нужно включать среди операторских кандидатов и проверять отдельно. Нет разрешения на массовую production-архивацию.
- `MailItem.Size` и MAPI provider flags, включая историческую неопределённость флагов, остаются диагностическими. Совпадение размера не служит доказательством целостности; известный size drift сам по себе не является доказательством повреждения.
