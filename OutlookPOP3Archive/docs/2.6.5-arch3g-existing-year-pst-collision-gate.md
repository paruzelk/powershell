# ARCH3g — контроль существующего годового PST и точного исходного письма

**Режим:** только чтение, не является первым реальным переносом.  
**Основа:** прошедшая операторскую проверку ARCH3f на `info@stios.ru.pst`.  
**Операторский факт:** `C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.Archive-2020.pst` уже существует. Его нельзя перезаписывать, молча использовать для первого нового пилота или считать пустым.  
**Источник:** `C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst`, отмеченный оператором как тестовый с реальными письмами.

## Запуск (Windows PowerShell 5.1 STA; из папки проекта)

```powershell
$source = 'C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'
$id = '00000000E1878292411BC64291BD506DCEFD2A35E4FC3B00'

# Читает имена/размеры файлов в каталоге; Outlook не открывает.
.\Invoke-ARCH3g.ps1 -Mode Plan -SourcePst $source -SourceEntryId $id -ArchiveYear 2020 | Format-List

# Точное письмо Inbox/StoreID и реальный счётчик вложений; никаких перемещений.
$audit = .\Invoke-ARCH3g.ps1 -Mode Audit -SourcePst $source -SourceEntryId $id -ArchiveYear 2020
$audit | Format-List Schema,Status,ExistingYearArchiveCollision,ExistingPartCount,NextUnusedPartPathPreview,NextUnusedPartNotReserved,ExactInboxItemIndependentlyLocated,AttachmentCount,SourceArchiveDate,OriginalTargetFolderPath,WriterPermit,ProductionReady
$audit.ExistingParts | Format-Table Part,Path,FileLengthBytes -AutoSize
```

Не запускать 64-битный PowerShell 7 вместо `powershell.exe` 5.1; запуск `Audit` требует STA, Outlook 2019 с профилем `Outlook`, и единственного процесса Outlook в той же Windows-сессии.

| Параметр | Значения | Умолчание | Значение |
| --- | --- | --- | --- |
| `-Mode` | `Plan` или `Audit` | обязательный | План читает только каталог; Audit подключается к уже запущенному Outlook |
| `-SourcePst` | точный локальный `info@stios.ru.pst` | обязательный | Проверка существующего тестового источника; для Audit файл должен существовать |
| `-SourceEntryId` | 16–1024 шестнадцатеричных символов | обязательный | Идентификатор ОДНОГО письма, полученный в ARCH3f |
| `-ArchiveYear` | 1900–2100 | `2020` | Ожидаемый год исходного ArchiveSelector |

`Plan` и `Audit` используют только существующую исходную логику `Get-OPAArchivePstPartsOnDisk`, `Get-OPAArchivePartPath`, `Get-OPAArchiveItemDate`, `Get-OPAArchiveTargetPath`; `Audit` дополнительно повторяет строгий `Open-OPA265ARCH2dSession` и проверяет точное письмо по `Namespace.GetItemFromID(EntryID,StoreID)`, класс 43, точную исходную папку Inbox, StoreID и год. Отсутствие совпадения блокирует приёмку.

`AttachmentCount=-1` из ARCH3f — неизвестное значение без прямого чтения; ARCH3g Audit читает фактический `MailItem.Attachments.Count`, но ещё НЕ выполняет full semantic witness и SHA-256 вложений. Исходный архив `Archive-2020.pst` может содержать письма: инструмент читает метаданные файлов, **не подтверждает их содержимое**. Поле `NextUnusedPartPathPreview` обозначает только предварительное имя из исходного алгоритма Part N+1; оно **не резервирует PST и не разрешает никакой writer**. Повторно проверять свободный путь нужно непосредственно перед любым будущим `PrepareIntent`.

## Запреты и дальнейшая интеграция

В ARCH3g нет реального `MailItem.Move`, создания PST, изменения оригинальных архивов, `OperationJournal`, `DuplicateIndex` или восстановления; `WriterPermit=False`, `ProductionReady=False`, `AutomaticRetryAllowed=False`.

Следующий этап — отдельная строго однократная реальная интеграция исходного `MailMover` с **новым** назначением, закреплёнными `EntryID/StoreID/FolderID`, original ARCH2b полным Body/HTML/получателями/attachment SHA256 witness, `PrepareIntent` до любых изменений, immutable `MoveClaimed` до COM, read-only независимой проверкой после настоящего рестарта Outlook и только после этого коммитом оригинального Journal/Reconciled и DuplicateIndex. Запрещено отключать synthetic-only ограничения ARCH3d/ARCH3e, повторять любые старые RunId, автоматически повторять неопределённый Move или включать массовый `Archive/Resume/Auto`.

Это дополнительный **read-only** этап из-за выявленного существующего PST. Реальные переносы ARCH2c4 / ARCH2d / ARCH2d5 остаются отдельными ранее зафиксированными испытаниями, а не частью приёмки ARCH3g.
