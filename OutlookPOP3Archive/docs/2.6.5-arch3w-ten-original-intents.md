# ARCH3w — десять ORIGINAL OperationJournal Intent из запечатанного ARCH3v, без Move

**20 ноября 2026 — DEV / protected evidence-only original journal.** Предыдущий этап **ARCH3v** успешно завершил `Seal` и независимый `Review` для 10 реальных писем и 12 вложений; сохранённый оригинальный ARCH2b full witness содержит SHA Body/HTML/recipient/flags и фактического содержимого вложений. ARCH3w не переписывает и не переносит сообщения: он создаёт десять `Intent` исключительно в отдельном защищённом каталоге LOCALAPPDATA через **оригинальный** `Write-OPAOperationJournalEvent`.

## Точный полный синтаксис и порядок запуска

Для `Audit/Prepare` требуется Outlook 2019 с профилем `Outlook` и **Windows PowerShell 5.1 -STA**. `Plan/Review` используют только файлы. Сохраняйте прежний **RunId**, не вводите новый: `ARCH3w` имеет отдельный префикс каталога и не трогает свидетельство `ARCH3v`.

```powershell
$pin = @{
  RunId='093b5ce9-4a90-46fa-b6a5-7cdba61d2f15'
  SealSha256='d071afbff028d4cbadcea69318a6d68009242ac401cd2a91abf08b5ffe9f6799'
  ExpectedAuditSha256='609e60e01082860ec8dfd936510243c812ba2c99b1403685a3d96c3718000a21'
  ExpectedPreviewSha256='d9bc37c5f87aace732adb122d89488eb44111b7333ebf3b5d33c087766a42e57'
  ExpectedOriginalIndexSha256='5ada35eb30f34ff60dc4b89f23aa071b72cc0b98e5ff57299d61f1714b13d7ae'
}

# 1. PLAN: чтение уже защищённого ARCH3v без Outlook или записи файлов
.\Invoke-ARCH3w.ps1 -Mode Plan @pin | Format-List

# 2. AUDIT: повторная ORIGINAL ARCH3u и полная ORIGINAL ARCH2b
# проверка десяти сообщений и 12 вложений; существующие Part1/Part2 PST
# читаются и SHA проверяются; Part3 должна отсутствовать
$audit = .\Invoke-ARCH3w.ps1 -Mode Audit @pin
$audit | Format-List
$audit.ExistingOriginalArchiveParts | Format-Table -AutoSize

# 3. WHATIF: только демонстрация, без записи, не вызывает Outlook
.\Invoke-ARCH3w.ps1 -Mode Prepare @pin -ExpectedPrepareDigest $audit.PrepareDigest -ConfirmPrepareIntent -WhatIf | Format-List

# 4. PREPARE: ровно один раз! Только после проверки Audit/WhatIf
# создаст защищённую папку с manifest + ORIGINAL 10 Intent JSONL,
# не вызывает Move() и не создаёт архив PST
$prepared = .\Invoke-ARCH3w.ps1 -Mode Prepare @pin -ExpectedPrepareDigest $audit.PrepareDigest -ConfirmPrepareIntent -Confirm:$false
$prepared | Format-List

# 5. REVIEW: независимое чтение исходного ARCH3v Seal + ORIGINAL
# 10 journal events, без Outlook или изменения PST/index
$review = .\Invoke-ARCH3w.ps1 -Mode Review -RunId $pin.RunId -SealSha256 $pin.SealSha256 -ManifestSha256 $prepared.ManifestSha256 -JournalSha256 $prepared.JournalSha256
$review | Format-List
```

Полная командная строка:

`Invoke-ARCH3w.ps1 -Mode <Plan|Audit|Prepare|Review> -RunId <canonical-lowercase-GUID> [-SealSha256 <64-hex>] [-ExpectedAuditSha256 <64-hex>] [-ExpectedPreviewSha256 <64-hex>] [-ExpectedOriginalIndexSha256 <64-hex>] [-ExpectedPrepareDigest <64-hex>] [-ManifestSha256 <64-hex>] [-JournalSha256 <64-hex>] [-ConfirmPrepareIntent] [-WhatIf] [-Confirm:$false]`

| Параметр | Режимы | Назначение |
|---|---|---|
| `-Mode` | Все, обязателен | `Plan` без Outlook; `Audit` свежая полная оригинальная семантика; `Prepare` evidence-only записи исходного OperationJournal; `Review` независимая проверка. |
| `-RunId` | Все, обязателен | **Тот же** `093b5ce9-4a90-46fa-b6a5-7cdba61d2f15`, который использовался ARCH3u/v. |
| `-SealSha256` | Все | Внешне сохранённый exact SHA256 файла ARCH3v Seal (`d071...`). |
| `-ExpectedAuditSha256` | Plan/Audit/Prepare | Исходный ARCH3v `AuditSha256` (`609e...`); заново вычисленный SHA должен совпасть. |
| `-ExpectedPreviewSha256` | Plan/Audit/Prepare | Оригинальный ARCH3u `PreviewSha256` (`d9bc...`). |
| `-ExpectedOriginalIndexSha256` | Plan/Audit/Prepare | Зафиксированный общий DuplicateIndex (`5ada...`), читается, не изменяется. |
| `-ExpectedPrepareDigest` | Prepare | Новый `PrepareDigest` из строго read-only AUDIT; привязывает архив Part1/2 SHA256 + 10 source contract/semantic SHA + seal/index. |
| `-ManifestSha256` | Review | Хэш защищённого manifest, возвращённый успешным Prepare. |
| `-JournalSha256` | Review | Хэш оригинального `OperationJournal` с ровно 10 `Intent`, выданный Prepare. |
| `-ConfirmPrepareIntent` | Prepare | Обязательное согласие **исключительно** на защищённые manifest + original journal **без PST и Move**. |
| `-WhatIf` | Prepare | Пропускает даже Outlook и запись, возвращает `TenOriginalPrepareIntentWhatIfNoOutlookNoWrites`. |
| `-Confirm:$false` | Prepare | Отключает второй PowerShell interactive prompt после `-ConfirmPrepareIntent`. |

## Архитектурные ограничения и безопасность

**Не новый mover, а исходный журнал.** `ARCH3w` повторно читает `ARCH3v` через `Test-OPA265ARCH3vFullTenReadback`, проверяет SHA файла, внутренний `AuditSha256`, десять первоначальных SHA `Get-OPA265ARCH3dOriginalWitnessHash` и все исходные `ARCH3b` контракты. Далее `Get-OPA265ARCH3vFullReadOnlyAudit` запускает original ARCH3u и original ARCH2b, включая `Attachment.SaveAsFile` во временной **изолированной** ACL-папке. Все 10 исходных EntryID, Inbox/StoreID, Body/HTML/recipients и 12 содержимых вложений должны совпасть с защищённым Seal.

Новый `Get-OPA265ARCH3wOriginalYearParts` строго требует **две** уже существующие части PST за 2020 (01 и 02), вычисляет SHA256 обеих; `Archive-2020-03.pst` должна отсутствовать. Оригинальный `DuplicateIndex` (501) должен сохранить исходную SHA. **Любое отличие** — прекращение до записи.

При `Prepare` вычисленный `PrepareDigest` сравнивается с показанным ранее Audit; повторно проверяются реальные архивы, PST и исходный POP3 StoreID. Затем используется **существующий** `New-OPA265ARCH3iPrivateEvidenceDirectory` для атомарного защищённого NTFS ACL и **существующий** `Write-OPA265ARCH3cJsonOnce` для immutable manifest. Для десяти операций в строгом порядке `Sequence=1..10` вызывается **оригинальная** `Write-OPAOperationJournalEvent -Phase Intent`, которая записывает SHA256-конверт с `Flush(true)`. Каждая строка привязана к original `ARCH3b OperationId`, оригинальному SourceEntryId, исходному реальному POP3 StoreID и target `2020\Входящие`, к архиву Part3 и индивидуальному full witness SHA из неизменённого ARCH3v.

Строго отдельный путь (два файла):

```text
%LOCALAPPDATA%\OPA265-ARCH3w-093b5ce9-4a90-46fa-b6a5-7cdba61d2f15\
  original-ten-prepare-intents.json
  original-operation-journal.jsonl
```

Существующие файлы `OutlookPOP3Archive-Transactions\DuplicateIndex.jsonl`, оригинальный исторический `ARCH3j` и архивные PST **не изменяются**.

**Важная аварийная граница:** начиная с создания защищённого каталога, никакого автоматического повторения `Prepare` — даже если удалось записать только 1..9 `Intent`, остался только manifest или оборвался JSONL. Ничего не удалять и не «дописывать вручную»: отдельное read-only расследование. `Review` требует ровно 2 файла, 10 валидных original SHA-envelope `Intent` с уникальными SourceEntryId/OperationId, точным ordinal/target/store, неизменный внешний SHA256 manifest и journal. **Подготовленный Intent не есть MoveClaimed.** Статусы безопасности после Prepare: `WriterPermit=False`, `ProductionReady=False`, `MoveClaimed=False`, `RealMailMovePerformed=False`, `AutomaticMoveRetryAllowed=False`.

### Не разрешено

`MailItem.Move()`, `MoveClaimed`, `AddStoreEx`, автоматические повторы, какие-либо архивные PST writer, исходный shared DuplicateIndex writer, `Archive/Resume/Auto` и 90GB production. После реального ARCH3w `Prepare/Review` следующий отдельно выпущенный ARCH3x должен добавить надёжные исходные `MoveClaimed/ProviderInvocation` fence в оригинальный `MailMover`, реальные COM Move не делаются в ARCH3w.
