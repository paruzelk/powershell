# OutlookPOP3Archive 2.6.4-A — crash-window protocol (DESIGN ONLY)

## Scope and safety boundary

This milestone defines a pure, non-mutating contract for future isolated Windows
PowerShell 5.1 STA Worker crash tests. It does NOT implement test-only or
production MailMove, Worker kill, Outlook COM, PST creation or journal writes.
All 2.6.3 read-only reconciliation and FIX13b production paths are unchanged.

Module: Core/Worker/WorkerCrashProtocol.ps1

Functions:
- Get-OPACrashWindowMatrix: eight crash-window/fault definitions.
- Get-OPACrashWindowDefinition: reject unknown cases.
- New-OPACrashTestPlan: generate correlated RunId and test-only intent without running anything.
- Assert-OPACrashTimeline: verify minimum ordering constraints.
- Get-OPACrashReplayDirective: classify diagnostic evidence without ever authorizing mail mutation, automatic retry, journal completion or Worker termination.

## Failure matrix

| Window | Last trusted point | May COM Move have run? | Deterministic barrier? | Recovery |
|---|---|---|---|---|
| BeforeIntentFlush | No durable Intent | No if protocol obeyed | Yes, controller | Refuse dispatch |
| AfterIntentBeforeDispatch | Intent flushed | No if Worker not started | Yes, controller | Review Intent |
| WorkerStartedBeforeMove | Owned Worker launched | No if test barrier reliable | Yes, Worker | Review worker evidence |
| DuringMove | COM Move started | YES | NO | Independent read-only PST scan |
| AfterMoveBeforeResponse | COM call may have returned | YES | Yes, Worker | Independent read-only PST scan |
| AfterResponseBeforeTerminal | Response validated but terminal not flushed | YES | Yes, controller | Recheck journal plus PSTs |
| WorkerTimeoutOrMissingResponse | Missing trustworthy response | YES | NO | Preserve journal and scan |
| OutlookUnavailable | COM unavailable or error | YES | NO | Stop and review when accessible |

The first three windows assume future correctly placed and authenticated test
barriers. They do not establish facts merely because a journal has no record.
A missing Intent must NEVER be treated as permission to retry a previous
unknown Move.

There is no guaranteed deterministic way to kill a process precisely within
the synchronous Outlook MailItem.Move call. DuringMove is a future stress
experiment, not a promise of a specific instruction-level crash point.

## Protocol temporal invariants

1. Flush Intent durably (FileStream.Flush(true)) BEFORE Worker dispatch.
2. No Move without owned child Worker and exact scoped test data.
3. A Move attempt is one-shot; never retry automatically after uncertain state.
4. A Worker response is NOT independent proof that a MailMove completed.
5. Read journal integrity, scope identities, full source and archive inventories
   before any manual classification.
6. Missing/truncated/corrupt journal, incomplete scan or mismatched StoreID,
   folder or PST identity means stop and preserve evidence.
7. Do not append Completed or Reconciled during phase A.
8. Do not terminate Outlook.exe, unrelated PIDs, other sessions or services.
9. No automatic retries or auto-completion even for a unique archive candidate.
10. Automatic Archive/Resume/Auto Worker integration remains disabled.

## Correlation identities for future test-only implementation

Controller: unique RunId, transaction GUID, operation GUID, owned child PID,
exact named test barrier, journal path and SHA256 of its durable content.

Worker: Windows PowerShell 5.1 STA, validated PID and RequestId, no arbitrary
command execution endpoint. The standard Worker request allowlist remains
unchanged in phase A.

Data: two NEW disposable PSTs in a run-unique temporary directory, exact full
PST path, StoreID and folder path for both, complete 2.6.3 fingerprint
(InternetMessageId, Subject, Sender and Size). No production or IMAP PSTs.

Recovery: new PowerShell process, same mounted disposable test PSTs, verified
append-only Intent journal and read-only source/target folder snapshots.
All outputs fail closed and require manual review.

## Implementation gates

A (current): pure crash matrix, diagnostic plan, timeline guard and replay
policy with 23 Pester tests, no Worker execution or PST mutation.

B (future): separate test-only worker operation and hard-scope guard for
run-unique disposable PSTs. Production Worker allowlist still unchanged.

C (future): deterministic hooks on either side of Move and parent-controlled
termination of its OWN child PID. No arbitrary Worker/Outlook termination.

D (future): durable event trace and read-only replay in independent process,
per-window Pester and real COM tests, manual evidence reports.

E (future): explicit disposable PST detach/reopen with StoreID, EntryID and
message fingerprint stability diagnostics.

Production integration is NOT part of 2.6.4-A.
