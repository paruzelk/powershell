## What BW4k7s implements

- Read-only full or bounded original POP3 source Inbox/Sent/user mail folder enumeration. Reuse strict BW4k7q POP3-only folder EntryID/StoreID and recheck after scan. Read Class and EntryID for all candidates; MessageClass ONLY for Class != 43 objects. No body, HTML, attachment, recipient, subject, Save/Move/Delete. Duplicate item ID check. MaxNonMailWitnesses=25 default; too many objects STOP. Each witness has Class, mapped Microsoft OlObjectClass name, MessageClass or NotAvailable, exact EntryID and folder EntryID. Every nonmail object requires manual preservation; never automatically delete, skip or move.
- Read-only Office 16.0 HKCU PST policies and preferences: Software\Policies\Microsoft\Office\16.0\Outlook\PST and Software\Microsoft\Office\16.0\Outlook\PST. Inspect DWORD MaxLargeFileSize/WarnLargeFileSize (MiB, 1048576 bytes) and MaxFileSize/WarnFileSize (ANSI, bytes). If Unicode pair not explicitly configured, use default only as UNVERIFIED assumption, not effective machine proof. Partial, incorrect type or incompatible size limits require review; no registry writes or unlimited-size bypass.
- Capacity simulation references earlier BW4k7r forecast max archive size 45000000000 bytes and safety margin 3000000000, but does NOT establish real PST Unicode format, OST/PST policy application or physical growth safety.
- Optional -PreviousFullYearInventory from the previous BW4k7r $full variable: internally crosschecks complete year distribution, 26602+3 totals (against current original Q scope), 21985 pre-2026 MailItems, and annual candidate names. This is operator-provided *unsealed* metadata, not immutable PST evidence or real archive creation.
- Default -MaxTotalItems 5000 yields only partial witness coverage if Inbox still contains 26605 items. Explicit -MaxTotalItems 50000 can scan all original candidates and independently count nonmail items. Outlook changes mid-scan or between before/after scope scans -> STOP. No durable checkpoint, no source modifications.

## Operator runbook (Windows PowerShell ISE 5.1 STA)

Unzip the versioned DEV ZIP containing only OutlookPOP3Archive. Open Outlook profile Outlook, keep test archives as-is, run from extracted project root.

PowerShell:

    .\Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'

    # Registry-only, Outlook not needed:
    $reg = & '.\Core\Diagnostics\Invoke-OPA265BW4k7sPop3InventoryReadinessReview.ps1' -RegistryOnly
    $reg.LimitDecision | Format-List
    $reg.PolicyProbe.Values | Format-List
    $reg.UserProbe.Values | Format-List

    # No external reads and no writers:
    & '.\Core\Diagnostics\Invoke-OPA265BW4k7sPop3InventoryReadinessReview.ps1' -WhatIf

    # Full 26605 candidate item class scan; previous $full from BW4k7r in same ISE session:
    $s = & '.\Core\Diagnostics\Invoke-OPA265BW4k7sPop3InventoryReadinessReview.ps1' -MaxTotalItems 50000 -PreviousFullYearInventory $full
    $s | Format-List Status, ScopeCandidateItems, CandidateItemsExamined, FullNonMailInventoryCoverage, MailItemsObserved, NonMailItemsObserved, WriterPermit, ProductionReady
    $s.NonMailWitnesses | Format-Table FolderPath, Class, OlObjectClassName, MessageClass, MessageClassObservation, EntryId -AutoSize
    $s.RegistryLimitDecision | Format-List
    $s.ReadOnlyArchiveYearCandidates | Format-Table Year, TotalMailItems, FirstPlannedArchivePst, ForecastMinimumSegmentsForObservedBytes -AutoSize

If previous $full is unavailable, omit -PreviousFullYearInventory; the report will NOT invent a validated six-year plan. Run a new BW4k7r full scan if needed. No mail or registry changes ever.

## Microsoft references and caution

Microsoft OlObjectClass enumeration: https://learn.microsoft.com/en-us/office/vba/api/outlook.olobjectclass
Microsoft PST/OST size policy: https://learn.microsoft.com/en-us/microsoft-365-apps/outlook/data-files/configure-size-limit-outlook-data-files

Office 16.0 default Unicode MaxLargeFileSize=51200 MiB (50 GiB); WarnLargeFileSize=48640 MiB (47.5 GiB). Difference >=5% recommended. WarnLargeFileSize is a maximum data threshold, not a user alert. Unsupported large limits can reduce performance. Registry settings can also affect OST. Do NOT disable size limits to archive a 90GB PST: use annual files with per-file capacity and rollover instead. This stage does not assert size settings applied or that PSTs can accept actual Move operations.
