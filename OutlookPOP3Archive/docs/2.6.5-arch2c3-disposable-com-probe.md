# 2.6.5-ARCH2c3 — реальный Outlook COM: контролируемая проверка вложения в одноразовом PST

**Статус:** DEV / **тестовый сценарий подготовлен, но ещё не выполнен на реальном Outlook**. 2.6.5-ARCH2c2 — предыдущая точка возврата (3e100c12637f924d01a3c610151e682b617a79a8), 3778 тестов / 127 контейнеров PASS.

Цель: не писать новую систему перемещения до проверки, что **настоящий Outlook 2019/классический Outlook**, через `Attachment.SaveAsFile`, корректно работает с защищённым каталогом ARCH2c2, включая пользователя, NTFS DACL, эксклюзивную `.opa-lease` и сравнение независимого SHA-256 фактических байтов. Приёмка Copy→Verify→Delete и перенос в другой PST **не входят** в этот этап.

## Защита от ошибочного выбора PST

`Core/Diagnostics/Invoke-OPA265ARCH2c3DisposableAttachmentProbe.ps1` принимает только две существующие исторические изолированные раскладки: `BW4k7v` и `BW4k7v2a1`. Абсолютный путь вычисляется по `SuiteId` и `LOCALAPPDATA`, **произвольный `-PstPath` не принимается**. Запрещены UNC/symlink пути, отсутствующий файл, неверное имя/родитель папки, отличие от профиля `Outlook`, больше одного Outlook.exe, отсутствие уже смонтированного тестового PST, совпадение тестового PST с `DefaultStore` или `Account.DeliveryStore`. Программа не вызывает `AddStore`, `AddStoreEx`, `MailItem.Copy`, `MailItem.Move`, `MailItem.Delete`, `MailItem.Save` или `Send`.

- `Plan`: только вычисляет ожидаемые пути, не связывается с Outlook и не пишет файлы.
- `Inventory`: read-only просмотр одной тестовой папки (до 32 писем, с маркировкой `OPA265-` и SuiteId в теме); выдаёт `EntryId`, хеш темы и количество вложений, но не выдаёт тело, имена вложений или байты.
- `Probe`: только одно конкретное письмо из одноразовой папки, `EntryId` из `Inventory`, **ровно одно вложение** типа by-value. Сохраняет его временную копию только через ARCH2b/ARCH2c2, хеширует SHA-256 фактических байтов, сравнивает с независимо указанными `ExpectedPayloadSha256` и `ExpectedPayloadBytes`, затем проверяет cleanup. При расхождении результат `CriticalAttachmentEvidenceMismatchNoWriter`, не выдаёт разрешения на Move.
- `PostRestartProbe`: тот же тест, дополнительно требует и проверяет отличающиеся `OutlookProcessId` **и** `OutlookProcessStartUtcTicks` из первого прогона. Не повторяет никакую модифицирующую операцию.

**Ограничение:** у выбранного disposable PST должно **уже существовать** синтетическое письмо с одним by-value вложением; сборка не создаёт fixture, не подключает PST и не запускает Outlook. `BW4k7v2a1` обычно содержит пилот без вложений, поэтому `Probe` корректно отклонит его. Для фактического теста выбрать только подтверждённое синтетическое вложение в другом существующем disposable PST либо отдельно создать новый контролируемый fixture (вне этого билда). Не тестировать на рабочем POP3 PST.

## Команды оператора на Windows PowerShell 5.1 STA

```powershell
# Из каталога OutlookPOP3Archive. План: БЕЗ Outlook и без файловых изменений.
$run='00000000-0000-4000-8000-000000000001' # заменить на SuiteId существующего теста
$ctrl='.\Core\Diagnostics\Invoke-OPA265ARCH2c3DisposableAttachmentProbe.ps1'
powershell.exe -NoProfile -STA -File $ctrl -Mode Plan -FixtureKind BW4k7v -SuiteId $run

# Outlook должен уже работать в профиле Outlook, а именно указанный PST должен быть смонтирован.
powershell.exe -NoProfile -STA -File $ctrl -Mode Inventory -FixtureKind BW4k7v -SuiteId $run

# Взять конкретный EntryId из Inventory и НЕЗАВИСИМО вычисленный
# SHA256/длину исходного файла, которым вручную создавали тестовое вложение:
$payload='C:\Temp\original-synthetic-attachment.bin' # только свой тестовый файл
$sha=(Get-FileHash -LiteralPath $payload -Algorithm SHA256).Hash.ToLowerInvariant()
$bytes=(Get-Item -LiteralPath $payload).Length
$entry='00000000...' # заменить на точный EntryId из Inventory
$first=powershell.exe -NoProfile -STA -File $ctrl -Mode Probe -FixtureKind BW4k7v -SuiteId $run -EntryId $entry -ExpectedPayloadSha256 $sha -ExpectedPayloadBytes $bytes
```

**Важно:** при запуске отдельного процесса `powershell.exe -File` результат выводится текстом. Чтобы сохранить объект `$first` с PID/ticks, запускать диагностический скрипт **непосредственно** из уже запущенной STA-консоли Windows PowerShell 5.1:

```powershell
$first=& $ctrl -Mode Probe -FixtureKind BW4k7v -SuiteId $run -EntryId $entry -ExpectedPayloadSha256 $sha -ExpectedPayloadBytes $bytes
$first | Format-List

# Полностью закрыть и заново открыть Outlook, не отсоединяя тестовый PST.
$after=& $ctrl -Mode PostRestartProbe -FixtureKind BW4k7v -SuiteId $run -EntryId $entry -ExpectedPayloadSha256 $sha -ExpectedPayloadBytes $bytes -OriginalOutlookProcessId $first.OutlookProcessId -OriginalOutlookStartUtcTicks $first.OutlookProcessStartUtcTicks
$after | Format-List
```

Не использовать `PostRestartProbe` до фактического перезапуска Outlook.

## Evidence и решение

Для успешного интеграционного прогона требуются оба статуса `DisposableAttachmentBytesMatchedIndependentBaseline`, отсутствие временных каталогов после обычного завершения, закрытый `.opa-lease`, перезапуск Outlook с другим PID/ticks и повторный SHA-256 Match. Временные копии реальных байтов не публиковать и не архивировать в логах.

При несоответствии записать только статусы, PID, SuiteId, хеш и длину исходного синтетического payload, затем расследовать причину **до** любого Move. Успешный SHA-256 из одного PST не доказывает безопасность перемещения между PST, журналирования, аварийного Resume, 90 ГБ или обработки вложений типа 5/OLE. `Archive/Resume/Auto` сохраняют ARCH2a запрет, включая `-WhatIf`.

## CI / roadmap

`Tests/Diagnostics/ARCH2c3DisposableProbe.Tests.ps1` содержит 26 синтетических политик: выбор тестового PST, отсутствие использования рабочего хранилища, контроль default/delivery store, уникальность, точный SHA и размеры, ложный restart, строгие статические запреты COM writer. CI не может подтвердить реальный Outlook, поскольку runner не содержит Outlook 2019: **`RealOutlookAcceptancePending=true`**. Сборка остаётся DEV и не даёт writer permit.

Следующий шаг после вывода с реальной машины: `ARCH2c4` — независимая сверка read-only COM после restart и проектирование отдельного Copy→Verify→Delete без автоматического удаления источника. См. [ARCH2c2](2.6.5-arch2c2-private-acl-lease.md), [ARCH2b](2.6.5-arch2b-semantic-verifier.md) и [SEM-001](SEMANTIC-INTEGRITY-POLICY.md).
