## Новый тестовый режим, не production

На целевой станции PowerShell 5.1 STA, классический Outlook запущен. Единственный обнаруженный POP3 должен быть точно указанным существующим локальным тестовым PST. Иные или несколько POP3 блокируют запуск; IMAP не архивируется. Не запускать на рабочей почте, без резервного копирования или при неясном состоянии старых архивов/индексов. Ни один файл не удаляется ради нового старта.

Проверка параметров (без COM и постоянных записей):

~~~powershell
$source = Join-Path $env:USERPROFILE 'Documents\Файлы Outlook\info@stios.ru.pst'
$opts = @{
    Mode = 'Auto'
    ConfirmDevAutoArchive = $true
    ConfirmDevLongArchive = $true
    LongArchiveSourcePst = $source
    OlderThanMonths = 12
    ArchiveGrouping = 'YearQuarter'
    Quiet = $true
}
.\OutlookPOP3Archive.ps1 @opts -WhatIf | Format-List
~~~

Ожидается NoOutlookOrPersistentWrites, LongArchive=True, BatchSize=500, MaxBatchesPerSource=0, PinnedSourcePst, IncludeRootMail=True, отключены policy размеров, DurabilityMode=Safe, ProductionReady=False. WhatIf не проверяет наличие/владение PST или состояние Outlook.

### Реальная приёмка после CI

Сначала один контролируемый пакет (не запускать вместе с другим архиватором):

~~~powershell
Get-Process OUTLOOK | Select-Object Id,StartTime,SessionId
$r = .\OutlookPOP3Archive.ps1 @opts -AutoDevMaxBatches 1
$r | Format-List
$r.Sources | Format-List
Get-Process OUTLOOK | Select-Object Id,StartTime,SessionId
~~~

Сверить exit, журнал, статус последней партии, pending, ошибки и совпадение PID/start. При 20/30, неизвестном worker, ошибке записи или pending не удалять файлы и не повторять Archive вслепую. После принятия этого результата — запуск без -AutoDevMaxBatches (или 0) для исчерпания. При наличии старого pending сначала исходный verification-only Resume по его identity, затем новая выборка, никогда повтор старого Move. Ожидание ребёнка до 3600 секунд; при истечении supervisor прекращает запуск новых worker, но не убивает активный Outlook/worker. Повторный запуск — только после диагностики и освобождения lease. В режиме Quiet summary в %LOCALAPPDATA%\OutlookPOP3Archive-ARCH7f; исходные журналы/ledger сохраняются.

### Параметры и семантика

- ConfirmDevAutoArchive и ConfirmDevLongArchive — оба обязательны в Auto; LongArchiveSourcePst — точный абсолютный локальный путь. Прежний Auto 10/100 не изменён.
- Limit: 1..500, 0/не указан = 500 в long; AutoDevMaxBatches: 0 (по умолчанию long) до 100, ноль означает нет суммарного лимита. Партия считается отдельно, no eligible подтверждается отдельным сканированием. Возраст и группировка прежние. Размер исходного PST не критерий завершения.
- Age cutoff пересчитывается при новой партии исходным кодом; это исчерпание доступных по возрасту кандидатов на момент очередной проверки, не неподвижный снимок всей почты. Deferred исключаются через оригинальный проверенный ledger. Exhausted не означает, что в PST нет deferred/неподдерживаемых сообщений.
- Остановка на неизвестном исходе, неисправимой ошибке, pending, отсутствии прогресса или массовом сбое экспорта. Не отключать антивирус. Не пытаться повторно переносить неизвестный claim. Reconciled/Indexed только после проверки оригинальных свидетельств.
- В отдельном worker флаг ConfirmDevLongArchive расширяет только явно подтверждённый тест Archive/Resume до 500; старый лимит 10 сохраняется без флага. Контролируемый interruption ARCH7d остаётся только для старого режима; recovery ARCH7c обрабатывает доказанный prefix до 500.
- Invoke-OPAAutoDev.ps1, Invoke-OPARdsAutoDev.ps1 и New-OPARdsTaskPlan.ps1 сохраняют прежние ограниченные параметры. Long Auto в этой сборке запускается непосредственно через основной скрипт; не регистрировать задание RDS, production закрыт.
- ExitCode Quiet: 0 — доступные кандидаты исчерпаны, 10 — установленный лимит партий, 20 — partial/blocked, 30 — исключение/неопределённость (может быть выброшено исключение до возврата объекта). Deferred и отсутствие прогресса отдельно проверяются.
