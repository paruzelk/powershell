  comparison, plus observational helpers to examine exact PST StoreID,
  test-folder FolderID and MailItem EntryID via complete read-only scans
  of the two disposable PST folders. The test demands exactly ONE

  Any missing/incomplete/duplicated fingerprint fails closed.
- Core/Diagnostics/Invoke-OPA264IdentityReopenTest.ps1: separate,

  message fixture is accepted.
- Tests/Worker/WorkerIdentityStability.Tests.ps1: 28 synthetic file-only
  tests for stability, StoreID/FolderID/EntryID changes, scope spoofing,
  one-shot claims, status and nonmutating invariants.

## Execution safety and limitations

No automatic execution after CI. No real Outlook tests were run by the
build author. Before a live experiment, verify a disposable Outlook
profile in a separate VM or isolated test session with a valid fixture.
A user confirmation switch cannot itself prove profile isolation.

The diagnostic creates and flushes an exclusive identity-probe.claim,
then writes identity-before.json BEFORE any detach. It detaches only
the root folder of the exact two mounted temporary PST files that
match the request paths and pre-detach StoreIDs. It NEVER removes files.
It then checks the exact PST files still exist, are not reparse points
and have nontrivial size BEFORE AddStoreEx(..., 2). Microsoft Outlook
olStoreUnicode=2; 3 is ANSI. It reattaches the SAME two files, scans the
synthetic folders and writes identity-report.json once.

If anything fails mid-sequence, the diagnostic refuses automatic
rollback, remount, cleanup, retry or journal update. Preserve all
artifacts for manual investigation. A failed detach/attach experiment
may leave test PSTs unmounted until a human repairs the test session.
Each future experiment MUST use a newly generated disposable fixture.

StoreID, FolderID, EntryID or folder path changes classify as
StoreIdChanged, FolderIdentityChanged, MailEntryIdChanged or
LocationChanged; simultaneous differences remain visible as booleans.
Even Stable NEVER authorizes a Move, retry, Changed Intent, Completed,
Reconciled or production integration. The original journal stays
byte-for-byte unchanged.
