## Authoritative Microsoft references and scope

1. Microsoft **[MS-OXCMSG] §2.2.1.6 PidTagMessageFlags** explicitly lists `mfUnmodified = 0x00000002` as *message not modified since first save or delivery*, with store/provider-managed lifecycle status. `mfRead=0x1` and `mfHasAttach=0x10` are documented in the same table. See https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxcmsg/a0c52fe2-3014-43a7-942d-f43f6f91c366.
2. Microsoft **PidTagMessageFlags canonical property**, property tag `PR_MESSAGE_FLAGS = 0x0E070003`, documents provider updating the bit field while saving, moving or processing mail; it can clear `MSGFLAG_UNMODIFIED` after subsequent saves. See https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessageflags-canonical-property.
3. Microsoft **PidTagStoreSupportMask** lists `STORE_HTML_OK=0x00010000` in a **different property**. It is not a `PidTagMessageFlags` definition. See https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagstoresupportmask-canonical-property.
4. Microsoft **PidTagMessageStatus** documents application bits of a **different property**, not the raw `PR_MESSAGE_FLAGS` bit `0x00010000`. See https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessagestatus-canonical-property.
5. Microsoft [MS-PST] message objects documents `PidTagMessageFlags` as a PST message object property: https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-pst/3b890c8d-0276-491e-be58-ea766c888ab0.

**Conclusion:** Original source `PR_MESSAGE_FLAGS=65555/0x00010013`, destination `17/0x00000011`; XOR `65538/0x00010002`. Exactly the previously set `0x00000002` and `0x00010000` bits are cleared after Move. `0x2` is *identified by Microsoft* (`mfUnmodified`). `0x00010000` is **not identified by the reviewed MS-OXCMSG PidTagMessageFlags table**. We do **not** claim it has no semantics, nor infer its meaning from other MAPI properties or automatically permit ignoring it. Additional Outlook/PST provider-specific evidence would be needed for an approved SEM-001 exception.
