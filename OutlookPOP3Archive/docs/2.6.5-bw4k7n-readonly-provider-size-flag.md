## Provider property evidence and sources

- Microsoft PidTagMessageFlags canonical property: https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessageflags-canonical-property. The message store provider can update flags after save or movement. 0x00000002 = documented mfUnmodified, see [MS-OXCMSG] 2.2.1.6, https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxcmsg/a0c52fe2-3014-43a7-942d-f43f6f91c366. The reviewed table does NOT establish a meaning for 0x00010000 in PidTagMessageFlags.
- PidTagMessageStatus 0x0E170003 is a DIFFERENT property with its own semantics. https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessagestatus-canonical-property. A 0x00010000 application-specific bit in MessageStatus would NOT define the same bit in MessageFlags.
- STORE_HTML_OK 0x00010000 belongs to PidTagStoreSupportMask 0x340D0003, not to PR_MESSAGE_FLAGS. https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagstoresupportmask-canonical-property. BW4k7n NEVER reuses constant meaning across properties.
- PidTagMessageSize (0x0E080003) is an approximate provider-computed aggregate of message property sizes, not necessarily literal MIME or physical PST file bytes. A provider may omit it, and it may be updated by SaveChanges. https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessagesize-canonical-property and https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/saving-a-message.
- PidTagMessageSizeExtended (0x0E080014) is a 64-bit variant with the same property ID but a different type. https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessagesizeextended-canonical-property.
- Crucial limitation: the immutable BW4k7l original witness captured MailItem.Size, PR_MESSAGE_FLAGS and PR_MESSAGE_STATUS but did NOT capture the original pre-Move PR_MESSAGE_SIZE or PR_MESSAGE_SIZE_EXTENDED raw MAPI property. A current archived MAPI property read cannot recreate missing pre-Move history or prove what caused the -532 change.

## BW4k7n implementation

1. Validate exact pinned fixture and original immutable BW4k7l SHA and BW4k7m Claim SHA with the existing independent post-Move audit. Require source zero, destination one, full exact semantic content match, raw flags 65555->17, mask 0x00010002 and known diagnostic size 10489->9957. No mismatches or global waiver.
2. Read the unique mounted archive PST and the exact archived message (only) from two separate COM access paths: folder Items.Restrict by the immutable InternetMessageId, and namespace GetItemFromID of the immutable destination EntryID. Compare a strictly bounded, fixed scalar MAPI property inventory twice.
3. Required: PR_MESSAGE_FLAGS 0x0E070003, PR_MESSAGE_STATUS 0x0E170003, PR_HASATTACH 0x0E1B000B. Optional: PR_MESSAGE_SIZE 0x0E080003, PR_MESSAGE_SIZE_EXTENDED 0x0E080014, PR_NATIVE_BODY 0x10160003, PR_RTF_IN_SYNC 0x0E1F000B, PR_INTERNET_CPID 0x3FDE0003, PR_MESSAGE_CODEPAGE 0x3FFD0003, PR_LAST_MODIFICATION_TIME 0x30080040 and PR_CREATION_TIME 0x30070040. Missing optional properties with exact MAPI_E_NOT_FOUND are represented as Available=false, Value=null; a different provider error or wrong scalar type fails closed. No unbounded binary MAPI body/RTF downloads.
4. Classify whether each optional provider size equals archived MailItem.Size; never infer a pre-Move raw PR_MESSAGE_SIZE value or cause of the -532 delta. Classification remains TwoFixtureFlagsReproducedSizeDeltaObservedCauseStillUnclassified.
5. No Move, Save, Delete, SetProperty, Claim, journal, evidence writes, production Archive/Resume/Auto dispatch or automatic retry. Temporary 1024-byte SaveAsFile copies for inherited BW4k7m attachment SHA audit are removed after reading; no PST mutations are authorized.
