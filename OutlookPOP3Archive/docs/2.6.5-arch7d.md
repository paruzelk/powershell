## Синтаксис

~~~powershell
.\Invoke-OPALiveArchiveBatches.ps1 -SourcePst <string> -ProfileName <string> -ConfirmTestArchive -ConfirmLiveOutlookVerification [-BatchSize <int>] [-MaxBatches <int>] [-OlderThanMonths <int>] [-ArchiveGrouping <Year|YearQuarter|YearMonth>] [-IncludeFolderPath <string[]>] [-IncludeRootMail] [-MaxResumeAttempts <int>] [-RetryDelaySeconds <int>] [-WorkerTimeoutSeconds <int>] [-InterruptAfterReturned <int>] [-WhatIf]

.\Invoke-OPALiveArchiveBatches.ps1 -SourcePst <string> -ProfileName <string> -ConfirmTestArchive -ConfirmLiveOutlookVerification -RecoverOnly [-MaxResumeAttempts <int>] [-RetryDelaySeconds <int>] [-WorkerTimeoutSeconds <int>] [-WhatIf]
~~~

| Ключ | Default | Назначение |
|---|---|---|
| SourcePst | обязательный | существующий локальный тестовый POP3 PST |
| ProfileName | обязательный | точный профиль |
| ConfirmTestArchive | False | явное согласие на тестовый PST |
| ConfirmLiveOutlookVerification | False | обязательная attach-only политика |
| BatchSize | 10 | 1–10, bounded DEV |
| MaxBatches | 1 | 1–100, максимальное число завершённых партий за запуск |
| OlderThanMonths | 12 | 1–1200, возраст |
| ArchiveGrouping | YearQuarter | Year, YearQuarter, YearMonth |
| IncludeFolderPath | все допустимые папки | точные пути |
| IncludeRootMail | False | добавить письма корня |
| MaxResumeAttempts | 3 | 1–10 попыток Resume на партию в рамках одного запуска |
| RetryDelaySeconds | 5 | 5–300, задержка между попытками |
| WorkerTimeoutSeconds | 600 | 30–3600, ожидание одного дочернего процесса; не убивает worker |
| InterruptAfterReturned | 0 | 0–9, специальный DEV fault point после durable receipt, меньше BatchSize, MaxBatches=1, без старого Pending |
| RecoverOnly | False | только восстановить существующий Pending, без новых Archive и без ключей выбора партии |
| WhatIf | False | проверка параметров без COM и постоянных записей |

Ограничение размера архивного PST самой утилитой отключено; системные ограничения Outlook/файловой системы и проверка свободного места остаются. Основной скрипт получает внутренний параметр ARCH7dInterruptAfterReturned (0–9, default 0); он разрешён только при подтверждённом ограниченном live Archive, меньше Limit, после записи и flush оригинального Move receipt. Это искусственная ошибка с штатным выходом worker, не имитация потери питания или произвольного падения в COM.

## Совместный реальный тест после CI PASS

Оставить Outlook открытым. Выполнить в Windows PowerShell 5.1 STA из распакованного каталога ARCH7d:

~~~powershell
$source='C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'
$before=Get-Process OUTLOOK | Select-Object Id,StartTime
$opts=@{
    SourcePst=$source
    ProfileName='Outlook'
    ConfirmTestArchive=$true
    ConfirmLiveOutlookVerification=$true
    BatchSize=10
    MaxBatches=1
    OlderThanMonths=60
    ArchiveGrouping='YearQuarter'
    IncludeFolderPath='\\info@stios.ru\Входящие'
    InterruptAfterReturned=2
}
.\Invoke-OPALiveArchiveBatches.ps1 @opts -WhatIf
~~~

После NoOutlookOrPersistentWrites, если нет незавершённого Pending, выполнить один раз:

~~~powershell
$result=.\Invoke-OPALiveArchiveBatches.ps1 @opts
$result | Format-List
$result.LastRecovery | Format-List
$before
Get-Process OUTLOOK | Select-Object Id,StartTime
~~~

Ожидается: ArchiveWorkers=1, LastArchiveExitCode=1 (контролируемый выход), ResumeWorkers=1 при успехе первой проверки, Verified=Reconciled=Indexed=2, Unprocessed + Deferred + Verified = Planned, Unprocessed остаётся для следующей партии, MoveInvocations=0 при Resume, PendingCleared=True, Outlook PID/start неизменны, MoveWorkerId != VerifyWorkerId. Если доступных писем мало или большинство пропущено, fault point может не сработать: не объявлять тест PASS по одной только завершённой партии. При ошибке не повторять тест Archive; сохранить LogDirectory и Pending. Для подтверждения fault point проверить stdout первого worker на 'ARCH7d controlled interruption after durable paired receipt'.

Если остался Pending, отдельный запуск только восстановления (после завершения прежнего worker):

~~~powershell
.\Invoke-OPALiveArchiveBatches.ps1 -SourcePst $source -ProfileName Outlook -ConfirmTestArchive -ConfirmLiveOutlookVerification -RecoverOnly -WhatIf
.\Invoke-OPALiveArchiveBatches.ps1 -SourcePst $source -ProfileName Outlook -ConfirmTestArchive -ConfirmLiveOutlookVerification -RecoverOnly
~~~

## Поведение и границы

Контроллер сам не обращается к COM. Supervisor lease отделён от оригинального пользовательского mutex; child wrapper имеет отдельную worker lease. Оригинальный main сохраняет собственный mutex и ARCH4 lease. Для каждого процесса отдельный stdout/stderr и UTF-8 JSON result. EncodedCommand передаёт параметры как UTF-16LE JSON/Base64, без интерполяции произвольного пути в исполняемую строку. Supervisor.jsonl записывается с flush(true). Рабочие логи под OutlookPOP3Archive-Transactions/ARCH7d-run-<guid>, могут содержать диагностические сведения о почте, сохраняются для администратора; отдельная политика ACL/retention/quiet — ARCH7f. Не публиковать логи без проверки.

Перед новым Archive читается исходный Pending. Если есть совместимый, сначала только Resume. После завершившегося Archive с Pending запускается новый child, всегда Recovery-only ARCH7c. Повторяется только Resume, ограниченно, с паузой, при сохранённом Pending. При изменении identity, неподтверждённом completion, исчезновении Pending без результата, ошибке Archive до Pending, превышении тайм-аута или исчерпании попыток — остановка, не повторять Archive. После восстановления прерванной партии с Unprocessed>0 контроллер завершает текущий запуск; будущий Auto продолжит новой селекцией на ARCH7e/d следующей итерации. Нулевые партии и exhaustion завершаются, документированные skip-only могут продолжаться в пределах MaxBatches.

Никакого Outlook Quit, Stop-Process, Kill, запуска Outlook или переключения профиля. При тайм-ауте worker остаётся жить, поскольку может быть внутри Move; новый запуск блокируется активной lease и исходным mutex. Не считать тайм-аут доказательством окончания COM. Неизвестный Move и повреждённый журнал остаются ручным hold. Не запускается production Auto, нет автоматического обнаружения всех POP3, нет неограниченного lifetime retry. Retry cap пока на запуск контроллера, не постоянный между логинами. Не доказана физическая durability кэша Outlook. CI использует синтетические данные и отдельный реальный STA PowerShell со stub, а не настоящий Outlook. Не устанавливать пользователям через планировщик до реальной приёмки и дальнейших этапов.
