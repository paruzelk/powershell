Production content preservation must compare a mail message immediately **before** Move to the same mail message **after** Move, not compare a newly constructed pre-Save template to its post-Save Outlook storage representation. `SEM-001` remains fully normative.

## What changes in BW4k7v2a7

This release **does not replay or modify** any of the old BW4k7v2a1, BW4k7v2a4, BW4k7v2a5 or BW4k7v2a6 historical SuiteIds. New GUID means a **new one-time isolated test**, new disposable Unicode PST, new source synthetic Draft.

1. Preflight: exact existing Outlook profile `Outlook`, POP3 `info@stios.ru`, its original delivery PST forbidden as new test source or target, and original default Drafts (possibly IMAP/server-synced). Only new synthetic test Subject considered.
2. `CreatePilot` needs explicit approval to create **one new unsent synthetic Draft in default Drafts** and attach **one new Unicode disposable PST**. The default Draft can sync to a server. Writes are real to that other mailbox. No old email is touched.
3. Persist a write-once durable `create-intent.json` BEFORE any mail/PST writer. Exactly one `Items.Add('IPM.Note')` + `MailItem.Save()` is allowed; **never retry creation with the same SuiteId** after any error.
4. The original BW4k7v2a4 failed immediately post-Save on a combined source-one/target-zero `Items.Restrict` count. In v2a7 **do not read immediate Restrict counts after Save**. Instead independently reopen the **exact saved EntryID** twice and verify pinned default `StoreID`, `FolderID`, Subject, Class, To, unread state.
5. Require the submitted expected Body to be preserved **verbatim as the exact prefix** of the saved Body. Allow only either **no suffix** or the **known three-character disposable-fixture suffix** `CRLF + SPACE`, `CRLF + TAB`, `SPACE + CRLF` or `TAB + CRLF`. Reject other changes, signatures, missing body text, arbitrary whitespace, unknown suffixes and changed second read. These four variants are a strict **synthetic fixture post-Save baseline policy**, NOT a general SEM-001 content waiver.
6. Seal the **actual saved source Body SHA-256**, original template SHA-256, expected/observed lengths, Body classification and full source semantic witness in immutable `pilot-premovemanifest.json`. It is never overwritten.
7. Separate command `ReviewPilot` checks the original manifest hash, exact source=1/target=0 using numeric `Restrict.Count` with a Query result object (no PowerShell singleton COM scalar `.Count` ambiguity), pinned exact saved body SHA and full semantic witness. **No Move in CreatePilot or ReviewPilot**. Old test mail and original POP3 delivery PST never selected.
8. Operator separately approves **exactly one** `MailItem.Move()`, only after successful independent review. A durable `one-shot-move-claim.json` is created using `FileMode.CreateNew` and `Flush(true)` BEFORE COM Move. On COM failure or crash do NOT retry; only independent reconciliation.
9. After fully restarting Outlook, `Reconcile` independently checks zero source and exactly one destination with matching **actual pre-Move saved Body**, subject, recipient and unread state, storing MAPI raw flags and size drift for **manual SEM-001 review**. No production Archive/Resume/Auto enabled.
