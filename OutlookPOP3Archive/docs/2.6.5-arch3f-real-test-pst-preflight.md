# ARCH3f — реальный тестовый PST: безопасная инвентаризация и подготовка сквозных испытаний

**Состояние:** ARCH3f, шаг 1 / read-only real-POP3 preflight (DEV). **Реальный перенос в этой сборке не выполняется.**

## Исходный PST

Оператор разрешил использовать тестовый `C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst` с большим количеством настоящих писем для дальнейших контролируемых испытаний. Это **настоящий PST Outlook с реальными сообщениями**, а не пустой или искусственный файл. Дополнение к архитектуре и рискам IMAP: [решение об использовании тестового PST](2.6.5-arch3f-test-pst-authorization.md).

Повторная загрузка почты по IMAP возможна со слов оператора, но не гарантирует сохранности всех POP3-only писем, отправленных, пользовательских папок и локальных свойств. Перед реальным переносом рекомендуется холодная резервная копия (закрытый Outlook), либо явно зафиксированный отказ.

## Использование (Windows PowerShell 5.1, STA)

Откройте **запущенный Outlook 2019**, профиль `Outlook` и исходный PST. Не запускайте второй процесс Outlook. Перейдите в папку распакованного проекта:

```powershell
$source = 'C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'

# Только строки плана: не открывает Outlook/PST и не пишет файлов
powershell.exe -NoProfile -STA -File '.\Invoke-ARCH3f.ps1' -Mode Plan -SourcePst $source |
    Format-List

# Реальное чтение Outlook/POP3: 5 кандидатов на папку, без переноса.
# Выполнять в том же окне Windows PowerShell 5.1 (STA), чтобы
# сохранить вложенные объекты в переменной $inventory:
$inventory = .\Invoke-ARCH3f.ps1 -Mode Inventory -SourcePst $source
$inventory | Format-List Schema,Status,SourcePst,SourceDesignation,ProfileName,Pop3ScopeApproved,OutlookProcessId,SourcePstLengthBytes,EligibleNonemptyFolderCount,FolderItemsCountSum,SampleCandidateCount,YearCountsAreFullInventory,NoPstOrJournalWrites,WriterPermit,ProductionReady
$inventory.Folders | Format-Table SourceFolderPath,ItemsCount,SentLike -AutoSize
$inventory.YearSampleCounts | Format-Table Year,SampleCount -AutoSize
$inventory.Candidates | Format-Table ArchiveDate,SourceFolderPath,ArchiveYear,PlannedArchivePart1Pst,PlannedTargetFolderPath -AutoSize

# Ограничения поиска: не более 10 кандидатов на папку, максимум 64 папки,
# фильтр писем старше 12 месяцев; сами оригиналы не перемещаются
$inventory = .\Invoke-ARCH3f.ps1 -Mode Inventory -SourcePst $source -SamplePerFolder 10 -MaxFolders 64 -OlderThanMonths 12
```

### Все параметры

| Параметр | Тип, значения | Значение по умолчанию | Назначение |
| --- | --- | --- | --- |
| `-Mode` | `Plan` / `Inventory` | `Plan` | Строго read-only план или реальное чтение исходного PST через Outlook |
| `-SourcePst` | `string`, обязательный | нет | Локальный файл с **точным** именем `info@stios.ru.pst` |
| `-SamplePerFolder` | `int` 1–20 | 5 | Максимум кандидатов на каждую подходящую папку |
| `-MaxFolders` | `int` 1–128 | 64 | Предельное число непустых почтовых папок |
| `-OlderThanMonths` | `int` 0–120 | 0 | Фильтр давности; 0 — без возрастного ограничения |
| `-WhatIf` | стандартный PowerShell switch | выключен | Не даёт разрешения на запись; режимы этой версии вообще не содержат писателя |

`Inventory` проверяет, что подключён **ровно один** исходный POP3 Store для `info@stios.ru`, Outlook использует профиль `Outlook`, а источник не является хранилищем по умолчанию. Повторно используются оригинальные `Open-OPA265ARCH2dSession`, `Get-OPAEligiblePop3MailFolders`, `Get-OPAWellKnownFolderEntryIds`, `Get-OPAArchiveCandidates`, `Get-OPAArchivePartPath`, `Get-OPAArchiveTargetPath`.

Оригинальная классификация сохраняет Inbox, Sent, пользовательские и вложенные папки, исключает Outbox/удалённые/спам/системные черновики. Пользовательская папка с тем же названием, что и системная, определяется **по EntryID**, а не ошибочно исключается по названию при доступной системной карте.

**Важное различие метрик:** `FolderItemsCountSum` — сумма наблюдаемых Outlook Items.Count по непустым подходящим папкам (возможны не-MailItem). `YearSampleCounts` — распределение только выбранных кандидатов, это **не полная статистика годов** и не доказательство количества перемещаемых писем. Результаты по части PST (`Archive-2020.pst`) — лишь **расчёт по оригинальному правилу Part 1**, реальный rollover может выбрать другую часть.

`Inventory` может сортировать объект коллекции Outlook `Items` исходными функциями, но не вызывает `MailItem.Move`, `Namespace.AddStoreEx`, `Save`, `Delete`, не создаёт JSON, новые PST и журналы.

## Где заканчивается текущий шаг ARCH3f

- Реальный `info@stios.ru.pst` разрешён и используется для **чтения** после подтверждения профиля и StoreID.
- **Отдельный real one-shot writer ещё не включён.** В ARCH3d/ARCH3e работает только fake COM / отсутствующий TEMP PST. Эти защиты **нельзя просто отключить** для настоящего исходного PST.
- Все ранее подтверждённые пилоты ARCH2d5 **100/100** остаются отдельным доказательством исходного COM Move; в ARCH3f нужно проверить новые границы *сквозной* работы, не копировать старый движок.
- Следующие реальные шаги: ограниченный идентификатором исходного письма/папки RunId; предварительный original full semantic witness; durable intent **до создания PST**; one-shot COM-claim; независимое read-only Reconcile после **настоящего** рестарта Outlook; только затем оригинальный DuplicateIndex.
- Испытания Inbox, SentOn, подпапок, 2020/2021, rollover и аварийных окон нужны на текущем оператором обозначенном **тестовом** PST. Для намеренного повреждения PST используется отдельная одноразовая копия, а не исходный файл.
- Массовый `Archive`/`Resume`/`Auto` **закрыт**, `WriterPermit=False`, `ProductionReady=False`. Не переписывать оригинальный годовой архиватор.

### Что требуется от оператора после получения сборки

Вывести результаты `-Mode Plan` и `-Mode Inventory`. Особенно важны `Pop3ScopeApproved`, `Folders`, `SentLike`, годовые пути и `CandidateSampleCount`. Данные помогут выбрать малую уникальную партию разных годов/папок для следующего **однократного** реального интеграционного этапа без повторной отладки старого COM Move.

Схема результата: `2.6.5-ARCH3f.OriginalYearPreview.1`, статус `ExistingTestPstRealMailRoutePreviewNoPstOrComWrites`.
