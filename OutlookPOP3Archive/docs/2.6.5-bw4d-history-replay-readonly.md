# 2.6.5-BW4d: independent read-only LIVE3/LIVE4 journal replay fence (DEV)

## Purpose

Previous BW4c passed both GitHub Windows PowerShell 5.1 CI (1610 tests/65
containers) and an operator's live Outlook readback. The operator's chosen
MailItem had an InternetMessageId of the pattern
<opa264-live3-GUID@example.invalid>. This is **evidence of a previously
created synthetic test series**, not evidence it is a fresh Move candidate.

BW4d preserves Option B: BW3a original journal must remain a single unresolved
Intent; no Reconciled, claim, retry, Move or production Worker integration.
BW4d performs separate read-only checks of:
1. Historical seven pinned SHA-256 values and exactly one original Intent,
   before and after the Outlook COM read (reuses the BW4c route).
2. Existing local LIVE3/LIVE4 test-run directories, reading only the bounded
   operation journal and claim/response evidence files. Their file hashes and
   run counts must be identical before and after the Outlook read.
3. The observed candidate MailItem's EntryID and InternetMessageId compared
   against all visible prior operation Intent/Completed/Indeterminate records.

Even when NO matching journal event is present, a known
<opa264-live3-GUID@example.invalid> identity is conservatively BLOCKED.
A folder may have been deleted, moved or archived; the OS TEMP history cannot
establish complete coverage. The catalog always reports CatalogComplete=False,
ReplaySafetyProven=False, CanRetryPreviousMove=False, CanDispatchWorker=False,
CanInvokeMailMove=False, AutomaticRetryAllowed=False, ProductionReady=False.
Zero matches is NEVER a Move permit.

The independent channel is the on-disk operation journal, NOT independent
external MAPI item-content proof, NOT a full PST forensic snapshot.
Outlook can modify its mounted PST autonomously. BW4d never writes PST,
journal, claims, or evidence files and does not even produce a reusable Move
permit. A broken/partial/malformed history journal, unbounded number of
test-runs, changed observed file SHA or mismatched original historic data
stops the review (fail closed). The scan includes only exact folders named
OPA264-LIVE3-{32 hex chars}; other external and older records are not
implicitly covered.

## Native Windows PowerShell 5.1 STA

Unzip the CI-approved BW4d DEV ZIP. Start Outlook using profile Outlook and
select ONE unrelated synthetic test MailItem; do not select historical BW3a
message or assume a previous LIVE3 synthetic message is fresh.

    .\Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'

    $source = 'C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'
    $outlook = [Runtime.InteropServices.Marshal]::GetActiveObject('Outlook.Application')
    $selection = $outlook.ActiveExplorer().Selection
    if ($selection.Count -ne 1 -or [int]$selection.Item(1).Class -ne 43) {
        throw 'Select exactly one synthetic MailItem in Outlook.'
    }
    $item = $selection.Item(1)
    $folderEntryId = [string]$item.Parent.EntryID
    $itemEntryId = [string]$item.EntryID

    .\OutlookPOP3Archive.ps1 -Mode Archive -ProfileName 'Outlook' -WhatIf -Limit 1 -WorkerPilot -ConfirmDevWorkerPilot -WorkerPilotReviewHistoryReplay -WorkerPilotRunId 'a7b51427-7494-43f4-bc96-64915f6bee7e' -WorkerPilotSourcePst $source -WorkerPilotExpectedHistoricalJournalSha256 '5a68dbc4186c69eff13e49c7d69a19f16eba86e04969bb5aea3be0327820a648' -WorkerPilotCandidateFolderEntryId $folderEntryId -WorkerPilotCandidateEntryId $itemEntryId -WorkerPilotMaxFolderItems 1000 | Format-List

Default bounded catalog root: current Windows account system TEMP, with
up to 256 OPA264-LIVE3-<32 hex> folders. Standalone diagnostic may supply
-HistoryRoot and -MaxHistoryRuns to audit an exact existing local evidence
root. It DOES NOT recurse across entire disk or claim complete coverage.
Beware that a folder with more than 1000 Outlook messages fails the bounded
BW4c scan: select a smaller disposable test folder, not a production mailbox.

On a previously seen LIVE3 item the expected status is either:
BlockedKnownPriorLive3Live4OperationEvidence
or BlockedSyntheticLive3OriginCannotProveNoEarlierMove.
Both are successful safety blocks, NEVER a replay authorization.
