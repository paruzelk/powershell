## Versioned conservative semantic acceptance matrix

Policy ID **SEM-001-BW4k7o-v1** is a pure classifier, not a production acceptance or new writer. **Every outcome remains WriterPermit=False, ProductionReady=False, JournalCompletionAllowed=False, AutomaticRetryAllowed=False.**

| Evidence category | Classification | Policy consequence |
|---|---|---|
| Original evidence/Claim unverified; fewer than 2 independent reads | EvidenceNotAuthenticatedBlocked | STOP; preserve files |
| Source count not 0 or destination count not 1 | SourceDestinationIdentityMismatchBlocked | STOP; ambiguous store/identity |
| Body, headers/digests, recipients or attachment SHA differs | SemanticContentOrAttachmentMismatchBlocked | STOP; no content waiver |
| PR_MESSAGE_STATUS changes | PrMessageStatusChangedBlocked | STOP; semantic state mismatch |
| READ (bit 0x1) or HASATTACH (bit 0x10) changes | ReadOrHasAttachFlagChangedBlocked | STOP |
| Any undocumented/unknown raw PR_MESSAGE_FLAGS bits change (including 0x00010000) | UnclassifiedRawMapiFlagsChangedBlocked | **STOP: this is the ACTUAL observed BW4k7m case** |
| Archive PR_MESSAGE_SIZE unavailable/unprobed | ProviderMessageSizeNotObservedNeedsReview | Review only; do not fake a zero value |
| PR_MESSAGE_SIZE differs from archive MailItem.Size | ProviderMessageSizeDisagreesWithMailItemNeedsReview | Review only; no byte-loss inference |
| Only documented mfUnmodified (0x00000002) changes | DocumentedMfUnmodifiedChangeNeedsReview | Review only; not automatically accepted |
| Only diagnostic MailItem.Size changes, logical and tested MAPI fields match | SizeOnlyDifferenceNeedsReview | Review only; **no global +38 / +512 / -532 waiver** |
| All tested logical and selected MAPI fields match | ExactObservedLogicalAndMetadataMatchReadOnly | Read-only observation, STILL NOT production permission |

**Precedence:** unverified original evidence -> identity -> content -> separate MAPI status -> user READ/HASATTACH -> unknown raw flags -> provider size observations -> known mfUnmodified -> diagnostic MailItem.Size -> observed exact. Unknown flags are always evaluated before any proposed size or lifecycle tolerance.

The 0x00000002 bit is documented as mfUnmodified in the reviewed Microsoft [MS-OXCMSG] PidTagMessageFlags table. The same numeric value **0x00010000** occurs in the separate PidTagStoreSupportMask as STORE_HTML_OK, but that does NOT identify a MessageFlags bit. PR_MESSAGE_STATUS is another separate tag (0x0E170003), and 0x00010000 there has no automatic meaning in PR_MESSAGE_FLAGS. No waiver can be issued for the unknown bit based on the mere persistence of matching message body.

## Implementation in BW4k7o

- Pure worker helper Core/Worker/BW4k7oSemanticIntegrityPolicy265.ps1: versioned Get-OPA265BW4k7oPolicy, Get-OPA265BW4k7oSemanticDecision, exact forensic report validator. These functions do not open PST, call Outlook COM or write to filesystem.
- Live controller Core/Diagnostics/Invoke-OPA265BW4k7oSemanticIntegrityReview.ps1: calls existing BW4k7n1 **independent** read-only Outlook forensic diagnostics, validates exact original SHA-256 Evidence and one-shot Claim, source-zero/dest-one and the full 11-property scalar inventory including the PT_I8 NotProbed status; then returns pure policy decision.
- The live result for the actual fixture MUST be Status=VerifiedLogicalContentButUnknownMapiFlagBlockedNoWaiver and PolicyClassification=UnclassifiedRawMapiFlagsChangedBlocked. A different outcome means STOP; never auto-approve or normalize it away.
- -WhatIf returns only a static read-only notice with no Outlook access.
- The source-side semantic proof is bounded to the current synthetic fixture, NOT a full production coverage proof. PhysicalPstDurabilityProven=False, SentItemsAndCustomFoldersCoverageProven=False and YearlyPstCapacityRolloverProven=False are explicit.

## Remaining requirements before archiving 90-GB POP3 PST

- Complete source-scope proofs including POP3 **Sent Items** and custom folders and large attachment/headers; avoid confusing "Outbox" with Sent Items.
- Year-grouped PST files and capacity rollover with safety margin, physical PST size policy, backups, compact.
- More than one message in a batch; durable Claim/Intent/restart/resume and deliberate post-crash ambiguous operation isolation; verified no duplicate/hidden loss.
- Establish the unknown raw 0x00010000 meaning or a separately reviewed, narrowly justified policy that does NOT silently normalize undocumented flags. Never use a universal raw-bit allowance.
- Archive/Resume/Auto production integration remains disabled.
