# BW4k7v2a1 — one synthetic pilot in the EXISTING Outlook POP3 profile

## Change from BW4k7v2 and BW4k7v2a

The original BW4k7v2a standalone-profile gate is preserved unchanged and remains a historical CI checkpoint. BW4k7v2a1 adds a **different** and explicitly approved diagnostic workflow for the user's **existing test Outlook profile**, named `Outlook`, with the real test POP3 account `info@stios.ru`. No extra Outlook profile or switch of default data file is required.

Outlook's documented `NameSpace.AddStoreEx(pst, 2)` creates and attaches a **new Unicode PST** to the current profile. The test script verifies `AccountType=2` (POP3), exact account SMTP address and `Account.DeliveryStore.StoreID`, and requires the new PST to be a different store. Then `Folder.Items.Add('IPM.Note')` creates **one** disposable synthetic mail item in a new folder belonging to the new PST, rather than `Application.CreateItem()` (which previously routed a test message to the default Drafts in BW4k7v).

The historical failed BW4k7v SuiteId `78a3e477-98fc-4134-b400-429b3e3b216b`, old accidental Drafts item, all original PSTs/evidence, and original irreversible Move claim are unchanged. BW4k7v2a1 never touches existing mail items, never Move/Send/Delete, never changes the Outlook profile default store, never modifies Office registry, never grants production Archive/Resume/Auto permission.

**Important:** Adding a test PST does modify the *existing test profile* by attaching a new data file. The script does not detach it automatically and does not claim that the existing profile itself remains unchanged. The script intentionally refuses to retry a SuiteId after writing its immutable one-shot intent, even after a COM exception.

## Windows PowerShell 5.1 STA operator runbook

Use the extracted BW4k7v2a1 ZIP and open an interactive Windows PowerShell 5.1 console in STA mode, in the project folder. Start Outlook normally with the **existing** `Outlook` profile.

    .\Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'
    $script = '.\Core\Diagnostics\Invoke-OPA265BW4k7v2a1ExistingProfilePilot.ps1'
    $plan = & $script -Mode Plan
    $plan | Format-List
    & $script -Mode Prepare -SuiteId $plan.SuiteId -Confirm:$false
    $inspect = & $script -Mode Inspect -SuiteId $plan.SuiteId
    $inspect | Format-List

Proceed **only** when status is `ExistingOutlookPop3VerifiedFreshTestPstUnattached` and the POP3 delivery store matches the account you expect. The original source PST is not used for the synthetic message.

    $pilot = & $script -Mode CreatePilot -SuiteId $plan.SuiteId `
      -ConfirmExistingProfilePilot `
      -ApprovalText ('CREATE BW4K7V2A1 PILOT ' + $plan.SuiteId) -Confirm:$false
    $pilot | Format-List

Expected: `OneDirectFolderPilotSavedInNewPstOnExistingOutlookProfile` with `ManifestSha256`. **Completely close Outlook.exe**, check no Outlook process remains, then reopen Outlook in the same `Outlook` profile:

    $verified = & $script -Mode VerifyPilot -SuiteId $plan.SuiteId `
      -ExpectedManifestSha256 $pilot.ManifestSha256
    $verified | Format-List

Expected: `OnePilotReopenedAfterRestartInExactNewPstOfExistingProfile`.

If any step fails, preserve the created PST, `one-pilot-intent.json`, any manifest and HRESULT output. **DO NOT repeat CreatePilot for that SuiteId**. A fresh SuiteId is required for another attempt, following an explicit failure review. `-WhatIf` never accesses Outlook or writes files.

## Explicit limits and verification

- CI exercises **synthetic policies and static code safety only**. The live Outlook 2019 COM provider and actual creation are not verified until the operator runs this script.
- This proves only correct test PST / folder identity and one synthetic message's Subject, Body, To and UnRead witness after restart. It does **not** prove POP3 production archiving, historical MAPI timestamps, semantic equality for attachments, any `MailItem.Move`, batch operations or resumable recovery.
- Existing BW4k7v2/a standalone profile gates remain available for isolated testing, not requirements of this new mode.
- Windows PowerShell code files UTF-8 BOM; JSON evidence UTF-8 no BOM, immutable `CreateNew` and `Flush(true)`.
- `WriterPermit=False`, `ProductionReady=False`, `AutomaticRetryAllowed=False`.
