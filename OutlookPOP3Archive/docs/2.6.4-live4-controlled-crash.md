# 2.6.4-LIVE4 — controlled crash of ONE synthetic POP3 archive Move

## Purpose and scope

The user confirmed that the current Outlook profile "Outlook" and existing
POP3 PST are deliberately TEST data. LIVE3C native Windows PowerShell 5.1
CI passed 523/37. A real synthetic-only cross-PST MailItem.Move was
independently observed: source 1 -> 0, new archive 0 -> 1 with exact
synthetic fingerprint (RunId 1e926016-5760-446f-9c5c-14cd850dad11).
That RunId is ALREADY CLAIMED and must NEVER be reused.

LIVE4 adds two controlled Worker crash windows using a new synthetic
LIVE3C fixture/RunId for EACH window:
1. WorkerStartedBeforeMove: after Outlook COM source/item preflight but
   before the one-shot Move attempt claim and before MailItem.Move.
2. AfterMoveBeforeResponse: AFTER exact one-shot MailItem.Move returns
   but BEFORE the Worker writes its response.

The controller launches exactly one child powershell.exe in native PS5.1
STA, writes a durable dispatch claim BEFORE child process creation,
waits until that exact child writes an identity-and-PID checked flushed
barrier, then kills ONLY its owned child Process object. The controller
never kills Outlook.exe, never searches arbitrary PIDs, never tries a
second Worker operation and never writes Completed/Reconciled.
The crash Worker requires its controller claim, rejects previous barrier
and controller-result evidence and validates exact LIVE3 synthetic-only
StoreID+folder EntryID+message identifiers, before issuing its ONE Move.
Ordinary LIVE3 Worker also refuses a controller-dispatched RunId.

The independent LIVE4 recovery inspector reads the previous LIVE3C
synthetic source/target folder snapshot, validates the controller
report, durable claims, barrier RunId/OperationId/PID/crash mode and
compares one synthetic message only. It never calls Move or mutates
Outlook or journals. Even a verified success reports
RequiresIndependentReconciliation=True, JournalCompleted=False,
AutomaticRetryAllowed=False, ProductionReady=False.

No new full-size PST backup; do not run deferred LIVE2B. Never select
existing Inbox messages or reuse existing Archive-2019/2020 PSTs.

## Failure semantics

If any step throws, stops early, times out, lacks a crash barrier,
produces a response despite the crash, or observes missing/duplicate
synthetic mail, STOP THAT RunId and preserve all evidence. Never rerun
the controller/Worker for an already dispatched RunId or delete
durable claims. The controller handles *only its launched child*;
never use Stop-Process OUTLOOK. A new test may use a fresh RunId.
