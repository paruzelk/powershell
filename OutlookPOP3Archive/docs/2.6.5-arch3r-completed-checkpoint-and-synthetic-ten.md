# 2.6.5-ARCH3r — неизменяемый контрольный этап реального пилота и десять синтетических писем

Дата: 2026-11-19. **DEV-only, НЕ 90 ГБ production-ready.** Испытание выполнено на ТЕСТОВОМ PST `info@stios.ru.pst`; содержимое при необходимости можно перезагрузить по IMAP. Нового реального `MailItem.Move()` на ARCH3r нет.

## 1. Контрольная точка ARCH3q — завершена пользователем

Настоящий ARCH3o перенёс РОВНО одно тестовое письмо через ORIGINAL `MailMover`. ARCH3p после реального перезапуска Outlook (PID 11168 → 13040) с ORIGINAL `ArchiveVerifier` подтвердил отсутствие source EntryID и ровно одно семантически совпадающее письмо в новой Part2. ARCH3q успешно выполнил `Seal`, `Commit`, `Status`, финальный независимый `Review`: оригинальный журнал `Intent → Reconciled`, общая индексная запись 500 → **501**, по совпадающим файлам с закрытым авторетрай.

Сейчас ARCH3r ничего туда не пишет.

## 2. Режимы `Invoke-ARCH3r.ps1`

`Plan` и `Audit` принимают все шесть приведённых выше параметров исторического чекпойнта. Они вызывают оригинальные read-only `Get-OPA265ARCH3qState`, `Resolve-OPAOperationRecovery`, `Invoke-OPA265ARCH3qCommit -Mode Review`, `Get-OPA265ARCH3qReviewSeal`, `Read-OPA265ARCH3cPinnedJson` и оригинальный индексный reader. `Audit` дополнительно требует исходный полный ARCH3i witness и исходную доказанную postrestart семантику. **Не открывают Outlook и не изменяют PST, журнал или индекс.**

`Synthetic10` принимает только параметры инъекции синтетических сбоев и TEMP; **параметры реального RunId/SHA для него запрещены**. Создаёт под системным TEMP отдельный `OPA265-ARCH3r-SYNTH-<guid>` и в нём 10 уникальных SourceEntryId/ArchiveEntryId, полные виртуальные Body/HTML/Recipients/attachment SHA witness. Через ОРИГИНАЛЬНЫЕ `Test-OPA265ARCH2bWitnessSchema`, `Compare-OPA265ARCH2bMailSemanticWitness`, `Write-OPAOperationJournalEvent`, `Read-OPAOperationJournal`, `Resolve-OPAOperationRecovery`, `Write-OPA265ARCH3cJsonOnce`, `Add-OPADuplicateEntry`, `Import-OPADuplicateIndex` проверяет 10 синтетических состояний.

Схема синтетики: 10 оригинальных `Intent` → 10 immutable синтетических MoveClaim и ProviderInvocation (НО БЕЗ COM!) → десять исходных full semantic comparers → 10 оригинальных `Reconciled` → 10 append-only JSONL записей в **TEMP-only** DuplicateIndex → независимый readback исходного индекса. Никаких реальных PST не создаёт; путь фальшивого PST — только индексный идентификатор внутри системного TEMP.

**Ограничение:** синтетика не выполняет полный `Test-OPAArchiveMoves` на десяти настоящих Outlook `MailItem` и не доказывает их физическую долговременную сохранность. Поле `OriginalArchiveVerifierOutlookCOMExecuted=False` намеренно. Переход к реальной пачке возможен только после отдельной полной синтетической/COM проверки и явного разрешения. `WriterPermit=False`, `ProductionReady=False`.

## 3. Полный синтаксис всех ключей ARCH3r

| Параметр | Тип | Допустимые значения / назначение |
| --- | --- | --- |
| `-Mode` | string | `Plan`, `Audit`, `Synthetic10` (по умолчанию `Plan`) |
| `-RunId` | string | Только для `Plan/Audit`; точный операторский real ARCH3j RunId |
| `-IntentSha256` | string | Только `Plan/Audit`, SHA оригинального ARCH3j PrepareIntent |
| `-JournalSha256` | string | Только `Plan/Audit`, SHA исходного Intent-only журнала, **не** финального |
| `-ReviewSha256` | string | Только `Plan/Audit`, финальный ARCH3q independent Review Seal SHA |
| `-CommitClaimSha256` | string | Только `Plan/Audit`, защищённый ARCH3q Commit Claim |
| `-CommitSealSha256` | string | Только `Plan/Audit`, защищённый ARCH3q final IndexCommitted Seal |
| `-InjectFault` | string | Только `Synthetic10`: `None`, `DuplicateSource`, `DuplicateDestination`, `HtmlDrift`, `AttachmentDrift`, `ProviderUnknown`, `AfterClaimBeforeProvider`, `AfterJournalReconciled`, `AfterIndexAppend` |
| `-FaultAt` | integer | Номер виртуального письма 1..10, по умолчанию 4; только `Synthetic10` |
| `-SyntheticTempRoot` | path | Только `Synthetic10`; существующая подпапка внутри системного TEMP. Новый workspace всегда уникальный |

## 4. Команды оператора

Из каталога распакованного ZIP, **Windows PowerShell 5.1**:

```powershell
$checkpoint = @{
    RunId = '9d276dc4-a0e6-4e74-891f-81502fafe7db'
    IntentSha256 = 'f0860d55c5939498094832a8b924dbca9b65532cf53f8234f4aeda97ab631a2b'
    JournalSha256 = 'a19f113a6454b1d17333c9a53fc22d065876754b9fbab3167087487d0b2b981e'
    ReviewSha256 = '3c455f4da4ee32fd9f0d046ac5e36cc3d013c0913cf86ddee69d359f700831c3'
    CommitClaimSha256 = 'fc0e51d828d3b82fb3e46b22bdca6ff50f54f86366d1f9ec5ff5c937e221527a'
    CommitSealSha256 = '0fa26ba60ebe9685a6b13c5f989b1c5a840f54d5bc8302f87679b4e7dc6e67f0'
}
.\Invoke-ARCH3r.ps1 -Mode Plan @checkpoint | Format-List
.\Invoke-ARCH3r.ps1 -Mode Audit @checkpoint | Format-List
```

Запустить 10 синтетических писем через оригинальные модули, без Outlook:

```powershell
.\Invoke-ARCH3r.ps1 -Mode Synthetic10 | Format-List
.\Invoke-ARCH3r.ps1 -Mode Synthetic10 -InjectFault ProviderUnknown -FaultAt 4 | Format-List
.\Invoke-ARCH3r.ps1 -Mode Synthetic10 -InjectFault HtmlDrift -FaultAt 4 | Format-List
.\Invoke-ARCH3r.ps1 -Mode Synthetic10 -InjectFault AttachmentDrift -FaultAt 4 | Format-List
.\Invoke-ARCH3r.ps1 -Mode Synthetic10 -InjectFault AfterJournalReconciled -FaultAt 3 | Format-List
.\Invoke-ARCH3r.ps1 -Mode Synthetic10 -InjectFault AfterIndexAppend -FaultAt 2 | Format-List
```

В случае намеренного crash-фолта исходный synthetic journal/index остаётся внутри `SyntheticWorkspace` в OS TEMP для исследовательского readback. **Не** перезапускайте старые реальные `ARCH3o Move`, `ARCH3q Seal/Commit/Recover`. Не удаляйте защищённый операторский ARCH3j evidence.
