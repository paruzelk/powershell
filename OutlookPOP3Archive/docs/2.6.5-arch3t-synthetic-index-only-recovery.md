# ARCH3t — безопасное восстановление частичного original DuplicateIndex (10/2 → 10/10)

19 ноября 2026 года. **DEV / только синтетический OS TEMP**, без Outlook, PST и `MailItem.Move()`. `WriterPermit=False`, `ProductionReady=False`.

## Основание

Подтверждён ARCH3s (коммит `73833c62`): оригинальный `Test-OPAArchiveMoves` проверил 10 fake Outlook MailItems через исходный ARCH2b full witness, включая SHA256 байтов вложений, сохранённых через fake `SaveAsFile` в OS TEMP. Только после полного PASS исходные `OperationJournal` и `DuplicateIndex` подвергались fault-injection. При `AfterIndexAppend -FaultAt 2` остаются **20 journal events = 10 Intent + 10 Reconciled** и **2 записи в original append-only index**. Реальный ARCH3q (один Move, индекс 501) является *независимой, неизменяемой* контрольной точкой.

## Реализовано

`Core/Archive/ARCH3tSyntheticIndexOnlyRecovery.ps1` повторно читает **оригинальный журнал** и каждый исходный envelope SHA256; требует ровно 20 событий с точной последовательностью, всеми десятью `Reconciled`, уникальными Source/Archive EntryID, точным synthetic RunId/путём и без torn tail. Проверяет 10 immutable fake Claim и 10 ProviderInvocation, включая SHA256 ссылку Provider → Claim и full original semantic witness SHA.

Оригинальный `DuplicateIndex.jsonl` проверяется **построчно** до `Import-OPADuplicateIndex`: никакие чужие строки, дубли `SourceEntryId` (включая скрываемые last-wins importer), конфликтующие ArchiveEntryId/пути/TransactionId, плохой JSON или незаконченная строка не допускаются. Legacy .json не допускается. Вызов оригинального `Test-OPAArchiveMoves` на **новой синтетической десятиэлементной fake Outlook модели** обязателен до записи. Это не заменяет реальный independent Outlook postrestart.

`Audit` вычисляет SHA256 оригинальных TEMP journal/index и недостающие номера. `Recover` требует SHA обоих файлов *из предыдущего Audit*, явный флаг разрешения и повторяет аудит под эксклюзивным TEMP lease, после чего вызывает только исходный `Add-OPADuplicateEntry` для отсутствующих номеров. Используется `Safe` flush, закрытие stream и независимый readback; исходный journal никогда не дописывается. Если индекс уже содержит 10 верных записей — no-op без записи. Повтор после частичного восстановления требует **новых SHA из отдельного Audit**. Никакого replay/repair оригинальных `Intent`, `Reconciled` и `MailItem.Move()`.

Работает **исключительно** внутри существующего каталога `OS TEMP/OPA265-ARCH3s-FAKE-<guid>/OPA265-ARCH3r-SYNTH-<guid>`, запрещены reparse-points и реальные PST. Lock-файл создаётся только в отдельном TEMP workspace. Не разрешено использовать код для восстановления реального общего DuplicateIndex.

## Полный синтаксис

```powershell
.\Invoke-ARCH3t.ps1 -Mode Audit -Workspace <ARCH3s.OriginalJournalWorkspace>
.\Invoke-ARCH3t.ps1 -Mode Recover -Workspace <ARCH3s.OriginalJournalWorkspace> -ExpectedJournalSha256 <64_lower_hex> -ExpectedIndexSha256 <64_lower_hex> -ConfirmSyntheticRecovery [-WhatIf] [-Confirm:$false]
```

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `-Mode` | `Audit` | `Audit` — анализ без изменения журнала и индекса; `Recover` — дополнение только недостающих TEMP index entries. |
| `-Workspace` | обязателен | Только `OriginalJournalWorkspace` из `ARCH3s -Mode Integration -JournalFault AfterIndexAppend`. Не использовать `SyntheticWorkspace` верхнего уровня. |
| `-ExpectedJournalSha256` | пусто | Для `Recover` необходим строгий SHA-256 из текущего отдельного `Audit`. |
| `-ExpectedIndexSha256` | пусто | SHA-256 из текущего `Audit`; если index JSONL ещё не создан, допустимо пустое значение. |
| `-ConfirmSyntheticRecovery` | false | Обязательное отдельное явное разрешение на *синтетическую* запись. |
| `-WhatIf` | false | Запрет записи, выдаёт `WhatIfSyntheticRecoveryNoWrites`. |
| `-Confirm:$false` | не задан | Убирает дополнительный интерактивный PowerShell ShouldProcess запрос; **не** отменяет `-ConfirmSyntheticRecovery`. |

## Пример только с новыми синтетическими данными

```powershell
$broken = .\Invoke-ARCH3s.ps1 -Mode Integration -JournalFault AfterIndexAppend -FaultAt 2
$audit  = .\Invoke-ARCH3t.ps1 -Mode Audit -Workspace $broken.OriginalJournalWorkspace
$audit | Format-List
# Требуется 20 событий, 10 Reconciled, 2 Indexed, 8 MissingNumbers.
.\Invoke-ARCH3t.ps1 -Mode Recover -Workspace $audit.Workspace -ExpectedJournalSha256 $audit.OriginalJournalSha256 -ExpectedIndexSha256 $audit.OriginalIndexSha256 -ConfirmSyntheticRecovery -WhatIf | Format-List
$done = .\Invoke-ARCH3t.ps1 -Mode Recover -Workspace $audit.Workspace -ExpectedJournalSha256 $audit.OriginalJournalSha256 -ExpectedIndexSha256 $audit.OriginalIndexSha256 -ConfirmSyntheticRecovery -Confirm:$false
$done | Format-List
$review = .\Invoke-ARCH3t.ps1 -Mode Audit -Workspace $done.Workspace
$review | Format-List
# Ожидание: JournalEventCount=20, JournalReconciledCount=10, IndexedCount=10.
# Повторный Recover только с SHA нового $review и no-op.
```

**Важно:** `AfterJournalReconciled -FaultAt 3` (3 Reconciled / 0 Indexed) должен завершаться отказом: неизвестные исходы остальных семи не восстанавливаются индексом. Любое несоответствие — STOP, сохранить исходные данные, не пытаться повторять Move.
