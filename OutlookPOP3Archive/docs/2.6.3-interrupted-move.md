# 2.6.3 — Interrupted Move Reconciliation (DEV)

## Safety boundary

The independent `Core/Archive/MoveReconciliation.ps1` module never moves a message, writes Reconciled, creates/mounts a PST or permits automatic retry. It is not invoked by Archive, Resume or Auto. The Worker MailMove operation remains unavailable.

## Persisted evidence

2.6.3 extends MailMove Intent fields with SourceEntryId, SourceStoreId, SourceFolderPath, ArchivePst, TargetFolderPath, InternetMessageId, Subject, Sender and Size. Old 2.6.2 journals remain readable but an incomplete intent yields InsufficientEvidence. Journal SHA-256, sequence and transaction integrity are verified before analysis.

## Read-only classification

Full folder scans verify actual StoreID and folder paths, archive PST identity and four fingerprint fields. A failed COM property/collection read or incomplete fingerprint invalidates that snapshot.

| Status | Meaning |
|---|---|
| DestinationCandidate | Exactly one matching archive message, none in recorded source folder; **not proof** |
| SourceOnly | Match only in source; no automatic retry |
| BothPresent | Potential copy/duplicate; stop |
| MissingBoth | Cannot locate message; stop |
| Ambiguous | Multiple matching fingerprints; stop |
| IdentityConflict | EntryId/fingerprint conflict; stop |
| ScopeMismatch | Folder, store or archive path differs from Intent |
| IncompleteScan | Scan failed or inventory incomplete |
| UntrustedJournal | Truncated journal tail; preserve records |
| InsufficientEvidence | Old or metadata-poor Intent |
| AlreadyTerminal | Already confirmed in journal; no second action |

Every result has `ProvenMoved=False`, `AutomaticRetryAllowed=False`, `RequiresManualReview=True`. Source-only or destination-only observations never justify an automatic second Move or journal completion.

## Verification

Run `Invoke-CI.ps1 -ExpectedBuild '2.6.3-PREVIEW1'` under Windows PowerShell 5.1. Tests use fake source/destination COM folders and exercise identity/fingerprint/scan failures without modifying Outlook. Real integration needs disposable PSTs and a reviewed, separate approval protocol before any Worker Move is enabled.

## Controlled real-Outlook integration harness

`Core/Diagnostics/Invoke-OPA263LivePstTest.ps1` is explicitly opt-in, uses Windows PowerShell 5.1 STA, and requires an **existing donor PST path**. It creates two fresh Unicode PSTs under `%TEMP%/OPA263-Live-<guid>/`, each with its own uniquely named mail folder. The harness copies one matching MailItem from the donor's Inbox, moves **the copy** into the disposable source PST, and leaves the original item untouched. Outlook's `Copy()` may temporarily add a duplicate to the donor Inbox; interruption before the staging `Move()` may leave that duplicate. Use **only explicitly disposable PSTs** as the donor. The donor PST may grow physically from this activity.

The harness durably writes one unresolved MailMove Intent before the **first** controlled cross-PST `Move()`. It intentionally omits `Completed` to reproduce a crash window after Move. It checks `SourceOnly`, `DestinationCandidate`, `BothPresent`, and `Ambiguous` by placing copies only into isolated test folders. No automatic retry or journal `Reconciled` is issued. If COM changes the strict mail fingerprint (particularly `Size`), it prints a failure with the before/after size and leaves both PSTs and journal for investigation. It does not repair or reclassify the result silently.

```powershell
powershell.exe -NoProfile -STA
.\Core\Diagnostics\Invoke-OPA263LivePstTest.ps1 `
  -SeedPstPath 'C:\Users\<user>\Documents\Outlook Test\seed.pst' `
  -Execute
```

Only run while Outlook with the intended test PST is already running in the same interactive user session. The script never starts or quits Outlook, never opens an unrelated profile, and does not delete PST files or transaction evidence. The produced `report.json` and `*.operations.jsonl` are left in the unique temp directory along with both mounted PSTs. Close/detach the temporary stores manually after reviewing evidence.

This is a **mutating diagnostic harness using disposable test-only copies**, not a production feature: `MoveReconciliation.ps1` itself remains read-only and no production Worker Move is enabled.
