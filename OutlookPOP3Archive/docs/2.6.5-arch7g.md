## Безопасный план задачи (ничего не регистрирует)

Из каталога распакованного проекта в Windows PowerShell 5.1:

Дополнительные параметры: -InstallDirectory (по умолчанию каталог скрипта), -LogonDelayMinutes 0..30 (2), -AutoDevMaxBatches 1..100 (1), -OlderThanMonths 1..1200 (12), -ArchiveGrouping Year|YearQuarter|YearMonth (YearQuarter), -DailyAt HH:mm (нет по умолчанию). -ConfirmDevAutoArchive обязательно: все найденные POP3 должны быть тестовыми. ## Runtime WhatIf (без COM, без файловых записей)

~~~powershell
$sid = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
powershell.exe -NoProfile -NonInteractive -STA -File .\Invoke-OPARdsAutoDev.ps1 -ConfirmDevAutoArchive -ExpectedUserSid $sid -WhatIf
$LASTEXITCODE
~~~

Параметры runtime: -ConfirmDevAutoArchive, -ExpectedUserSid, -AutoDevMaxBatches (1), -OlderThanMonths (12), -ArchiveGrouping (YearQuarter), -WhatIf. WhatIf проверяет параметры и PS 5.1 STA, но не выполняет живую проверку пользователя/Outlook. При реальном DEV запуске перед Auto проверяются SID обычной локальной/доменной учётной записи, ожидаемый SID, SessionId > 0, интерактивность, отсутствие elevated admin token и ровно один OUTLOOK.EXE в этой сессии с подтверждённым владельцем (CIM Win32_Process/GetOwnerSid). Неизвестное состояние блокирует запуск. Далее оригинальный Auto повторно выполняет attach-only ROT, per-user mutex и directory-wide leases. Предварительная проверка процесса не заменяет COM-идентичность; гонки и RDS поведение требуют live acceptance.

| Exit | Значение | Реакция планировщика |
|---|---|---|
| 0 | Все источники исчерпаны / нет POP3 | Штатное завершение |
| 10 | Лимит партии | Не перезапускать; следующий штатный триггер |
| 20 | Partial/blocked | Проверить журналы/pending; не перезапускать вслепую |
| 30 | Неизвестный результат, ошибка, неверный пользователь/сессия, CIM | Не перезапускать; диагностика |
| 40 | Outlook отсутствует в текущей сессии | Отложить до следующего штатного входа/расписания; Outlook не запускать |

До вызова Auto диагностический JSONL ARCH7f не создаётся: код завершения и Task Scheduler Operational history являются источником диагностики preflight. После Auto действуют существующие приватные журналы и транзакционные доказательства. Внешний RestartOnFailure запрещён; код 40 не запускает автоматический повтор в цикле.

## XML и GPO (DEV, не разворачивать)

План использует InteractiveToken, LeastPrivilege, user SID в logon trigger и аргументах, IgnoreNew, Enabled=false, ExecutionTimeLimit=PT0S, AllowHardTerminate=false, StartWhenAvailable=false; не содержит паролей, S4U, SYSTEM или ExecutionPolicy Bypass. По умолчанию задержка входа 2 минуты; дополнительный ежедневный триггер выключен. Для RDS пилота отдельный GPO/GPP User Configuration / Preferences / Control Panel Settings / Scheduled Tasks, Update, только выбранный пользователь/хост, disabled, SID конкретного пользователя. Не применять один SID/XML ко всем пользователям; не активировать задачу до реальной приёмки. Установка в локальном защищённом каталоге, пользователям read/execute, запись администраторам. Не прерывать worker при Move; принудительный logoff/потеря питания не могут быть предотвращены настройкой XML. [Microsoft Task Scheduler XML schema](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema).
