# ARCH5a — embedded MSG semantic verification

ARCH5 real test 2026-11-24: the same source mail skipped in ARCH4 (attachment index 2, type 5) produced two different MSG export hashes. No claim or Move, Verified=0, Indexed=0, Resume completed transaction 20261124-115110-da167f3a. No replay of that transaction.

ARCH5a replaces type 5 binary equality with bounded recursive verification using Outlook NameSpace.OpenSharedItem on private exported .msg copies, without Display/Save/Send or activation. Each embedded MailItem is read twice, closed with olDiscard, and temp exports removed. Original semantic fields (subject, sender, recipients, body/HTML, dates, flags) and ordered attachment payloads are represented by a deterministic digest. Child MailItem.Size and MSG container bytes/size are not compared; type 1 and stable type 6 payloads retain byte SHA-256. The digest excludes only the existing diagnostic provider size; nested digest kind is explicit. Non-MailItem, read errors, missing data, changing semantic content, unsupported attachment type and unsafe/unremovable exports stop before claim. Signed/encrypted MSG may hold Outlook file handles; no bypass. Depth 4, 128 embedded reads per parent capture, 1 GiB per exported attachment, 128 attachments per mail. Historical schema .1 and .2 remain supported; new schema 2.6.5-ARCH5a.MailSemanticWitness.3 preserves flat journal depth.

Reference: https://learn.microsoft.com/en-us/office/vba/api/outlook.namespace.openshareditem and https://learn.microsoft.com/en-us/office/vba/api/outlook.olinspectorclose. This checks captured semantic content, not every hidden MAPI property or all embedded item types.

Zero-Move: after durable original selection termination and strict replay proving zero claims, returns and operation events, ARCH5a completes without Outlook restart and removes pending. Status BatchCompletedNoMoves, RestartRequired=False, Verified=0/Indexed=0. Never clears pending for unresolved claim. Normal nonzero batches still need independent restart before commit.
