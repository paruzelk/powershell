## Запуск Windows PowerShell 5.1 в STA

Распакуйте ZIP, запустите Outlook 2019 с профилем `Outlook`. В каталоге `OutlookPOP3Archive`:

```powershell
$pin = @{
    SourcePst = 'C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'
    SourceEntryId = '00000000E1878292411BC64291BD506DCEFD2A35E4FC3B00'
    ArchiveYear = 2020
    ExpectedSourceFolderEntryId = '00000000E1878292411BC64291BD506DCEFD2A3582800000'
    ExpectedStoreIdSha256 = 'c6f1cb064a78b6d8c676ace07d6ae8202f2477046e48d17baeade82581837ca3'
    ExpectedSourcePstLengthBytes = [long]7694763008
    ExpectedExistingArchiveLengthBytes = [long]271360
    ExpectedAttachmentCount = 0
    ExpectedArchiveDate = [datetime]'2020-02-13T12:57:58'
}

# Без COM и без записи.
.\Invoke-ARCH3h.ps1 -Mode Plan @pin | Format-List

# Реальное чтение оригинала и полный SHA256 semantic witness.
$w = .\Invoke-ARCH3h.ps1 -Mode Witness @pin
$w | Format-List Schema,Status,SourceEntryId,SourceArchiveDate,AttachmentCount,OriginalWitnessSha256,BodySha256,HtmlBodySha256,RecipientDigestSha256,FullWitnessCaptured,FullWitnessPersisted,LiveMovePerformed,WriterPermit,ProductionReady
```

Учитывайте региональный часовой пояс при интерпретации `[datetime]`: передайте локальную дату, **без UTC-конвертации**. По итогам зафиксируйте SHA256 `OriginalWitnessSha256` независимо от следующего запуска.

## Параметры полностью

| Параметр | Тип | Обязателен | Назначение |
| --- | --- | --- | --- |
| `-Mode` | `Plan` / `Witness` | Нет, `Plan` | План без COM или полный настоящий witness через Outlook |
| `-SourcePst` | строка, локальный `info@stios.ru.pst` | Да | Тестовый исходный POP3 PST |
| `-SourceEntryId` | полный hex Outlook EntryID | Да | Единственное разрешённое письмо |
| `-ArchiveYear` | int 1900–2100 | Да | Ожидаемый исходный год маршрута |
| `-ExpectedSourceFolderEntryId` | полный hex EntryID папки | Да | Подтвержденный Inbox |
| `-ExpectedStoreIdSha256` | hex SHA-256, 64 символа lowercase | Да | Проверка исходного StoreID без печати его содержимого |
| `-ExpectedSourcePstLengthBytes` | int64 > 0 | Да | Защита от изменения источника между этапами |
| `-ExpectedExistingArchiveLengthBytes` | int64 > 0 | Да | Запрет незаметного изменения уже имеющегося `Archive-2020.pst` |
| `-ExpectedAttachmentCount` | int 0–256 | Да | Пиннинг реального количества вложений |
| `-ExpectedArchiveDate` | datetime | Да | Точная проверенная дата письма, локальная без смещения |

Оба режима возвращают `WriterPermit=False`, `ProductionReady=False` и `LiveMovePerformed=False`. В режиме `Witness` оригинальная `Get-OPA265ARCH2bMailSemanticWitness` хеширует Body/HTML/получателей/вложения; применяются проверенные `Get-OPA265ARCH2bTextSha256`, `Test-OPA265ARCH2bWitnessSchema` и `Get-OPA265ARCH3dOriginalWitnessHash`. Исходные тексты писем не печатаются. Для письма без вложений хешируется 0 вложений; при последующих тестах с вложениями оригинальная реализация временно сохраняет их копии в частной папке TEMP и удаляет по завершении, поэтому `NoPstOrJournalWrites` **не означает отсутствия временных файлов**.

**Что ещё не готово:** durable `PrepareIntent`/файл с полным исходным witness, одноразовый разрешённый настоящий writer через исходный `Move-OPAItemsWithLimit`, изоляция исходного общего `DuplicateIndex` для существующей первой части, настоящий рестарт Outlook, независимая сверка/оригинальный `OperationJournal Reconciled` и `DuplicateIndex`. Запрещено приравнивать успешное получение исходного witness к завершению ARCH3h Live One-Shot. Старые RunId и COM Move нельзя повторять автоматически.

Полная проверка Windows PowerShell 5.1 Pester + PSScriptAnalyzer, BOM/JSON gates выполняется в CI; реальный Outlook в GitHub Actions не запускается.
