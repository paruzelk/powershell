## Architecture

NEW Core/Worker/BW4k7uSyntheticBatch265.ps1 and Core/Diagnostics/Invoke-OPA265BW4k7uSyntheticMultiItemPreflight.ps1 are pure PowerShell 5.1 synthetic in-memory models. NO Outlook COM calls, NO PST read/write/create, NO registry access, NO real or persisted journal/Claim, NO filesystem evidence writes, NO actual Move, no live operator data. Do NOT interpret these results as physical crash recovery tests or real Outlook MAPI equivalence.

Exactly 12 model fixtures with unique canonical SuiteId GUID, unique CaseIds and SHA256 manifest:
- Inbox2020Plain: 2020 Inbox plain.
- Inbox2021Unicode: 2021 Inbox Cyrillic.
- Inbox2024Html: 2024 Inbox HTML.
- Inbox2025Attachment1K: 2025 Inbox exact synthetic 1024-byte attachment, SHA256 of decoded bytes.
- Sent2023Unicode: 2023 Sent with Bcc recipient.
- Sent2025Attachment256K: 2025 Sent with actual 262144-byte deterministic attachment and raw-byte SHA256.
- User2022Nested: 2022 custom folder \Projects\Alpha\2022, attachment.
- User2024HtmlAttach: 2024 custom folder \Projects\Beta, HTML+attachment.
- Inbox2026Retained: current 2026 mail, excluded from archival.
- InboxNdrRetained, InboxReadReceiptRetained, InboxMeetingRetained: the 3 known class patterns as separate SYNTHETIC model objects, excluded and preserved.

The 8 first cases model eligible MailItems. The remaining 4 objects are preserved. Synthetic attachments are generated in memory as byte arrays and Base64; sha256 is computed over actual decoded bytes (not Base64 text). No real user item is a fixture. Messages include sender, ordered recipients To/Cc/Bcc, plain/HTML, headers, dates, read state, categories/followup, simulated before/after MAPI flags and size change, and original folder path.

Get-OPA265BW4k7uSyntheticCapacityPlan reuses BW4k7r conservative per-PST planning: default 45,000,000,000-byte max, 3,000,000,000-byte safety margin, 25% estimated expansion, 65,536 bytes per message. It allocates each modeled item sequentially by year, preserving exact original folder paths. SimulatedSegmentCapBytes=420000 forces an artificial 2025 Archive-2025-02.pst rollover case with no real PST involved. It rejects any single modeled item that exceeds the safe segment capacity. These are forecasts, not physical PST growth or durable capacity proof. No registry size-limit change.

New-OPA265BW4k7uSyntheticLedger models eight separate rows and one-shot attempt states:
UnclaimedSourceOnly -> ModeledIntentNoDiskClaim -> ClaimedSourcePresentNeverRetryAutomatically -> DestinationOnlyAwaitIndependentReconciliation -> SyntheticReconciledRiskReviewOnly.

Set-OPA265BW4k7uSyntheticPhase tracks one intent, one claim and one modeled transfer. The modeled transfer only clones the synthetic object in RAM and changes modeled source/destination presence. Independent reconciliation compares protected source content, folders, recipients, dates, user flags, raw attachment bytes/SHA256, and calls the prospective BW4k7t semantic A/B/C evaluator. Unknown flag 0x00010000 remains category C, not waived and not accepted. Missing content, changed recipients or tampered attachment -> blocked. Duplicate claim/transfer/reconciliation -> STOP.

Invoke-OPA265BW4k7uSyntheticBatch supports injected model interrupts AfterIntent, AfterClaim and AfterMove for an exact synthetic case. A claimed source still present is manual-review-only and NEVER retried. A destination-only item may be reconciled read-only, never moved again. The remaining unclaimed batch rows are not automatically resumed. The in-memory ledger and recovery model DO NOT survive PowerShell process exit, do NOT create a filesystem fsync-proof journal, and DO NOT demonstrate actual crash durability; the console must clearly retain ActualCrashOrRestartRecoveryProven=False and WriterPermit=False regardless of a synthetic PASS.

Download the verified public project-only BW4k7u DEV ZIP, extract into a separate folder, run the following commands from inside that project directory. Outlook is NOT needed.

## Scope limits and safety

BW4k7u deliberately does NOT prove actual POP3 Sent Messages, physical PST format/capacity, content persistence across Outlook restarts, per-item journal durability, genuine power-loss recovery or class-specific nonMail Move safety. Those need NEW disposable PSTs with independently pinned witnesses in future BW4k7v/BW4k7w. NEVER retry the old BW4k7m one-shot item. No previous user test files are deleted or detached.

Always OutlookMoveExecuted=False, RealPstOrRegistryAccessed=False, DiskIntentClaimOrJournalWritten=False, CrashDurabilityOrRealResumeProven=False, AutomaticRetryAllowed=False, WriterPermit=False, ProductionReady=False. Original BW4k7o historical SEM-001 remains blocked.

All newly modified PowerShell PS1 files must be UTF-8 with BOM (EF BB BF), Windows PowerShell 5.1 CI PSScriptAnalyzer/Pester plus original BW4j6 synthetic matrix and strict JSON release gates, project-only public ZIP with exact git commit and SHA256.
