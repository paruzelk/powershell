# OutlookPOP3Archive 2.6.4 — live Outlook safety gate (TEST ONLY)

This branch is a **diagnostic test runbook**, not a release. The user has
independently reported 464/34 Pester PASS and exact ZIP SHA/content match
for 2.6.4-G, but actual PST/Outlook COM tests have NOT been run.

## Stage 0: clean abandoned 2.6.3 PSTs

Use Core/Diagnostics/Remove-OPA263TestArchives.ps1, preview-only by
default, locally under Windows PowerShell 5.1.

    .\Core\Diagnostics\Remove-OPA263TestArchives.ps1 -SearchPath "$env:USERPROFILE\Downloads" -Recurse

If no files found and old test PSTs were created in TEMP:

    .\Core\Diagnostics\Remove-OPA263TestArchives.ps1 -SearchPath $env:TEMP -Recurse

Review filenames and sizes first. Files MUST be confirmed as expendable
from previous 2.6.3 tests. Detach any of those data files manually in
Outlook's Data Files settings. Fully close Outlook before deletion. The
script refuses to delete if ANY OUTLOOK.exe is running, if a candidate is
locked, if any path is through a junction/reparse point, or if a candidate
is outside the explicitly searched local directory. Only filenames
matching ^opa263_archive.*\.pst$ are ever eligible. No folders are
deleted and nothing named OPA264 is touched. An explicit -Delete and
-ApprovalToken DELETE-OPA263-ARCHIVES are required, plus interactive
confirmation (SupportsShouldProcess).

    .\Core\Diagnostics\Remove-OPA263TestArchives.ps1 -SearchPath "$env:USERPROFILE\Downloads" -Recurse -Delete -ApprovalToken DELETE-OPA263-ARCHIVES -Confirm

## Stage 1: read-only isolated Outlook preflight

Run ONLY with an isolated test Windows account/VM and test Outlook
profile named **OPA264-LAB**. Do not import a real mailbox or
production PST. The profile must have ZERO email accounts and ONE
empty local default data store. It must be the already-running
Outlook profile registered through COM, not a different instance.

    powershell.exe -NoLogo -NoProfile -STA -File ".\Core\Diagnostics\Test-OPA264IsolatedOutlook.ps1" -Review

Expected Status=ReadOnlyPreflightPassed, Profile=OPA264-LAB,
EmailAccounts=0, BaselineStores=1 and MailMoveExecuted=false.
This script attaches to the existing Outlook.Application with
Marshal.GetActiveObject ONLY. It never launches Outlook, attaches
a store, detaches a store, creates/deletes mail or files.

**Do not run the fixture, Controller, Move or IdentityReopen diagnostic
yet** until a successful preflight has been inspected and the live
fixture revision is pinned/validated in a separate development snapshot.
