# ARCH3x2 unified — ARCH3x1b + независимый postrestart original verifier и journal/index commit

**23 ноября 2026, DEV.** Только подтверждённый тестовый POP3 PST `info@stios.ru.pst`, Outlook 2019, Windows PowerShell 5.1 STA, исходный профиль `Outlook`.

## Исправление логики архивации

Исходный PST — постоянно изменяющееся хранилище. Его физическая длина (любой рост/уменьшение/сжатие) **не участвует в допуске к переносу**. ARCH3x1b не повторяет историческую выборку первых 10 кандидатов сортировщика и не требует неизменного общего количества Inbox. Вместо этого он открывает **10 точных исходных сообщений**, ранее подтверждённых ARCH3v и ARCH3w1, и проверяет их StoreID, родительскую папку, дату, оригинальные Body/HTML, получателей, пользовательские атрибуты, число и реальные байты вложений по семантическим SHA. Если конкретное письмо пропало или изменилось — останавливает этот строго одноразовый пилот, не повреждая остальные письма. Для будущей массовой архивации такой случай будет помечаться как skipped и продолжатся остальные.

Existing Part1/Part2 определяются по безопасным оригинальным путям, без сравнения физической длины или полного SHA двух PST. Part2, содержащий историческое одно письмо, независимо проверяется оригинальным `ArchiveVerifier` по полной семантике. Общий индекс дубликатов по-прежнему должен быть исходным для конкретного пилота (чтобы не получить двойную запись). Отдельная массовая версия позднее перейдёт от общего статичного SHA к конфликтным проверкам по каждому письму.

## Параметры и синтаксис

Все команды запускаются **в папке новой сборки ARCH3x2**; старые ARCH3v/w1 Seal/Manifest/Journal не трогать.

~~~powershell
$pin=@{
    RunId='093b5ce9-4a90-46fa-b6a5-7cdba61d2f15'
    SealSha256='d071afbff028d4cbadcea69318a6d68009242ac401cd2a91abf08b5ffe9f6799'
    ManifestSha256='7568fb8cad7f89ced44d11d1117d4ef3e53e193f9269abee2b7f0e5f7b44b7e5'
    JournalSha256='a70fc0a419d44818bdeb3f306a1bbd6076ee39074a53101dd2ba274c4d5cf74e'
}

# 1. Без Outlook, только защищённые файлы
.\Invoke-ARCH3x1.ps1 -Mode Status -RunId $pin.RunId | Format-List
.\Invoke-ARCH3x1.ps1 -Mode Plan @pin | Format-List

# 2. Реальные 10 ORIGINAL source full witnesses БЕЗ любых persistent writes
$audit= .\Invoke-ARCH3x1.ps1 -Mode Audit @pin
$audit | Format-List

# 3. WhatIf отдельно. Alias Set-Alias сообщения лишь побочный эффект загрузки модулей
.\Invoke-ARCH3x1.ps1 -Mode Move @pin -ExpectedPreflightDigest $audit.PreflightDigest -ConfirmTenRealMoves -WhatIf | Format-List

# 4. ЕДИНСТВЕННЫЙ реальный тестовый перенос после ознакомления с Audit/WhatIf
# и резервной копии тестового PST, без запуска второй раз при любом исходе:
# $moved = .\Invoke-ARCH3x1.ps1 -Mode Move @pin -ExpectedPreflightDigest $audit.PreflightDigest -ConfirmTenRealMoves -Confirm:$false
# $moved | Format-List
# .\Invoke-ARCH3x1.ps1 -Mode Status -RunId $pin.RunId | Format-List

# 5. ПОСЛЕ Move: полностью закрыть Outlook, затем запустить Outlook снова.
# Требуется ДРУГОЙ процесс Outlook с новым временем запуска;
# источник и архив Part3 должны быть подключены в том же профиле.
# .\Invoke-ARCH3x2.ps1 -Mode Plan @pin | Format-List
# $review = .\Invoke-ARCH3x2.ps1 -Mode Review @pin
# $review | Format-List

# 6. Только после полного PASS оригинального ArchiveVerifier всех десяти
# .\Invoke-ARCH3x2.ps1 -Mode Seal @pin -ConfirmReviewSeal -WhatIf | Format-List
# $sealed = .\Invoke-ARCH3x2.ps1 -Mode Seal @pin -ConfirmReviewSeal -Confirm:$false
# $sealed | Format-List

# 7. Независимый WRITE-гейт журнала/index - отдельное явное решение:
# .\Invoke-ARCH3x2.ps1 -Mode Commit @pin -ReviewSha256 $sealed.ReviewSha256 -ConfirmVerifiedCommit -WhatIf | Format-List
# $committed = .\Invoke-ARCH3x2.ps1 -Mode Commit @pin -ReviewSha256 $sealed.ReviewSha256 -ConfirmVerifiedCommit -Confirm:$false
# $committed | Format-List
# .\Invoke-ARCH3x2.ps1 -Mode Status -RunId $pin.RunId | Format-List
~~~

Для `Invoke-ARCH3x1.ps1`:
- `-Mode Status|Plan|Audit|Move`; `-RunId` обязателен, строго указанный GUID.
- Для Plan/Audit/Move обязательны `-SealSha256`, `-ManifestSha256`, `-JournalSha256` из уже подтверждённых архивов.
- Для Move **обязателен** `-ExpectedPreflightDigest` из **нового** ARCH3x2 сборки Audit плюс `-ConfirmTenRealMoves`; `-WhatIf` проверяет остановку до записей/контакта с Outlook. Старый ARCH3x1a PreflightDigest **НЕ годится**.

Для `Invoke-ARCH3x2.ps1`:
- `-Mode Status|Plan|Review|Seal|Commit|Recover` — обязательный режим. Status автономен.
- Plan/Review/Seal/Commit/Recover: все четыре поля из `$pin`.
- Seal: `-ConfirmReviewSeal` и повторная настоящая независимая проверка 10 писем в новом Outlook; защищённое создание одноразового `verified-ten-restart.json`.
- Commit: `-ReviewSha256` из успешного Seal и `-ConfirmVerifiedCommit`; повторный оригинальный 10-item ArchiveVerifier и только затем одноразовый `journal-index-commit-claim.json`, **другой** append-only оригинальный OperationJournal (10 Intent + 10 Reconciled) и 10 элементов общего индекса.
- Recover: **только** при наличии `journal-index-commit-claim.json` после прерванного Commit: `-ReviewSha256`, `-ConfirmRecovery`, полный повтор оригинального ReadOnly ArchiveVerifier; дописывает только отсутствующие зафиксированные события/индекс, НИКОГДА не вызывает Move. Нельзя использовать при оборванных/повреждённых JSONL. В случае сомнений остановиться и прислать доказательства.
- `-Confirm:$false` убирает вторичный запрос ShouldProcess; не заменяет explicit operator-флаги.
- `-WhatIf` для Seal/Commit/Recover не вносит изменений.

## Инварианты

1. Архив исходных подготовленных ARCH3w1 Intent **immutable**: original SHA исходного журнала `a70fc0a4...` всегда тот же. Новые verified Reconciled события пишутся ОРИГИНАЛЬНЫМ `Write-OPAOperationJournalEvent` в отдельно защищённый ARCH3x2 append-only журнал и связываются с исходным подготовленным SHA; исходные файлы не переписываются.
2. Postrestart `Test-OPAArchiveMoves -ExpectedMoved 10 -RequireSemanticWitness` обязан подтвердить отсутствие всех 10 исходных EntryID, ровно 10 полученных архивных писем в Part3, полные оригинальные Body/HTML/вложения, новый процесс Outlook. Общее количество писем в обычной Inbox не фиксируется.
3. Индекс пишется оригинальным `Add-OPADuplicateEntry` и немедленным `Sync-OPADuplicateJournalStreams`, после полного Reconciled. Отдельное самостоятельное подтверждение. Любой неожиданный индекс или частичная запись — STOP.
4. Никаких автоматических повторов Outlook `Move()`, даже после аварии на первом/десятом письме. Только ручное разбирательство, а после завершённой независимой проверки возможно восстановление индекса/журнала.
5. Это **один реальный пилот из 10 сообщений**, не разрешение основного `Archive/Resume/Auto` на 90 ГБ.

CI: Windows PowerShell 5.1, PSScriptAnalyzer, полная Pester, UTF-8 BOM, статические source-backed gates, только project ZIP/SHA256. В GitHub Actions настоящий Outlook/MAPI не используется.
