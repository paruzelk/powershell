# OutlookPOP3Archive 2.6.4-C — controlled crash injection, diagnostic only

## Status and validation
Unreleased, development-only, Windows PowerShell 5.1 CI **pending**.
User-reported prior 2.6.4-B2 CI PASS: 334 tests / 29 containers,
no failures or skips. This does not validate the new C code.

This increment adds 24 offline crash-barrier tests. Full expected suite:
**358 Pester tests in 30 containers**. No Outlook integration or live
MailItem.Move has been executed by this development operation.

## Safety model

**Never run this on a production Outlook/RDS profile**. The test fixture
creates two NEW PST files in a RunId-specific directory under OS TEMP.
A controlled crash mode requires three independent choices: run the
diagnostic controller's -Execute switch, provide one exact named
-ControlledCrashWindow, and opt in with -EnableControlledCrash.
There is no production Worker MailMove allowlist change, and Archive,
Resume and Auto remain on FIX13b.

Only the System.Diagnostics.Process object spawned by the test controller
may be terminated. The controller never accepts a caller-supplied PID,
kills Outlook.exe or terminates other workers.

## Supported deterministic crash windows

| Window | Barrier writer | Consequence |
| --- | --- | --- |
| AfterIntentBeforeDispatch | Controller, after flushed dispatch claim | Controller exits before child creation; no report; replay forbidden |
| WorkerStartedBeforeMove | Test Worker after Outlook namespace acquired | Parent checks flushed barrier + RunId + OperationId + PID, then terminates its own child; no COM Move |
| AfterMoveBeforeResponse | Test Worker after one COM Move returned | Only allowed after the durable worker Move claim; parent terminates its own child; no Worker response |
| AfterResponseBeforeTerminal | Controller after validated Worker response | Controller exits without controller-result.json; **no journal terminal exists in C**; label means before diagnostic report only |

The second and third windows use a bounded barrier wait. If the parent
disappears, the Worker stops after 30 seconds; it must never retry. For
the post-Move window, an existing durable, matching worker Move claim is
mandatory. A matching barrier is independent diagnostic evidence, not
proof that PST contents are correct.

The policy matrix also records DuringMove, but this increment DOES NOT
claim deterministic interruption inside a synchronous COM Move call.
The windows BeforeIntentFlush, WorkerTimeoutOrMissingResponse and
OutlookUnavailable remain separately classified by existing recovery
policy and are not callable as controlled fault injection modes.

## Protocol and evidence

- Intent flushed, request and last-written scope marker verified.
- One-shot controller-dispatch.claim flushed before any fault window.
- Child one-shot move-attempt.claim flushed before COM Move.
- Separate run-scoped crash-barrier.json written with FileMode.CreateNew,
  FileStream.Flush(true), RunId, OperationId, owner, and live PID.
- Parent validates child barrier against its own System.Diagnostics.Process.Id
  before calling Process.Kill() on THAT child object.
- In every window: NO automatic retries, NO journal Completed/Reconciled,
  NO change of production worker options; independent fresh-process
  source/destination read-only reconciliation remains mandatory.
- Never remove a claim to try another crash window on the same RunId.

## Live test gate

Live fixture/Move requires an isolated test VM or disposable Outlook
profile, explicit approval, and a NEW pair of real PSTs for EACH window.
Do not invoke the controller on a production account. Start with a
read-only fixture review, then the pre-dispatch and pre-Move scenarios.
Only after those pass should post-Move crashes be considered. Do not
infer real Move correctness from a parent process exit code. Phase D
will restart PowerShell and perform independent PST reconciliation.

Known risk: the B2 test fixture writes synthetic MAPI InternetMessageId
and sender fields, which must be tested on actual Outlook versions.
If Outlook cannot preserve the fields, the test MUST fail closed;
do not import a real email or bypass fingerprint validation.
