## Technical reason for conservative treatment

Microsoft documentation: PidTagMessageSizeExtended uses property ID 0x0E08 with PT_I8, property tag 0x0E080014. Documentation does NOT guarantee that the PST provider and Outlook PowerShell COM PropertyAccessor can marshal that variant type in this runtime. GetProperty is documented to return errors for unsupported property types, unavailable properties or mismatched proptag types, and type coercion is generally not performed.

References:
- https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessagesizeextended-canonical-property
- https://learn.microsoft.com/en-us/office/client-developer/outlook/mapi/pidtagmessagesize-canonical-property
- https://learn.microsoft.com/en-us/office/vba/outlook/how-to/navigation/getting-the-value-of-a-property
- https://github.com/MicrosoftDocs/VBA-Docs/blob/main/outlook/How-to/Navigation/best-practices-for-getting-and-setting-properties.md

Do not assume the COM failure is MAPI_E_NOT_FOUND. Never mark this provider property as "absent" just because it could not be read.

## Hotfix behavior

BW4k7n1 alters only the OPTIONAL "PrMessageSizeExtended" descriptor with exact Name='PrMessageSizeExtended', Tag='0x0E080014', Kind='Int64', Required=False:

- Skip invoking PropertyAccessor.GetProperty() for that exact PT_I8 tag in PS5.1 Outlook COM.
- Record it as Available=False, Value=null, ObservationState='NotProbedPowerShellComPtI8Interop'.
- In outer report: PrMessageSizeExtendedPresent=False, PrMessageSizeExtendedBytes=null, PrMessageSizeExtendedObservationState='NotProbedPowerShellComPtI8Interop', PrMessageSizeExtendedNotProbedByDesign=True, PrMessageSizeExtendedProviderSupportEstablished=False.
- These values indicate **not probed**. They do not establish that the actual provider value was missing or a specific number.
- All other 10 scalar fields still use live GetProperty; required PR_MESSAGE_FLAGS, PR_MESSAGE_STATUS and PR_HASATTACH remain fail-closed on ANY COM error. The optional PR_MESSAGE_SIZE 0x0E080003 is still attempted as originally planned and reports Read/MapiNotFound or a stop on a different error.
- Two independent archived COM paths compare ObservationState in addition to name/tag/available/value.
- No third Move, no evidence or Claim rewrite, no journal, no size or 0x00010000 waiver, no production.
- Original PRE-MOVE raw PR_MESSAGE_SIZE and extended size were NOT captured. The reason for the -532-byte MailItem.Size difference remains unproven, even when current 32-bit PR_MESSAGE_SIZE is obtained.
