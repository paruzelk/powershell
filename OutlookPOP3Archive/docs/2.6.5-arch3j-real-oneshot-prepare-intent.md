# ARCH3j — реальный POP3 One-Shot PrepareIntent, без Move

**Статус:** Windows PowerShell 5.1 DEV. Оригинальный MailMover Year/Part routing и Original OperationJournal Intent, без создания PST, COM Move и синхронизации DuplicateIndex.

## Зафиксированная операторская приёмка

- ARCH3i1 Review: `IndependentReadbackPassed=True`, `FullWitnessPersisted=True`, `WriterPermit=False`.
- Неповторяемое свидетельство ARCH3i RunId: `3773bcd7-5a07-4c31-8ce5-dfb16ddd30bf`.
- SHA-256 сохранённого файла: `5f5a86b6c1aba8a3d2ee328a36a5632f8edf1e89fdda8e7fd728688fe881b2a4`.
- Original semantic witness: `8782b410253f54cc5374661077cdfc9279bcfba12805f0dab42b461320cb999c`.
- Source EntryID: `00000000E1878292411BC64291BD506DCEFD2A35E4FC3B00`, POP3 Inbox, 2020, 0 attachments.
- Existing `info@stios.ru.Archive-2020.pst` = 271360 bytes, часть 1, **не открывать для записи**. Следующая часть по оригинальной Year-схеме — `info@stios.ru.Archive-2020-02.pst`, пока только резервируемый в контракте путь, **не создаётся**.

## Использование (Windows PowerShell 5.1, STA)

Работать в распакованном каталоге проекта. `Plan` не подключается к Outlook. `Audit` и `Prepare` требуют один запущенный Outlook 2019 и профиль `Outlook`. `Review` работает без Outlook.

```powershell
$run = [guid]::NewGuid().ToString('D') # новый ARCH3j RunId, НЕ старый ARCH3i RunId
$sealed = @{
    RunId = $run
    SealRunId = '3773bcd7-5a07-4c31-8ce5-dfb16ddd30bf'
    SealSha256 = '5f5a86b6c1aba8a3d2ee328a36a5632f8edf1e89fdda8e7fd728688fe881b2a4'
}

.\Invoke-ARCH3j.ps1 -Mode Plan @sealed | Format-List

# Прочитать реальный источник и оригинальный общий DuplicateIndex, без изменений
$audit = .\Invoke-ARCH3j.ps1 -Mode Audit @sealed
$audit | Format-List

# ДЕЛАТЬ ТОЛЬКО при Status=OriginalArchiveIndexAndSealedSourcePermitEvidenceOnlyPrepareIntent.
# Действие записывает только приватный PrepareIntent + оригинальный журнал Intent.
$prepared = .\Invoke-ARCH3j.ps1 -Mode Prepare @sealed -ConfirmPrepareIntent -Confirm:$false
$prepared | Format-List

# Независимое повторное чтение сохранённого Intent и оригинального журнала:
.\Invoke-ARCH3j.ps1 -Mode Review -RunId $run -IntentSha256 $prepared.IntentSha256 -JournalSha256 $prepared.JournalSha256 | Format-List
```

**Если Audit возвращает `ExistingOriginalDuplicateIndexBlocksNewRealOneShotPreparation`, не выполнять Prepare.** В поле `IndexReason` будет `OriginalSharedDuplicateIndexDirectoryMissing`, `OriginalSharedDuplicateIndexFilesMissing` или `SourceAlreadyInOriginalSharedDuplicateIndex`. Исходные механизмы не должны молча создавать/восстанавливать индекс при первом пилоте. Требуется отдельное решение по старым архивным индексам и сверке существующего архива.

## Полный синтаксис

| Параметр | Тип | Обязателен / правила |
| --- | --- | --- |
| `-Mode` | `Plan`, `Audit`, `Prepare`, `Review` | По умолчанию `Plan`. Реальный Move отсутствует. |
| `-RunId` | canonical lowercase GUID | Всегда; **новый** для ARCH3j, повтор Prepare запрещён. |
| `-SealRunId` | canonical lowercase GUID | Для Plan, Audit, Prepare; только RunId существующего ARCH3i. |
| `-SealSha256` | lowercase SHA256 64 hex | Для Plan, Audit, Prepare; от сохранённого ARCH3i файла. |
| `-ConfirmPrepareIntent` | switch | Обязателен для Prepare; **только запись доказательств**, не PST и не Move. |
| `-IntentSha256` | lowercase SHA256 64 hex | Для Review; результат Prepare. |
| `-JournalSha256` | lowercase SHA256 64 hex | Для Review; результат Prepare. |
| `-WhatIf` | switch | Для Prepare делает полный отказ от записи без обращения к Outlook. |
| `-Confirm` | ShouldProcess switch | Для Prepare требуется явное `-ConfirmPrepareIntent`; можно указать `-Confirm:$false`. |

## Предохранители ARCH3j

Исходный file-seal проверяется через оригинальный `Test-OPA265ARCH3iReadback` и `Read-OPA265ARCH3cPinnedJson`; в `Audit/Prepare` реальное письмо заново сверяется по `StoreID` SHA256, `EntryID`, `FolderEntryID`, `ArchiveDate` и полному `Get-OPA265ARCH2bMailSemanticWitness`. Маршрут использует **оригинальный** `New-OPA265ARCH3bOperationContract`, который вызывает `Get-OPAArchivePartPath` и `Get-OPAArchiveTargetPath`. Все существующие годовые части проверяются на диске; Part1 обязан остаться ровно 271360 байт, а Part2 — отсутствовать.

Исходный `DuplicateIndex` открывается **только на чтение** через оригинальный `Import-OPADuplicateIndex` и лишь после проверки существования каталога и хотя бы одного индексного файла. Любой отсутствующий файл, битый/неполный JSONL (включая строго проверяемую последнюю запись, даже если исходный reader tolerates tail) или совпадение `SourceEntryID` блокирует Prepare; `Sync-OPADuplicateIndexFromJournal` **не вызывается**, никакого автоматического восстановления/подмены.

Prepare с отдельным `RunId` создаёт `%LOCALAPPDATA%\OPA265-ARCH3j-{RunId}` с защищённой ACL, одноразовый `original-prepare-intent.json` через `CreateNew+Flush(true)` и оригинальный `original-operation-journal.jsonl` с **единственным** `Phase=Intent` (Flush(true)). Затем проверяются оба SHA и разбор настоящего OperationJournal. Незавершённый или частичный RunId не переиспользовать. После записи **нет** вызова `AddStoreEx`, `MailItem.Move`, открытия будущего PST, `MoveClaimed`, `DuplicateIndex` или `Archive/Resume/Auto`; флаги `WriterPermit=False`, `ProductionReady=False`.

**Дальнейший реальный пилот** должен использовать это закреплённое Prep evidence, создать **ровно один новый** Part2 PST с дополнительным разрешением, записать immutable MoveClaimed перед COM, никогда не повторять неопределённый Move, независимо проверить источник/архив через ORIGINAL `ArchiveVerifier` после настоящего рестарта Outlook; только затем Reconciled/Index. Требуются дополнительные CI + операторская приёмка перед разрешением на Move.
