# ARCH2c1 — изоляция временных файлов вложений и read-only инвентаризация после сбоя

**Статус:** DEV, Windows PowerShell 5.1; предварительный подэтап ARCH2c, **не является реальной Outlook-приёмкой**. Родительский этап: [ARCH2b](2.6.5-arch2b-semantic-verifier.md). Нормативные ограничения: [SEM-001](SEMANTIC-INTEGRITY-POLICY.md), [ADR](ADR-ARCH1-OUTLOOK-COM-BOUNDARY.md), [roadmap](DELIVERY-ROADMAP.md).

## Что меняется

- Основной `Get-OPA265ARCH2bAttachmentWitnesses` по-прежнему использует Outlook COM `Attachment.SaveAsFile` и SHA-256 фактических байтов (схема original pre-Move witness **не меняется**).
- Вместо сохранения каждой копии прямо в пользовательский TEMP создаётся **отдельный случайный каталог** `OPA-ARCH2c1-<GUID>` непосредственно внутри заданного temp-root. Имена вложений не попадают в файловые пути.
- После успешной записи, хеширования и при обычных исключениях отдельные файлы удаляются, затем каталог удаляется **без рекурсии**. Если каталог не пуст, подменён reparse-point или не удалился — **STOP**, а не стирание неизвестных файлов.
- `Get-OPA265ARCH2c1AttachmentWorkspaceInventory` только перечисляет каталоги с точным разрешённым именем. Функция не читает вложения, **не удаляет** их и не считает каталог безопасным для автоматического удаления: он может принадлежать ещё работающему процессу.
- Полное падение процесса/OS может оставить файлы. Автоматического удаления вчерашних/чужих каталогов **нет**, поскольку при нескольких процессах нельзя безопасно считать каталог неиспользуемым по одному возрасту.

## Проверка без Outlook

```powershell
# Из каталога OutlookPOP3Archive, только чтение TEMP.
. .\Core\Archive\ARCH2bSemanticWitness.ps1
Get-OPA265ARCH2c1AttachmentWorkspaceInventory |
    Format-Table WorkspacePath,LastWriteTimeUtc,RequiresManualReview -AutoSize
```

**Важно:** TEMP может содержать конфиденциальные вложения. Не публиковать временные копии в GitHub Issues, логах или ZIP.

После аварии безопасная последовательность: завершить **все** работающие копии архиватора/Outlook, сохранить evidence при необходимости, проверить точную принадлежность каталогов этому инструменту и только затем вручную удалить именно подтверждённые оставшиеся каталоги. Скрипт специально не предоставляет рекурсивную auto-cleanup команду.

## Тесты и ограничения

Новые тесты `Tests/Archive/ARCH2c1TempIsolation.Tests.ps1` покрывают success, нулевое и несколько вложений, частичный `SaveAsFile` + throw, несовпадение сообщённого и фактического размера, неподдерживаемый тип, отсутствие root, инвентаризацию остатков без чтения файлов и сохранность ARCH2a guard. Проверка выполняется без Outlook и без PST.

**Не проверено этим этапом:** реальный Outlook COM provider и его реакции на `SaveAsFile`, Windows ACL temp-root, power-loss/kill во время записи, нестандартные вложения/OLE, 256 МиБ фактической нагрузки, независимая сверка после restart, end-to-end Copy/Verify/Delete и 90 ГБ PST.

**Следующий этап: ARCH2c2** — строгий policy для temp ACL/active leases, тесты crash windows, затем отдельный consent-gated одноразовый реальный Outlook PST end-to-end. Пока `Archive`, `Resume`, `Auto` остаются **закрыты ARCH2a guard**, включая `-WhatIf`. Отсутствует разрешение на production Move.

## Использование чужих проектов

Сравнены официальные примеры Outlook `MailItem.Copy` / `Move` и MIT-лицензированные инструменты (например, `SSDECT/eml-to-pst`, `lxndrblz/PowerCountPST`), но код не скопирован: они решают смежные задачи или требуют PowerShell 7. У `SeverusJake/SutnesPstSplitter` при проверке не было явной лицензии, поэтому его код не заимствовался. Все изменения этого этапа написаны непосредственно для нашего PowerShell 5.1 COM runtime.

## Release gates

Обязательны PS5.1, PSScriptAnalyzer, Pester, JSON и `EF BB BF` для новых/изменённых PowerShell-файлов; только проектный ZIP `OutlookPOP3Archive-2.6.5-ARCH2c1-dev-g<commit>.zip`, SHA-256, сохранённая точка отката ARCH2b. Внутренний `RELEASE.Build` пока исторически `2.6.3-PREVIEW1`; этот DEV-билд не переименовывает его в «stable».
