# ARCH3x1 — 10 реальных POP3 COM Move через оригинальный MailMover

**20 ноября 2026. DEV / тестовый PST, Windows PowerShell 5.1 STA и профиль Outlook.**

Реализован однократный bounded batch-10 из уже запечатанных оригинальных ARCH3v (10 full SHA, 12 вложений) и ARCH3w1 (10 оригинальных Intent) в новый Year2020 Part3. Исторические ARCH3s–ARCH3x повторно испытывать вручную НЕ нужно. Основные Archive/Resume/Auto и запись в общий DuplicateIndex остаются закрытыми.

## Полный синтаксис

~~~powershell
.\Invoke-ARCH3x1.ps1 -Mode Plan -RunId <GUID> -SealSha256 <SHA> -ManifestSha256 <SHA> -JournalSha256 <SHA>
.\Invoke-ARCH3x1.ps1 -Mode Audit -RunId <GUID> -SealSha256 <SHA> -ManifestSha256 <SHA> -JournalSha256 <SHA>
.\Invoke-ARCH3x1.ps1 -Mode Move -RunId <GUID> -SealSha256 <SHA> -ManifestSha256 <SHA> -JournalSha256 <SHA> -ExpectedPreflightDigest <SHA> -ConfirmTenRealMoves [-WhatIf] [-Confirm:$false]
.\Invoke-ARCH3x1.ps1 -Mode Status -RunId <GUID>
~~~

Параметры:
- Mode: Plan — только чтение protected evidence без Outlook; Audit — live Outlook read-only полный source/Part2 verifier; Move — однократные 10 реальных COM Move; Status — только forensic прочтение writer evidence, без Outlook. Нет Resume/Recover/Auto.
- RunId: строго 093b5ce9-4a90-46fa-b6a5-7cdba61d2f15; НЕ создавать новый.
- SealSha256: исходный ARCH3v 10-mail Seal, d071afbff028d4cbadcea69318a6d68009242ac401cd2a91abf08b5ffe9f6799.
- ManifestSha256: SHA, полученный ТОЛЬКО после успешно завершённого ARCH3w1 Prepare.
- JournalSha256: SHA десяти исходных ARCH3w1 Intent, возвращённый ARCH3w1 Prepare.
- ExpectedPreflightDigest: ТОЛЬКО Move, SHA непосредственно предшествующего ARCH3x1 Audit (не ARCH3w PrepareDigest).
- ConfirmTenRealMoves: обязательное явно подтверждённое разрешение на одну партию из 10 необратимых реальных Move.
- WhatIf: Move отменяется до контакта с Outlook, записи PST, claim или создания workspace.
- Confirm:$false: отключает вторичное подтверждение ShouldProcess, но не ConfirmTenRealMoves.

ВАЖНО: в доступном контексте ещё нет подтверждённых конкретных ManifestSha256 и JournalSha256 успешно выполненного ARCH3w1 Prepare. Не придумывать их, не запускать Move без них. Если ARCH3w1 Prepare пока не завершён, разрешается только соответствующий подготовительный шаг ARCH3w1, без повторения прежних испытаний.

## Необратимая последовательность и ограничения

1. Исходный ARCH3w1 Review проверяет 10 оригинальных Intent/все source SHA и историческую ARCH3q/r доказательную цепочку. Live Audit повторно получает original ARCH3u selection, original ARCH2b Body/HTML/recipients/attachments full SHA всех десяти, проверяет Part1 raw SHA, Part2 original ArchiveVerifier semantic SHA, общий index SHA и свободную Part3. Возвращает новый PreflightDigest, БЕЗ записи.
2. Move делает новый Audit, сравнивает внешний SHA и проверяет POP3 StoreID/Outlook profile/Inbox. Потом оригинальная private ACL и immutable writer-entry CreateNew/Flush(true) в LOCALAPPDATA — ДО создания PST.
3. Только через ORIGINAL New-OPAArchivePst -ARCH3oRequireNewUnusedPst создаётся свободный Part3 и ORIGINAL Get-OPAArchiveFolder создаёт Year2020 Inbox.
4. Для ordinal 1..10 непосредственно перед переносом повторно считываются реальный MailItem и ORIGINAL ARCH2b full witness. Записывается NN-claim.json, затем оригинальный MailMover записывает NN-invocation.json BEFORE ровно одного реального MailItem.Move. После полученного Move возвращённый EntryID фиксируется в NN-returned.json. SHA связывает запись с предыдущей.
5. При частичных claim/invocation/returned, исключении COM, расхождении источника/индекса, неверной папке/архиве: STOP без retry. Старый writer root никогда не очищать и не переисполнять.
6. Даже 10/10 MoveReturned НЕ означают Reconciled. Только следующий самостоятельный этап ARCH3x2 может выполнить настоящий перезапуск Outlook, исходный Test-OPAArchiveMoves по всем 10, и после этого отдельный original OperationJournal Reconciled + shared DuplicateIndex commit.

ProductionReady=False, WriterPermit=False для основного архиватора, AutomaticMoveRetryAllowed=False, OriginalJournalReconciled=False, OriginalDuplicateIndexWritten=False. Реальные 90 ГБ не сертифицированы.

CI: Windows PowerShell 5.1, PSScriptAnalyzer, Pester, BOM и ZIP только OutlookPOP3Archive. CI не подключается к Outlook и не сертифицирует реальные Move.
