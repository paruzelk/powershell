## What is checked

1. Exact fresh scoped LIVE3 request, existing scope marker, POP3 source,
   run-unique temporary archive and **one complete unresolved Intent**.
2. Journal SHA256 equals the operator-verified original SHA before and
   after Outlook inspection. Existing journal must NOT be terminal.
3. Existing three **durable, regular files**, no reparse point:
   bw3-dispatch.claim, move-attempt.claim, bw3-controller-result.json.
   Their RunId, OperationId, WorkerRequestId, journal hash, SourcePst,
   response status, Worker PID and no-retry flags match precisely.
   move-attempt.claim text MUST equal the OperationId.
4. Legacy fixture response, LIVE4 dispatch/crash and LIVE6 resolution
   claims must be absent. BW3 protocol response.json was transient in
   the separate Worker host directory; its absence in fixture is correct.
5. Outlook COM attaches to ALREADY-RUNNING "Outlook" test profile via
   GetActiveObject only. Both PSTs must be uniquely mounted, the source
   bound to exactly one POP3 delivery account.
6. Exact source/target StoreIDs, folder paths, folder EntryIDs, folder
   names; only the two newly-created GUID-scoped folders are inspected.
7. Source=0, archive=1; direct archive Items.Item(1) is MailItem class 43,
   parent matches exact archive folder; Subject and InternetMessageId
   match original durable Intent; EntryID equals Worker returned ID.
8. Additional Namespace.GetItemFromID(destination EntryID, archive
   StoreID) verifies the same archive identity and parent.
9. A read-only size observation is reported. If archive MAPI size differs
   from Intent, the identity-based classification may still PASS, but
   ArchiveSizeDifferenceApproved=False and RequiresManualSizeReview=True.
   Size equality NEVER means cryptographic content equality.
10. Exact durable dispatch/controller/attempt evidence read as RAW text
    before COM is checked again AFTER COM; journal hash also rechecked.
