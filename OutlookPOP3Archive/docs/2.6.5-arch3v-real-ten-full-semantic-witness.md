# ARCH3v — полный оригинальный semantic witness для реальной тестовой партии 10 писем

**2026-11-20. DEVELOPMENT, без реального Move.** Контрольная точка: реальный ARCH3u `Plan/Inventory` успешно выполнен на тестовом POP3 `info@stios.ru.pst`; десять исходных писем `2020\Входящие`, оригинальный Inbox StoreID, две существующие части `Archive-2020.pst` и `Archive-2020-02.pst`, следующий архив `Archive-2020-03.pst` пока **не существует**. **ARCH3v** повторяет тот же оригинальный ARCH3u preflight и вычисляет для всех десяти полный оригинальный ARCH2b semantic witness до создания каких-либо новых неизменяемых evidence файлов.

## Полный синтаксис — основные команды

Выполняйте из распакованного **только OutlookPOP3Archive** через **Windows PowerShell 5.1 -STA**; Outlook с профилем `Outlook` должен быть открыт для `Audit` и `Seal`. Выборка должна остаться абсолютно той же — **не использовать новый RunId**, поскольку PreviewSha256 привязан к исходному RunId.

```powershell
$pin = @{
  RunId='093b5ce9-4a90-46fa-b6a5-7cdba61d2f15'
  SourcePst='C:\Users\bogoderov_e\Documents\Файлы Outlook\info@stios.ru.pst'
  ExpectedPreviewSha256='d9bc37c5f87aace732adb122d89488eb44111b7333ebf3b5d33c087766a42e57'
  ExpectedSourceStoreIdSha256='c6f1cb064a78b6d8c676ace07d6ae8202f2477046e48d17baeade82581837ca3'
  ExpectedOriginalIndexSha256='5ada35eb30f34ff60dc4b89f23aa071b72cc0b98e5ff57299d61f1714b13d7ae'
  ExpectedSourcePstLengthBytes=7735903232
}

# 1. Только план: никакого Outlook, PST, записи на диск
.\Invoke-ARCH3v.ps1 -Mode Plan -RunId $pin.RunId -SourcePst $pin.SourcePst | Format-List

# 2. ПЕРВЫЙ полный original ARCH2b witness для всех 10 из реального PST.
# SaveAsFile создаёт только временную частную копию вложения, удаляемую после SHA256.
# НЕ создаёт постоянный файл свидетельств / PST / архив / журнал.
$audit = .\Invoke-ARCH3v.ps1 -Mode Audit @pin
$audit | Format-List
$audit.Rows | Format-Table Ordinal,SourceEntryId,AttachmentCount,FullOriginalWitnessSha256 -AutoSize

# 3. Сначала WhatIf. Потребуется внешний AuditSha256 из предыдущего вывода.
.\Invoke-ARCH3v.ps1 -Mode Seal @pin -ExpectedAuditSha256 $audit.AuditSha256 -ConfirmEvidenceWrite -WhatIf | Format-List

# 4. Только после проверки AUDIT и WhatIf — одна запись защищённого файла
# свидетельств в LOCALAPPDATA (это НЕ COM Move, не запись в PST).
$sealed = .\Invoke-ARCH3v.ps1 -Mode Seal @pin -ExpectedAuditSha256 $audit.AuditSha256 -ConfirmEvidenceWrite -Confirm:$false
$sealed | Format-List

# 5. Независимый Review созданного evidence-файла без Outlook/PST:
$review = .\Invoke-ARCH3v.ps1 -Mode Review -RunId $pin.RunId -SealSha256 $sealed.SealSha256
$review | Format-List
```

При запуске из нового процесса, если он не STA:

```powershell
powershell.exe -NoLogo -NoProfile -STA
```

Затем в новом окне перейдите в каталог ARCH3v и выполните команды выше. Не используйте PowerShell 7 или ISE с неподходящим процессом Outlook. Результат `Audit` вычисляется заново; при изменении длины PST, выборки, хотя бы одного оригинального SHA или индекса — **STOP** без создания evidence. Это ожидаемое защитное поведение.

## Полный синтаксис всех параметров

`Invoke-ARCH3v.ps1 [-Mode Plan|Audit|Seal|Review] -RunId <canonical-GUID> [-SourcePst <local-exact-info@stios.ru.pst>] [-ExpectedPreviewSha256 <64-hex>] [-ExpectedSourceStoreIdSha256 <64-hex>] [-ExpectedOriginalIndexSha256 <64-hex>] [-ExpectedSourcePstLengthBytes <Int64>] [-ExpectedAuditSha256 <64-hex>] [-SealSha256 <64-hex>] [-ConfirmEvidenceWrite] [-WhatIf] [-Confirm:$false]`

| Ключ | Mode | Назначение |
|---|---|---|
| `-Mode Plan` | Plan | Нет Outlook; показывает только схему будущего полного свидетельства. |
| `-Mode Audit` | Audit | Строго реальный Outlook; original ARCH3u Inventory, original ARCH2b `Get-OPA265ARCH2bMailSemanticWitness` для 10 писем; без постоянной evidence-записи. |
| `-Mode Seal` | Seal | Полностью повторяет Audit и сверяет переданный `ExpectedAuditSha256` перед созданием защищённого evidence. Нельзя повторять для этого RunId. |
| `-Mode Review` | Review | Независимое чтение защищённого evidence только по RunId + SHA файла; не подключается к Outlook. |
| `-RunId` | Все | **Именно** ранее подтверждённый ARCH3u GUID, чтобы зафиксировать выборку. |
| `-SourcePst` | Plan/Audit/Seal | Полный локальный путь к существующему тестовому `info@stios.ru.pst`. В Review не передаётся. |
| `-ExpectedPreviewSha256` | Audit/Seal | Точная SHA оригинального десятистрочного ARCH3u предварительного плана. |
| `-ExpectedSourceStoreIdSha256` | Audit/Seal | SHA исходного POP3 StoreID, не IMAP и не default PST. |
| `-ExpectedOriginalIndexSha256` | Audit/Seal | SHA оригинального append-only `DuplicateIndex.jsonl` (501 историческая запись). |
| `-ExpectedSourcePstLengthBytes` | Audit/Seal | Наблюдавшаяся длина исходного PST. Любое изменение блокирует процедуру; намеренный fail-closed. |
| `-ExpectedAuditSha256` | Seal | 64-символьный digest полученного `Audit`, который привязывает десять оригинальных полных хэшей, роли, даты, целевую часть и входные оригинальные SHA. |
| `-SealSha256` | Review | SHA-256 записанного evidence-файла, выданная после однократного Seal. |
| `-ConfirmEvidenceWrite` | Seal | Явное разрешение **только** на evidence-файл в LOCALAPPDATA. Не разрешает Move. |
| `-WhatIf` | Seal | Демонстрация без создания evidence. |
| `-Confirm:$false` | Seal | Устраняет интерактивное подтверждение после явного `-ConfirmEvidenceWrite`. |

## Техническая граница

1. Перед каждым `Audit/Seal` исходный ARCH3u заново выбирает оригинальные 10 EntryID через `Get-OPAArchiveCandidates`, проверяет POP3/Inbox/Store и original shared DuplicateIndex SHA, не допускает изменившейся части `2020-03`.
2. Затем каждый MailItem отдельно получается из оригинального StoreID через `Namespace.GetItemFromID` и проверяется по Inbox.Parent, исходной ArchiveDate, числу вложений и SubjectSha256.
3. Для всех десяти вызывается ORIGINAL `Get-OPA265ARCH2bMailSemanticWitness`: Body SHA, HTML SHA, Received/Sent, Sender/To/Cc/Bcc/Recipient SHA, UnRead/Importance/Sensitivity/Categories, фактические `Attachment.SaveAsFile` с SHA256 и размерами в защищённой временной рабочей области.
4. ORIGINAL `Get-OPA265ARCH3dOriginalWitnessHash` выдаёт индивидуальный полный witness SHA; `Get-OPA265ARCH3bDigest` собирает десятистрочный `AuditSha256` с явным ordinal и original route hash.
5. Только для `Seal` и только после совпадения externally pinned AuditSha256 вызываются **существующие** `New-OPA265ARCH3iPrivateEvidenceDirectory` (защищённая NTFS ACL без окна наследования) и **существующий** `Write-OPA265ARCH3cJsonOnce` (CreateNew/Flush(true), без overwrite).
6. `Review` независимо пересчитывает SHA файла и оригинальные хэши всех 10 полных witness, проверяет исходные поля, не открывая исходный PST.

Содержимое Body/HTML/вложений **не сохраняется**, только оригинальные SHA-256 и метаданные. Временные копии вложений могут на короткое время находиться в частном TEMP; оригинальная функция должна их удалять. При аварийном завершении возможны остаточные TEMP-копии, требующие отдельного ручного контроля.

### Запреты и следующий этап

`RealMailMovePerformed=False`, `OriginalOperationJournalWritten=False`, `OriginalDuplicateIndexWritten=False`, `ArchivePstCreated=False`, `WriterPermit=False`, `ProductionReady=False`. Этап не реализует никакой live writer и **не даёт** права включать `Archive/Resume/Auto`.

После подтверждения оператором `Audit → Seal → Review` следующий **ARCH3w** должен отдельно подготовить durable Intent/Claim для этих 10 оригинальных операций и защиту от неоднозначного исхода при последующем одном ограниченном реальном запуске. Реальный COM Move не выполняется в ARCH3v.
