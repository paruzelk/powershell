BW3m performs the next independent verification of what was actually

**BW3m does not implement or enable an original journal writer.**
No -Execute/-Record/-Commit, original FileStream with write access,
LIVE6 -Execute, MailItem.Move, PST writes, or original resolution claim
creation. It accepts -Review only. It calls BW3l, which creates and
writes *one new TEMP COPY*, not the original. Do not characterize
this command as no filesystem writes anywhere; TEMP copy writes occur.

## Procedure

1. Native Windows PowerShell 5.1 STA, exact RunId, source PST and
   original SHA256, explicit -Review.
2. Confirm no resolution claims exist; snapshot the seven immutable
   SHA256s, original one-Intent journal and pinned schema.
3. Reinvoke BW3l -RehearseVerifiedCopy, which independently runs BW3j
   real Outlook -Review and performs one new TEMP-copy-only append.
4. Require all exact 26 BW3l verdict fields, including original
   untouched, no write permit, no retry or production.
5. Read the NEW BW3l copy marker, exact TEMP claim and entire two-event
   journal INDEPENDENTLY. Check strict claim field count, original
   Intent SHA256, copy-only scope, original one-Intent byte prefix,
   final copy SHA256, exact Reconciled sequence 2/destination/PST,
   preserved original fields, journal schema and recovery replay.
6. Reject every offline synthetic replica in the real audit.
   Pester can audit an offline replica through a distinct test-only
   readback switch; the public wrapper does not expose that switch,
   and the final security decision requires ActualHistoricalByteCopy.
7. Rehash all original seven files, check both absent historical
   resolution claim slots, original single-Intent replay and original
   journal pinned SHA256 once more. No historical writes.
8. Return a nonauthorizing independent security verdict.

## Required risk controls for future original writer (NOT implemented)

- Separate, fresh, explicit human permission specifying exactly the
  RunId, OperationId, journal SHA256 and one intended Reconciled event.
- Preservation of seven original file hashes, immutable size acceptance
  exception and matching source/archive PST identity before any write.
- One-shot CreateNew claim; reject partial, existing, conflicting,
  reparse/symlink claims with zero cleanup/retry.
- Under a held exclusive FileStream lock, re-read original file bytes,
  enforce exactly original one Intent, pinned SHA256 and no terminal.
- One hashed JSONL envelope, Sequence 2, Phase Reconciled, destination
  exact archived EntryID, FileStream.Flush(true).
- Independent postappend replay and original evidence retention.
- If claim exists but append not completed: manual investigation STOP.
  If terminal append may have completed before verification: independent
  manual review STOP. NO automatic retry or another MailItem.Move.
- Threats still requiring dedicated review: TOCTOU/reparse point races,
  adversarial concurrent writers, storage failure after Flush(true),
  original PST corruption and lack of full pre-Move content hash.

**This stage does not grant permission or create a write-capable
historical route.** A verified BW3m does not itself permit Reconciled.
The old LIVE6 executor remains incompatible with historical BW3a.
