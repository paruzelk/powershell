## Реализация — исходные модули, НЕ параллельный массовый архиватор

В **исходном `MailMover.ps1`** добавлены две opt-in функции:

1. `New-OPAArchivePst -ARCH3oRequireNewUnusedPst`: оригинальная функция создания PST отказывается от любого существующего или уже подключённого файла перед `AddStoreEx`, не открывает старую Part1. По умолчанию поведение прочих архивных сценариев НЕ изменилось.
2. `Invoke-OPA265ARCH3oOneOriginalMailMoverProviderCall`: оригинальная единственная точка Outlook `MailItem.Move`, требует точный защищённый `ARCH3o-MoveClaimed` и SHA-256; перед вызовом COM записывает вторую необратимую отметку `ARCH3o-ProviderInvocation.json` через `FileMode.CreateNew`, `Flush(true)`. Повторить этот вызов при существующем файле невозможно.

Контроллер `Core/Archive/ARCH3oOneRealOriginalMailMover.ps1` использует исходные `ARCH3n` read-only original PrepareIntent/Journal/witness/index gates, тот же original COM POP3 Scope, `Get-OPAArchiveItemDate`, `Get-OPA265ARCH2bMailSemanticWitness`, `New-OPAArchivePst` и `Get-OPAArchiveFolder` для original Year2020 Part2. Источник, исходная папка, StoreID, дата, год, полное семантическое свидетельство и OriginalContract повторно проверяются ПЕРЕД любой записью.

Порядок операции: *unmodified original ARCH3j PrepareIntent и OperationJournal Intent* → `ARCH3o-WriterEntry.json` (**необратимая отметка до создания PST**) → original `New-OPAArchivePst` только NEW Part2 → original `Get-OPAArchiveFolder`, empty target check → повторный full original semantic witness → `ARCH3o-DestinationReady.json` → `ARCH3o-MoveClaimed.json` → `ARCH3o-ProviderInvocation.json` → **один** Outlook `MailItem.Move()` → `ARCH3o-MoveReturned.json` (если COM вернул валидный EntryID).

Любая ошибка, обрыв процесса или неопределённый COM outcome после `WriterEntry` = **STOP**, не повторять `Move`, `Prepare` или `Resume`. Файлы в protected LOCALAPPDATA никогда не перезаписываются. Если COM Move вернул результат, это ещё НЕ подтверждает сохранность письма: требуется отдельный реальный Outlook restart и оригинальный `ArchiveVerifier`.

**Критично:** исходный `OperationJournal` остаётся в `Intent` до независимой пострестартовой проверки. Общий `DuplicateIndex` остаётся неизменённым; `Add-OPADuplicateEntry` на ARCH3o не вызывается. Ни `Archive`, ни `Resume`, ни `Auto` не включены. `ProductionReady=False` даже после успешного COM.

## Команды на Windows PowerShell 5.1 STA

Сначала используйте только `Plan`, `Audit`, `Status` и `-WhatIf` на тестовом Outlook 2019 с запущенным профилем `Outlook`:

```powershell
$pin = @{
    RunId = '9d276dc4-a0e6-4e74-891f-81502fafe7db'
    IntentSha256 = 'f0860d55c5939498094832a8b924dbca9b65532cf53f8234f4aeda97ab631a2b'
    JournalSha256 = 'a19f113a6454b1d17333c9a53fc22d065876754b9fbab3167087487d0b2b981e'
}
.\Invoke-ARCH3o.ps1 -Mode Plan @pin | Format-List
.\Invoke-ARCH3o.ps1 -Mode Audit @pin | Format-List
.\Invoke-ARCH3o.ps1 -Mode Move @pin -ConfirmOneRealMove -WhatIf | Format-List
.\Invoke-ARCH3o.ps1 -Mode Status @pin | Format-List
```

**Реальный `Move` является разрушительным для исходного размещения письма. Выполнять только после успешного Plan/Audit, дополнительного операционного решения и организации настоящего независимого пострестартового сверочного этапа; не выполнять автоматически в CI.**

```powershell
$moved = .\Invoke-ARCH3o.ps1 -Mode Move @pin -ConfirmOneRealMove -Confirm:$false
$moved | Format-List
```

При любом исключении или неопределённом выводе **не повторяйте** `-Mode Move`, вместо этого выполните ТОЛЬКО `-Mode Status` и независимую проверку, сохранив все evidence. Не используйте данный вывод как доказательство сохранности письма.

| Параметр | Тип | Ограничение |
| --- | --- | --- |
| `-Mode` | Plan / Audit / Move / Status | Plan без Outlook; Audit read-only; Move строго один реальный вызов; Status forensic read-only даже после частичной операции. |
| `-RunId` | string | Точный user-принятый ARCH3j RunId. |
| `-IntentSha256` | lowercase sha256 string | Точный sealed оригинальный PrepareIntent. |
| `-JournalSha256` | lowercase sha256 string | Точный оригинальный Intent-Only OperationJournal. |
| `-ConfirmOneRealMove` | switch | Требуется только Move; не действует в Plan/Audit/Status. |
| `-WhatIf` | common parameter | В Move возвращает результат без Outlook, создания PST и evidence. |
| `-Confirm` | common parameter | PowerShell ShouldProcess; `-Confirm:$false` не заменяет обязательный `-ConfirmOneRealMove`. |
