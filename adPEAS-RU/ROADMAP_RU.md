5. **D18.** SCCM, SCOM, VMware/ESX, подсети, исторические атрибуты,

Группировка D14–D19 предварительная: каждый следующий этап выбирает
**ещё не проверенные FindingId**, а не слепо следует названиям категорий.

## После каталога (отдельные задачи)

- Сверить все исходные `docs/*.md` с `docs/ru-RU/*.md`: русские
  страницы пока существенно короче оригинальных, поэтому считать их
  полным переводом нельзя. Сохранить команды, параметры, ссылки,
  примеры и исключения без изменения поведения.
- Завершить инвентаризацию динамической выдачи в `Checks`, `Core`,
  `Helpers`, `Collector`, `Reporting` и HTML/JS; английские
  технические имена и реальные значения AD не переводить.
- Сопоставить карточки и отчёты (HTML/TXT/JSON) с оригиналом:
  отсутствие неверных выводов, сохранение фильтров, экспорта,
  группировок и рекомендаций. Ранее созданные HTML надо пересоздать.
- Провести проверки Windows PowerShell 5.1, UTF-8 BOM для .ps1/.psm1/.psd1,
  компиляции JS и набор офлайн-регрессионных тестов.
- Отдельно выполнить аудит работы в тестовом домене AD.
  GitHub Actions проверяет сборку и статическую логику, но
  **не подтверждает** корректность всех запросов в реальном домене.
- Проверить юридические уведомления автора и коммерческие
  условия исходного adPEAS. Не считать исходник лицензией MIT/GPL.

## Правила приёмки каждого D-этапа

1. Для каждого FindingId точно совпадает **число и порядок** пунктов
   с закреплённым исходником EN. Все EN-строки сохраняются как witness.
2. Русский текст не теряет условия, отрицания, ограничения применения
   и различия между безопасной настройкой, реальной уязвимостью
   и требующим проверки сигналом.
3. Ранее подтверждённые FindingId не переписываются незаметно;
   повторяющиеся или посторонние ID приводят к ошибке сборки.
4. Не изменяются исполняемые PowerShell-команды исправления,
   логика обнаружения, уровни риска, метаданные, атрибуты LDAP и
   исходный английский справочник.
5. Новый JSON проверяется отдельным тестом EN ↔ RU ↔ HTML,
   а регрессионные тесты предыдущих D-этапов остаются активными.
6. Пакет и SHA-256 публикуются **только после успешной CI**.

Общая история этапов: [README_RU.md](README_RU.md).

## Результат D14

Закреплённое состояние после исходного коммита этапа D14: 294 типа
с предметной сверкой Impact/Remediation, 98 ещё предстоит сверить.
Остаток структурных расхождений по `SourceFieldParity392.json`
после пересборки должен уменьшиться до 42 Impact и 41 Remediation.
Новое содержимое отчётов требует повторного запуска аудита; сохранённые
старые HTML-файлы не обновляются автоматически.

Следующий этап — **D15**. Для него необходимо выбирать ещё не сверенные
находки (например, оставшиеся права и доверительные отношения),
проверять исходные массивы и оговорки безопасности, затем добавлять
регрессионный тест и собирать архив через GitHub Actions.


## Результат D15

Новые каталоги `SourceVerifiedCore-24a/24b.ru-RU.json` переводят
24 типа находок (86 Impact, 85 Remediation) с сохранением точного
английского свидетеля. 294 предшествующих типа запрещено перезаписывать.
Ключевые ограничения: `Protected Users` не предназначена для gMSA,
`Trust Selective Authentication` и сильные алгоритмы PKI являются
защитными настройками, а штатные разрешения Exchange не следует удалять
без оценки модели безопасности.

Итоговое предметное покрытие **318/392**, осталось **74**.
После пересборки ожидается структурный остаток **18 Impact/17 Remediation**.
Следующий этап — D16, оставшиеся Exchange RBAC и SMTP.



## Результат D16

Сверены 20 новых находок (16 Exchange, 4 дополнительные), 59 Impact,
56 Remediation. Применение фиксирует 318 ранее проверенных ID и
сохраняет пустое `Remediation = @()` для `LAPS_INSTALLED`.
Ожидаемое покрытие после сборки — **338/392**, осталось **54**.

Ожидаемые **0/0** структурных расхождений означают лишь, что
списки русских и исходных пунктов одинаковы по количеству.
Оставшиеся 54 типа необходимо предметно проверить: автоматическая
структурная проверка не удостоверяет точный смысл. Нельзя считать
весь каталог полноценно сверенным до завершения этой работы.

Следующий этап — **D17**: выбрать оставшиеся непроверенные FindingId,
проверить исходный текст и контекст каждого пункта, добавить
отдельный тест и обновить сборку и Markdown-документацию.
