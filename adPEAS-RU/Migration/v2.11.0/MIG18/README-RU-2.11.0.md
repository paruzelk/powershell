## Быстрый запуск (Windows PowerShell 5.1)

~~~powershell
cd 'C:\Tools\adPEAS-RU\candidate'
Import-Module .\adPEAS.ps1 -Force
Invoke-adPEAS -Domain example.local -UseWindowsAuth -OPSEC -Outputfile '.\AD-Audit-MIG19gh' -Format All
Disconnect-adPEAS
~~~

Создаются AD-Audit-MIG19gh.html, AD-Audit-MIG19gh.txt и AD-Audit-MIG19gh.json.
Outputfile принимает имя без расширения.

**LDAPS с проверкой сертификата:**

~~~powershell
Import-Module .\adPEAS.ps1 -Force
Connect-adPEAS -Domain example.local -UseWindowsAuth -UseLDAPS -IgnoreSSLErrors:$false
Invoke-adPEAS -OPSEC -Outputfile '.\AD-Audit-LDAPS' -Format All
Disconnect-adPEAS
~~~

В исходном Connect-adPEAS проверка TLS-сертификата **отключена по умолчанию**.
Используйте -IgnoreSSLErrors:$false для её включения.

**Выборочные разделы:**

~~~powershell
Invoke-adPEAS -Domain example.local -UseWindowsAuth -Module Domain,Accounts,GPO,Rights -OPSEC -Outputfile '.\AD-Audit-Selected' -Format All
~~~

**Другая учётная запись:**

~~~powershell
Invoke-adPEAS -Domain example.local -Credential (Get-Credential) -OPSEC -Outputfile '.\AD-Audit-Alternate' -Format All
~~~

## Экспорт BloodHound CE

При обычном аудите выполняется модуль Bloodhound, который собирает данные для графического анализа AD в отдельный ZIP. Это не резервная копия AD и не основной отчёт. Архив импортируется в BloodHound Community Edition через интерфейс загрузки данных. Данные чувствительны; храните их локально и не публикуйте в репозитории.

Для обычного аудита без дополнительного архива:

~~~powershell
Invoke-adPEAS -Domain example.local -UseWindowsAuth -ExcludeModule Bloodhound -Outputfile '.\AD-Audit' -Format All
~~~

В проверенном режиме OPSEC модуль Bloodhound не запускался. OPSEC не является гарантией полностью пассивного аудита.

## Параметры Invoke-adPEAS — оригинал 2.11.0

Общая форма (параметры аутентификации имеют взаимоисключающие наборы):

~~~text
Invoke-adPEAS [-Domain <String>] [-Server <String>] [-UseLDAPS]
  [-UseWindowsAuth | -Credential <PSCredential> | -Username <String> -Password <Object> | -Certificate <String> [-CertificatePassword <Object>]]
  [-Outputfile <String>] [-Module <String[]>] [-ExcludeModule <String[]>]
  [-OPSEC] [-NoColor] [-VerboseLogging] [-InactiveDays <Int32>]
  [-IncludePrivileged] [-TimeoutSeconds <Int32>] [-Format <Text|HTML|JSON|All>]
  [-OutputAppend] [-License <String>] [-Statistics]
~~~

| Ключ | Тип/умолчание | Назначение |
|---|---|---|
| -Domain | String | Имя домена AD для нового соединения |
| -Server | String | FQDN/IP контроллера домена |
| -UseLDAPS | Switch | LDAPS, порт 636 |
| -UseWindowsAuth | Switch | Аутентификация пользователя Windows |
| -Credential | PSCredential | Альтернативная учётная запись |
| -Username | String | Имя при аутентификации с паролем |
| -Password | String или SecureString | Пароль, вместе с Username |
| -Certificate | String | PFX/PKCS#12 либо Base64 |
| -CertificatePassword | String или SecureString | Пароль PFX, по умолчанию пустой |
| -Outputfile | String | Путь отчёта без расширения |
| -Module | String[] | Выбрать модули |
| -ExcludeModule | String[] | Исключить модули |
| -OPSEC | Switch, выключен | Пропустить активные/массовые проверки |
| -NoColor | Switch | Отключить ANSI |
| -VerboseLogging | Switch | Расширенный лог; для файла нужен Outputfile |
| -InactiveDays | Int32, 90 | Порог неактивности 1–3650 дней |
| -IncludePrivileged | Switch | Показывать ожидаемые привилегированные назначения |
| -TimeoutSeconds | Int32, 30 | Тайм-аут 5–600 секунд |
| -Format | Text/HTML/JSON/All | По умолчанию All |
| -OutputAppend | Switch | Дополнение отчёта с JSON; нужен Outputfile и JSON/All |
| -License | String | Путь к лицензии |
| -Statistics | Switch | LDAP-статистика |

Модули: Domain, Creds, Rights, Delegation, ADCS, Accounts, GPO,
Computer, Application, Shares, Bloodhound.

Shares по умолчанию не запускается: подключается по SMB к компьютерам
домена. OPSEC уменьшает активность, но **не обеспечивает полностью
пассивный** аудит.

~~~text

    -Username <String> -NTHash <String> | -Username <String> -AES256Key <String> |
    -Username <String> -AES128Key <String> | -Kirbi <String> | -Ccache <String>]
  [-ForceNTLM] [-ForceSimpleBind] [-ForceKerberos] [-BuildCompletionCache]
  [-License <String>] [-TimeoutSeconds <Int32>]
~~~

| Ключ | Назначение |
|---|---|
| -Domain | Явно указанный FQDN домена |
| -Server | Контроллер домена |
| -UseLDAPS | Использовать TLS |
| -IgnoreSSLErrors | По умолчанию TRUE; :$false включает проверку сертификата |
| -DnsServer | Пользовательский DNS |
| -PatchHostsFile | Изменение hosts, требует разрешений |
| -Quiet | Уменьшить вывод |
| -UseWindowsAuth | Вход текущего пользователя |
| -Credential | PSCredential |
| -Username | Пользователь для парольной/ключевой аутентификации |
| -Password | Пароль |
| -Certificate | Путь или Base64 PFX |
| -CertificatePassword | Пароль PFX |
| -ForcePassTheCert | Клиентский сертификат Schannel вместо PKINIT |
| -NTHash | NT-хеш (32 hex) |
| -AES256Key | AES-256 (64 hex) |
| -AES128Key | AES-128 (32 hex) |
| -Kirbi | Билет Kerberos: файл/Base64 |
| -Ccache | Кеш Kerberos: файл/Base64 |
| -ForceNTLM | Вход через NTLM |
| -ForceSimpleBind | Простой LDAP bind |
| -ForceKerberos | Только Kerberos |
| -BuildCompletionCache | Предварительный кеш имён |
| -License | Файл лицензии |
| -TimeoutSeconds | 5–600 секунд, по умолчанию 30 |

Не смешивайте разные наборы аутентификации.

## Синтаксис дополнительных команд

~~~text
Get-adPEASSession [-TestConnection] [-Quiet]
Disconnect-adPEAS [-Force]
Convert-adPEASReport -InputJson <String> -OutputPath <String>
    [-Format <Text|HTML|JSON|All>] [-License <String>] [-NoColor]
Compare-adPEASReport -Baseline <String> -Current <String>
    [-OutputPath <String>] [-NoColor]
Get-adPEASHelp [-Section <QuickStart|Checks|Commands>[]]
Get-adPEASHelp -Search <String>
~~~

Get-adPEASSession: TestConnection проверяет соединение, Quiet уменьшает вывод.
Disconnect-adPEAS: Force принудительно завершает сеанс.
Convert-adPEASReport: InputJson — исходный JSON, OutputPath — базовое имя файлов; Format по умолчанию All; License — файл лицензии; NoColor отключает ANSI.
Compare-adPEASReport: Baseline — исходный JSON, Current — новый JSON; OutputPath — базовое имя файлов сравнения, NoColor — без ANSI. Сравнивайте один домен и одинаковый охват проверок; пропущенные модули не равнозначны исправленным находкам.
Get-adPEASHelp: Section выбирает разделы, Search ищет текст/команду (отдельный набор параметров).
Системные общие параметры PowerShell здесь не перечислены. Для остальных функций используйте Get-Command -Syntax и Get-Help -Full; полнота перевода их справки не заявляется.

~~~powershell
Convert-adPEASReport -InputJson '.\scan.json' -OutputPath '.\converted' -Format All -NoColor
Compare-adPEASReport -Baseline '.\old.json' -Current '.\new.json' -OutputPath '.\diff' -NoColor
Get-adPEASHelp -Section Commands,Checks
Get-adPEASHelp -Search 'LDAP'
~~~

## MIG8a — устранение регрессии заметных строк интерфейса

Исправлены непосредственно в исходных шаблонах 2.11.0: заголовок «Первоочередные действия», подпись «критических находок всего», а также пустое состояние без критических находок и описание в справке. Лицензионное уведомление показано по-русски как в шапке HTML, так и при печати/PDF. Полный исходный правовой смысл, условие действующей коммерческой лицензии и механизм проверки лицензии сохранены. Если upstream вернёт иное уведомление, оно останется без изменений, а не исчезнет.

MIG8a изменяет **только отображение**, не меняет вычисление находок, оценку риска, состав результатов, права использования и JSON-экспорт. В CI закреплены регрессионные проверки для обеих отображаемых версий лицензии и динамического блока приоритетов. Статус: Preview до нового реального HTML.

## MIG9 — комплексная проверка видимого перевода на отчёте MIG8a

Сравнены реальные HTML MIG7, MIG8 и MIG8a. Число карточек остаётся **78**, тогда как сводка содержит **105 результатов**: единицы подсчёта различны. В MIG8a были переведены заголовок и счётчик приоритетов, но тексты описания опасности, рекомендаций и всплывающих подсказок всё ещё показывались по-английски. Причина — отдельный путь JavaScript, читавший исходные `checkDescriptions` и `findingDefinitions` в обход существующих проверенных каталогов `ruMIG2CheckDetails` (128 описаний проверок) и `ruMIG2Technical` (408 находок).

MIG9 использует оригинальные русские каталоги именно при **отображении** трёх приоритетных действий и их подробностей. Описания, советы, количество затронутых объектов, информационные всплывающие подсказки, справка по отчёту (46 строк), подписи и причины вычисленных оценок риска, динамические кнопки «Развернуть всё / Свернуть всё» переведены. Обозначения `(direct)` и `(nested)` переведены только при показе атрибута `privilegedGroups`, имена групп и реальные данные AD не меняются. В русской справке указаны фактические цвета: «Сведения» — зелёный, «Безопасно» — синий.

**Не менялись:** формулы расчёта риска, находки, ID, запросы AD, исходные данные, юридические условия лицензии, JSON, команды исправления. Новые проверки CI выполняют генерацию трёх приоритетных карточек на синтетических данных и сверяют русские тексты с уже проверенными каталогами.

**Статус:** PREVIEW до проверки нового реального HTML из MIG9.

переключателя темы Light/Dark. Условия лицензии сохранены.

CI проверяет настоящий PowerShell-рендерер с тремя синтетическими атрибутами
и исполняет JavaScript для четырёх чисел в обоих состояниях.
Исходный отчёт пользователя не публикуется. Статус MIG10: PREVIEW,
до повторной проверки HTML на реальном домене.

## MIG19k — локальная приёмка без повторного аудита

Из корня распакованного архива в свежей сессии Windows PowerShell 5.1 (предварительно проверить успешный CI):

~~~powershell
.\Invoke-MIG19kLocalAcceptance.ps1 -OpsecJson '.\AD-Audit-MIG19i-OPSEC.json' -FullJson '.\AD-Audit-MIG19i-Full.json'
~~~

Исходные JSON не включены в архив; укажите фактические пути. Скрипт предназначен для конкретной пары MIG19i, создаёт отдельный новый каталог, вызывает только Convert-adPEASReport, проверяет контрольные счётчики, метаданные, записи JSON, подписи и текст. Даты/формы сериализации могут отличаться при повторном формировании: REVIEW не означает автоматически повреждение AD, а требует проверки отличий. Не выгружать реальные отчёты в GitHub. Отправить только MIG19k-acceptance.json и при необходимости разрешённые локальные отчёты. На CI проверяются полные, прерванные и legacy-кэши только на синтетике. Следующий этап — MIG20, несколько разрешённых реальных доменов. Не RELEASE.
