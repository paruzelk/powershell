# File-Server-Audit RU — готовая версия без установки

Русифицированная копия проекта https://github.com/sean-aura/File-Server-Audit версии 0.7.4, исходный commit faf157d96341e1336b8b39e0751cf16aa3f79f29. Лицензия MIT (LICENSE).
Изменения уже внесены прямо в исходные файлы: **не нужны инсталляторы, отдельные патчи, копирование файлов или сетевой доступ при запуске**.

## Что исправлено

- PowerShell PS1: UTF-8 с BOM для Windows PowerShell 5.1.
- CSV: явный -Encoding UTF8, в том числе при дозаписи; логи/checkpoints в UTF-8.
- HTML: встроенная русская локализация; кнопки **Участники: N**, **Развернуть все группы**, **Свернуть все группы**.
- Если данные о группе не собраны, явно указано Состав группы не загружен.
- Статус AD-пользователя: проверка по userAccountControl / ACCOUNTDISABLE 0x2; при отсутствии подтверждения — неизвестен.
- Исправление обработки единственного CSV в Build-AccessMapHtml.ps1.
- Один запуск NTFS-аудита и HTML через Invoke-FileServerAudit-RU.ps1.
- Повторная HTML-сборка из CSV через Build-AccessMapFromFolder.ps1.

## Один запуск

Откройте Windows PowerShell 5.1 в каталоге проекта:

~~~powershell
.\Invoke-FileServerAudit-RU.ps1 -Path '\\SHARE\Network' -ExpandGroups -MaxDepth 2 -OpenHtml
~~~

Результат: NTFSAudit_yyyyMMdd_HHmmss с CSV и подпапкой AccessMap_yyyyMMdd_HHmmss, содержащей AccessMap.html и AccessMap_data. HTML открывается локально без сервера.

Все параметры оригинального сканера сохранены: -Path, -IncludeFiles, -IncludeInheritedFileAces, -MaxDepth, -NoRecursion, -BreadthFirst, -ThrottleLimit, -ExpandGroups, -ExpandGroupsExclude, -SkipInheritedAces, -OutputFolder, -NoAdLookup, -Force, -Resume.

Для раскрытия участников групп обязателен -ExpandGroups. По умолчанию исключены крупные группы Domain Users, Everyone, Authenticated Users, Users, BUILTIN\Users. Их можно переопределить через -ExpandGroupsExclude. Без раскрытия HTML честно пишет, что состав группы не загружен.

~~~powershell
.\Invoke-FileServerAudit-RU.ps1 -Path '\\SHARE\Network' -ExpandGroups -MaxDepth 2 -OutputFolder 'D:\Audit\Run1' -OpenHtml
~~~

## Сборка отчёта из ранее полученных данных

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Audit\Run1' -OpenHtml
.\Build-AccessMapFromFolder.ps1 'D:\Audit\Run1\AccessMap_20261106_112710' -OpenHtml
~~~

Для пересоздания HTML в уже заполненном каталоге используется -Force. Важно: повторная сборка старого CSV не обновляет статус пользователей из AD; для этого требуется новый аудит.

## Исходные сценарии

Их можно использовать отдельно: Get-FileServerShareInventory.ps1, Invoke-NTFSPermissionAudit.ps1, Build-AccessMapHtml.ps1. Функциональность SMB/NTFS/DFS исходного проекта сохранена. Системные шары и корзины специально не исключались — используйте конкретный UNC-путь через -Path.

## Проверка

~~~powershell
.\Tests\Test-Source.ps1
~~~

Проверяет синтаксис PowerShell, кодировку BOM, наличие встроенных функций HTML и AD-проверку. Интеграционная проверка на реальном AD/Windows Server проводится отдельно.

Windows PowerShell 5.1 поддерживается; исходный сканер требует PowerShell 7 для параллельного режима -ThrottleLimit более 1. Для AD нужен доступ к контроллеру домена; модуль ActiveDirectory (RSAT) не обязателен.

Отчёт показывает ACE и пользователей в группах, а не гарантированные эффективные права пользователя через SMB+NTFS. Отключение наследования не всегда является ошибкой. Отчёт с именами пользователей и структурой ACL следует хранить в защищённом каталоге.

Русские подписи, встроенная справка и пояснения к рискам теперь записаны непосредственно в AccessMapTemplate.html; внешний русификатор и перевод через MutationObserver больше не используются. Поля CSV/JSON, имена команд, пути и алгоритмы остаются исходными. Часть диагностических сообщений может быть на английском.

## Сводка (исправление 1.0.8)

Кнопка **«Сводка»** показывает общие показатели: пользователей и группы, количество ACE,
папки с отключённым наследованием, включённые/отключённые учётные записи,
распределение прав (диаграмма), замечания по безопасности и ошибки аудита.

В 1.0.8 добавлена защита от пустого экрана: отсутствующие необязательные статистические поля
обрабатываются безопасно; при исключении на экране показывается диагностическое сообщение
и подробности доступны в консоли браузера (F12 → Console).
Без данных конкретного сбойного отчёта не установлена точная причина прежнего пустого экрана.

Для **старого отчёта** повторный NTFS-аудит не нужен: обновите HTML из CSV с явным разрешением
перезаписи существующей папки карты:

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_123441' -Force -OpenHtml
~~~

При обновлении файлов источников отчёта перегенерация HTML требуется, так как HTML уже содержит
копию исходного AccessMapTemplate.html.

## Левая панель: раскрытие состава AD-групп (1.0.9)

В разделе «Пользователи и группы» у каждой группы есть стрелка **▸**. Она показывает
участников, уже сохранённых в `AccessMap_data/manifest.js`, без запроса к AD.
Нажатие на имя пользователя открывает его карточку и доступы. Состояние раскрытия
сохраняется при перерисовке списка и выборе пользователя.

На карточке выбранной группы появился собственный раскрываемый блок
«Показать состав группы (N по данным аудита)». Большие группы отображаются порциями
по 150 человек. На странице не нужно загружать все разрешения сразу.

**Важно:** `Direct member count` из AD — число **непосредственных** членов группы,
а `members[]` из отчёта — **рекурсивно раскрытое** членство, сформированное по
строкам `GrantedViaGroup` при сканировании с `-ExpandGroups`. Количество
может различаться. Если старый отчёт хранит только `Direct member count` без
`members[]`, показать имена по одному числу невозможно: на экране будет
«Состав группы не записан в отчёт», и для получения имён потребуется
новое сканирование с `-ExpandGroups`.

Для использования новой версии интерфейса **не обязательно заново сканировать**,
если в старых CSV уже присутствуют раскрытые участники групп. Достаточно пересобрать
HTML из существующих CSV (в отдельной распакованной версии проекта):

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_123441' -Force -OpenHtml
~~~

При скачивании ZIP не копируйте один HTML-файл из новой версии поверх старого:
пересоберите отчёт из CSV, чтобы сохранить согласованность с `manifest.js`.

## Распределение прав (1.0.10)

Исправлен блок «Распределение прав доступа» в разделе «Сводка».
Предыдущая HTML-версия могла показывать все шесть счётчиков равными нулю
при наличии записей доступа: если поле `rightsDistribution` в
`AccessMap_data/manifest.js` было некорректным, интерфейс подставлял нули.

Теперь сборщик `Build-AccessMapHtml.ps1` независимо пересчитывает категории
по итоговым записям `share_N.js` и **проверяет сумму счётчиков** в JSON.
Если сумма не совпадает с `totalEdgeCount`, ошибочный отчёт не публикуется.

В HTML ошибки не маскируются: при отсутствии корректного массива счётчиков
появляется кнопка «Пересчитать права по данным отчёта». Отчёты до 50 000 ACE
пересчитываются автоматически, при большем количестве нужен явный запуск,
чтобы не загружать все данные в память браузера без запроса.
Пересчёт выполняется только по локальным файлам `AccessMap_data`,
без обращения к файловому серверу или AD. Легенда диаграммы на русском.

Для обновления старого отчёта достаточно **пересобрать HTML из готового каталога CSV**
в распакованной версии проекта:

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_153548' -Force -OpenHtml
~~~

При сохранении подозрения на некорректные значения можно проверить уже готовый
`manifest.js` (только чтение):

~~~powershell
.\Tests\Test-RightsManifest.ps1 -AccessMapFolder 'D:\Reports\NTFSAudit_20261106_153548\AccessMap_20261106_153548'
~~~

Статус `Valid` означает совпадение суммы шести категорий с числом ACE,
`InvalidCounters` — некорректный формат счётчиков,
`CountMismatch` — несовпадение сумм. Это проверка согласованности
отчёта, а не проверка эффективных прав пользователя.


## Русификация справки отчёта (1.0.11)

Переведены непосредственно в `AccessMapTemplate.html`:

- пояснения в разделе «Сводка»: количество пользователей, групп, папок, состояние учётных записей, ошибки сканирования и распределение NTFS-разрешений;
- таблица «Уровни доступа: разрешённые действия и возможные риски» со всеми шестью уровнями доступа;
- предупреждение о пределах применимости автоматических рекомендаций;
- замечания по широким группам, отключённому наследованию, неактивным аккаунтам, неразрешённым SID, пропущенным объектам и хранению устаревших данных;
- текстовые рекомендации по ACSC Essential Eight, NIST, CIS Controls, NZISM, ISM, GDPR, Privacy Act (с сохранением обозначений стандартов и номеров пунктов);
- подсказки дерева, графа, фильтров, карточек субъектов доступа и таблиц прав.

Вместо динамической подмены текста при загрузке страницы используется **перевод, встроенный непосредственно в HTML и JavaScript**. Имена полей `manifest.js`, внутренние значения `RIGHTS_LABELS`, коды прав, параметры PowerShell и формат исходного CSV сохранены для совместимости.

Имена пользователей, AD-групп, пути, оригинальные сообщения Windows/AD и названия нормативных документов в их официальной форме не переводятся произвольно: это исходные данные и идентификаторы.

**Пересборка старого HTML без повторного аудита:**

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_153548' -Force -OpenHtml
~~~

Важно: отчёт содержит снимок состояния на дату аудита. Пересборка HTML меняет отображение, но не обновляет данные AD и ACL.


## Единые метки состояния учётных записей (1.0.12)

Везде, где в интерфейсе выводятся пользователи, добавлены одинаковые метки:

- **Отключена** — `Enabled = false` из сохранённых сведений AD (красная метка).
- **Заблокирована** — `Locked = true` на момент аудита (красная метка).
- **Неактивна (90+ дн.)** — давний последний вход по сохранённой приблизительной дате `LastLogon` (жёлтая метка).

Они показываются у пользователя в левой панели, **внутри раскрытой AD-группы**
(и в карточке самой группы), в списке ACL папки, в том числе у вложенных
участников, и в подсказке графа связей. На графе отмеченные учётные записи
также выделяются цветной точкой, включая выбранный центральный узел.
Под списком раскрытой группы приводится отдельное число учётных записей,
требующих проверки, по каждой категории.

Если у пользователя есть одновременно несколько признаков, выводятся все
соответствующие метки. При неизвестном `Enabled` **не отображается ложная
метка «Отключена»**. Неактивность по `LastLogon` — предварительный
признак для проверки, а не подтверждение ненужности учётной записи.

**Без повторного сканирования:** если в исходном `ADIdentityDetails*.csv`
сохранены верные признаки статуса, достаточно пересобрать HTML из текущих CSV:

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_153548' -Force -OpenHtml
~~~

Если же сведения AD в CSV были собраны до исправления определения `Enabled`
или устарели, потребуется **новый NTFS/AD-аудит**, поскольку пересборка HTML
не обращается к контроллеру домена и не изменяет исходные статусы.


## Граф прав доступа: привязанные подписи и перетаскивание (1.0.13)

Исправлена визуализация графа прав доступа:

- Подписи «Полный доступ», «Изменение», «Чтение» и других прав теперь
  создаются **внутри SVG-узла соответствующего пользователя, группы или папки**.
  При перетаскивании подписи двигаются вместе с узлами, а линии обновляют
  свои концы; больше нет неподвижных надписей в центре/на фоне.
- Непосредственно рядом с узлом выводится наиболее значимая связь.
  При нескольких записях добавляется число остальных `(+N)`;
  в подсказке при наведении перечислены все типы прав этой связи,
  наследуемость и признак запрета.
- Для плотных графов (более 14 узлов) подписи прав **по умолчанию появляются
  при наведении или фокусе на узле**. Кнопка «Права: при наведении /
  Права: всегда» меняет режим. Это предотвращает наложение десятков длинных
  текстов друг на друга.
- Расстояние между узлами на плотных кольцах графа автоматически увеличено.
- Кнопка `⌗` теперь сбрасывает **не только масштаб, но и перетаскивание
  узлов** в исходную раскладку. После сброса линии и подписи остаются связаны.
- Подписи и права не изменяют сами NTFS/AD/SMB-разрешения: это только
  отображение данных сохранённого аудита.

**Обновление существующего отчёта без повторного сканирования:**

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_153548' -Force -OpenHtml
~~~

После перезаписи HTML закройте предыдущую вкладку отчёта и откройте
новый `AccessMap.html`, чтобы исключить отображение старой версии страницы.


## Легенда линий графа (1.0.14)

В графе **цвет и начертание линии описывают разные признаки**:

- **Красный пунктир** — `Full Control` («Полный доступ»), **унаследованный** от вышестоящей папки в NTFS.
- **Красная сплошная** — `Full Control`, назначенный **явно** в ACL.
- Для других цветов действует то же правило: цвет задаёт категорию прав, а пунктир — наследование.
- **Фиолетовый пунктир** также используется для связи «членство в AD-группе»; тип этой связи уточняется наведением на линию.
- Красный цвет **не является обозначением запрета** `Deny`: запрет определяется отдельным признаком ACL и отображается в подсказке как «Запрет».

При нескольких ACE граф отображает наиболее значимую связь; наведите курсор на линию или узел для просмотра подробностей. Все фактически сохранённые записи прав доступны в таблицах отчёта. Расчёт ACL не изменён, обновлена только легенда. Панель легенды расширена и получила прокрутку при ограниченной высоте.

Для обновления существующего отчёта без повторного NTFS-аудита выполните:

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_153548' -Force -OpenHtml
~~~


## Исправление легенды и перетаскивания графа (1.0.15)

Исправлены две регрессии предыдущих версий:

1. **Легенда:** при небольшой высоте окна её верх уходил за пределы графа,
   поскольку размер задавался через `65vh` и расположение — от нижней границы
   всего `graphWrap`. Теперь легенда находится внутри отдельной
   `graphCanvas`: отступ **8 px сверху и 48 px снизу**, независимая
   прокрутка по вертикали, при каждом открытии показ начинается с раздела
   «Узлы». Увеличение количества пунктов не перекрывает заголовок и не
   делает верх недоступным.
2. **Перетаскивание:** при наведении узлы переставлялись в конец SVG-списка,
   что в Chromium могло прерывать активный захват мыши. Перестановка удалена.
   Для перемещения используются `Pointer Events` и `setPointerCapture` с
   поддержкой мыши, стилуса и касания. Перетаскивание двигает узел, привязанную
   подпись прав и концы линий; простой щелчок открывает карточку объекта.
   Фон графа, как раньше, можно перемещать отдельно; кнопка `⌗` сбрасывает
   координаты и масштаб.

Выполнены синтетические тесты JavaScript (drag, click, pan, reset,
легенда) и проверка компоновки/прокрутки легенды в Chromium.
Реальные данные NTFS и AD не изменяются.

Для пересоздания HTML из сохранённых CSV повторный аудит не нужен:

~~~powershell
.\Build-AccessMapFromFolder.ps1 'D:\Reports\NTFSAudit_20261106_153548' -Force -OpenHtml
~~~

После пересборки закройте предыдущую вкладку и откройте новый `AccessMap.html`.
